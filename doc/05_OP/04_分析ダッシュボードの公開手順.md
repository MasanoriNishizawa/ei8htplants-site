# OP-04 — 分析ダッシュボードの公開手順

（2026-10-17 作成。同日、公開先を Render から Streamlit Community Cloud に変更）

分析ダッシュボード（`analytics/` フォルダ。売上・収支・予約・注文・アクセス数をグラフで見る画面）を、**Streamlit Community Cloud**（Streamlit の無料の公開サービス）で公開する手順。サイト本体（Render）とは別の場所で動かすので、サイト本体の設定には触らない。

画面の内容・ログインの動きは [FT-25 分析ダッシュボード](../01_BD/features/14_分析ダッシュボード.md) を参照。

> **公開先を移した理由**: はじめは分析ダッシュボードも Render の別のサービスとして公開していた。しかし Render の無料枠は「すべてのサービスを合わせて月 750 時間まで動かせる」という決まりで、サイト本体と分析ダッシュボードの2つで分け合うと足りなくなった。そこで分析ダッシュボードだけを、無料で使える Streamlit Community Cloud に移した。Render にはサイト本体だけを残す。

---

## 1. できあがりの形

| 項目 | 内容 |
|---|---|
| 公開先の URL | `https://ei8htplants-analytics.streamlit.app`（管理画面のメニュー「分析 ↗」がこの URL を開く） |
| 見られる人 | 管理画面と同じメールアドレス・パスワードでログインでき、`ANALYTICS_ALLOWED_EMAILS` に入っている人 |
| データ | 本番の Supabase を読むだけ（書き換え・削除はしない） |
| 料金 | 無料。しばらく使われないと休止し、次に開いたときは起動を待つ（画面に起こすためのボタンが出たら押す） |
| 更新 | `main` ブランチにプッシュすると、自動で作り直される |

> **URL について**: 管理画面の「分析 ↗」は `ei8htplants-analytics.streamlit.app` を開くように作ってある。アプリを作るときにカスタム URL を `ei8htplants-analytics` にすると、この URL になる。名前が使えず別の URL になったときは、`frontend/src/pages/admin/AdminLayout.tsx` の `ANALYTICS_URL` を直す必要がある（開発担当に依頼する）。

## 2. 事前に用意するもの

| もの | どこで確認するか |
|---|---|
| Streamlit Community Cloud のアカウント | https://share.streamlit.io に GitHub のアカウントでログインする。このリポジトリ（ei8htplants-site）を見られる GitHub のアカウントを使う |
| Supabase の URL・anon キー・service_role キー | Supabase 管理画面 > Project Settings > API（サイト本体と同じ値） |
| 見てよい人のメールアドレス（`ANALYTICS_ALLOWED_EMAILS` に入れる。必ず用意する） | 運営メンバーで決める |
| （任意）GA4 のプロパティ ID と、読み取り用の鍵ファイル（JSON） | Google アナリティクスの管理 > プロパティの設定。鍵ファイルは Google Cloud のサービスアカウントで作り、GA4 で「閲覧者」の権限を付けたもの |

> キー・鍵ファイルの中身は、この資料・チャット・コミットに書かない。Community Cloud の Secrets の欄にだけ入れる。

### Supabase で新規登録ができないことを確かめる

分析ダッシュボードには、Supabase にログインできるアカウントなら入れる（`ANALYTICS_ALLOWED_EMAILS` で絞る前提）。Supabase で誰でも新規登録できる設定のままだと、第三者がアカウントを作れてしまうので、公開の前に次を確かめる。

1. Supabase 管理画面 > **Authentication** > **Sign In / Providers**（画面によっては **Settings**）を開く
2. **Allow new users to sign up**（新規登録を許可する）が**オフ**になっていることを確かめる。オンならオフにして保存する
3. 管理者のアカウントを増やすときは、Supabase 管理画面から招待・追加する（[OP-02](02_運用・保守マニュアル.md) の「5-4. 管理者アカウントの追加・削除」）

## 3. Community Cloud でアプリを作る

アプリは GitHub の `main` ブランチのコードから作られる。Community Cloud 向けの変更（リポジトリ直下の `.streamlit/config.toml`、`analytics/lib/secrets_env.py` など。2026-10-17）が `main` に入っていることを確かめてから作る。

1. https://share.streamlit.io を開き、右上の **Create app** を押す（GitHub のリポジトリから作る方を選ぶ）
2. 次の表のとおりに入力する

| 項目 | 入れる値 |
|---|---|
| Repository | このリポジトリ（ei8htplants-site） |
| Branch | `main` |
| Main file path | `analytics/app.py` |
| App URL（カスタム URL） | `ei8htplants-analytics`（→ `https://ei8htplants-analytics.streamlit.app`） |

3. **Advanced settings** を開き、次を入れる

| 項目 | 入れる値 |
|---|---|
| Python version | `3.12` |
| Secrets | 下の「4. Secrets を入れる」の内容を貼り付ける |

4. **Deploy** を押す。作り終わるまで数分待つ

- 使うライブラリは `analytics/requirements.txt`（`app.py` と同じフォルダにある）から自動で入る。Build Command のような指定は要らない
- Python のバージョンは 3 の Advanced settings で選ぶ。`analytics/.python-version`（3.12.9）は自分の PC で動かすとき用で、Community Cloud では使われない
- 画面の色・エラーの詳細を出さない設定は、**リポジトリ直下の `.streamlit/config.toml`** から読まれる（Community Cloud はこの場所の設定しか読まないため。詳しくは [DD-01 モジュール構成](../02_DD/01_モジュール構成.md) の 6 章）。待ち受けのアドレス・ポートは Community Cloud が決めるので、こちらで指定しない
- Streamlit の安全のための既定の設定（XSRF 保護など）は変えない

## 4. Secrets を入れる

Secrets は、パスワードやキーのような秘密の値を入れておく欄。アプリを作るときは 3 の **Advanced settings** の **Secrets** に、作ったあとで変えるときは、アプリの **Settings** → **Secrets** に入れる。書き方は TOML という形式（`名前 = "値"` を1行ずつ並べる）。値はこの資料には書かない。

| 名前 | 必須 | 何に使うか |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 必須 | Supabase の URL（ログインとデータの読み取り） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 必須 | ログインの確認だけに使う公開用のキー |
| `SUPABASE_SERVICE_ROLE_KEY` | 必須 | データの読み取りに使う。強い権限のキーなので、ほかの場所には絶対に書かない |
| `ANALYTICS_ALLOWED_EMAILS` | 推奨（実質必須） | 見てよい人のメールアドレス。カンマ区切り（例: `a@example.com,b@example.com`）。大文字・小文字は区別しない。入れないと、Supabase にログインできる人は全員見られる。Community Cloud のアプリの URL はインターネット上の誰でも開けるので、ログインとこの許可リストだけが守りになる。Supabase で新規登録ができる設定だと、第三者が登録して見られてしまうため、必ず設定する。リストから外した人は、次に画面を操作したときにログアウトされる |
| `GA_PROPERTY_ID` | 任意 | GA4 のプロパティ ID（数字だけ。`G-` で始まる測定 ID ではない）。アクセス解析の画面で使う |
| `GA_CREDENTIALS_JSON` | 任意 | GA4 の鍵ファイルの**中身**。Community Cloud には鍵ファイルを置く場所が無いので、ファイルの中身をそのまま入れる |

### 書き方の例（値はすべてダミー）

実際の値に置き換えて貼り付ける。

```toml
NEXT_PUBLIC_SUPABASE_URL = "https://xxxxxxxx.supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY = "ダミーの anon キー"
SUPABASE_SERVICE_ROLE_KEY = "ダミーの service_role キー"
ANALYTICS_ALLOWED_EMAILS = "owner@example.com,staff@example.com"
GA_PROPERTY_ID = "123456789"
GA_CREDENTIALS_JSON = '''
{
  "type": "service_account",
  "project_id": "example-project",
  "private_key_id": "0123456789abcdef",
  "private_key": "-----BEGIN PRIVATE KEY-----\nダミー\n-----END PRIVATE KEY-----\n",
  "client_email": "analytics-reader@example-project.iam.gserviceaccount.com",
  "token_uri": "https://oauth2.googleapis.com/token"
}
'''
```

- 値は**すべて一番外側**に書く（`[〜]` という見出しの下に入れない）。一番外側に書いた値だけを、分析ダッシュボードが読み取れる
- `GA_CREDENTIALS_JSON` は、鍵ファイル（JSON）を開いて中身をすべてコピーし、**`'''`（シングルクォート3つ）で前後を囲んで**貼り付ける。`"""`（ダブルクォート3つ）で囲むと、鍵の中の `\n` という文字が変わってしまう
- `GA_PROPERTY_ID`・`GA_CREDENTIALS_JSON` を入れないときは、アクセス解析の画面に設定の手順が表示されるだけで、ほかの画面は使える
- 鍵ファイルはリポジトリに入れない（コミットしない）。`.streamlit/secrets.toml` と `analytics/` 直下の JSON ファイルは `.gitignore` で除外している
- 自分の PC で動かすときは、これまでどおりリポジトリ直下の `.env` に書く（鍵は `GA_CREDENTIALS` に鍵ファイルの場所を書く方法も使える。`GA_CREDENTIALS_JSON` と両方あれば `GA_CREDENTIALS_JSON` を使う）

### Secrets を変えたとき

保存すると、少し待てば新しい値で動く。反映されないときは、アプリの画面右下の **Manage app** → メニュー（︙）の **Reboot app** で起動し直す。

## 5. 公開できたかの確認

| 順 | すること | 確認すること |
|---|---|---|
| 1 | Community Cloud の画面で、アプリが作り終わったことを見る | アプリの画面が開く。右下の **Manage app** を押すと出る記録（ログ）に、エラーが続けて出ていない |
| 2 | 管理画面にログインし、左のメニューの「分析 ↗」を押す | 新しいタブが開き、管理画面のタブはそのまま残る。新しいタブの URL が `https://ei8htplants-analytics.streamlit.app` |
| 3 | 開いた画面を見る | 「ei8ht plants 分析」の見出しと、メールアドレス・パスワードの入力欄だけが出ている（グラフは出ていない）。休止していたときは、起こすためのボタン（「Yes, get this app back up!」など）を押し、起動を待つ |
| 4 | 間違ったパスワードで「ログイン」を押す | 「メールアドレスまたはパスワードが違います。」と出る |
| 5 | 管理画面と同じメールアドレス・パスワードで「ログイン」を押す | 「概要」の画面が表示され、左のメニューに「ログイン中: （メールアドレス）」と「ログアウト」が出る |
| 6 | 左のメニューで「イベント収支」「ワークショップ」「ショップ」「問い合わせ・記事」「予測・シミュレーション」を順に開く | 数字・グラフが表示される。「データを読み込めませんでした」が出ない |
| 7 | （GA4 を設定したとき）「アクセス解析」を開く | 訪問者数などの数字が出る。設定の手順や「Google アナリティクスのデータを読み込めませんでした」が出ない |
| 8 | `ANALYTICS_ALLOWED_EMAILS` に入っていないアカウントでログインする（試せるアカウントがあるとき） | 「このアカウントでは閲覧できません。」と出て、中に入れない |
| 9 | 「ログアウト」を押す | ログイン画面に戻る |
| 10 | ブラウザを再読み込みする | もう一度ログインが必要になる |

## 6. うまくいかないとき

| 症状 | 考えられる原因と対処 |
|---|---|
| 「ログインの設定がありません（NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY）。」と出る | Secrets に `NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY` が無い、空、または `[〜]` の見出しの下に書いている。一番外側に書いて保存する |
| 正しいパスワードでも「メールアドレスまたはパスワードが違います。」と出る | 管理画面にはログインできるか確かめる。管理画面でも入れないなら、アカウントの問題（[OP-02 運用・保守マニュアル](02_運用・保守マニュアル.md) の「3-1. Admin にログインできない」）。管理画面には入れるなら、`NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY` がサイト本体と同じ値か確かめる |
| 「このアカウントでは閲覧できません。」と出る | `ANALYTICS_ALLOWED_EMAILS` にそのメールアドレスが入っていない。見てよい人なら、そのメールアドレスを `ANALYTICS_ALLOWED_EMAILS` に足して保存する（リストそのものは消さない） |
| 「ログインの失敗が続いたため、しばらく待ってからもう一度お試しください。」と出る | 5 回続けて失敗した。60 秒待ってからもう一度試す |
| 正しいパスワードでも、しばらくログインできない | ほかの人（第三者を含む）のログインの失敗が続くと、Supabase の回数制限にかかることがある（ログインは Community Cloud のサーバーから Supabase に送るため、みんなで同じ制限を使う）。時間をおいてから試す |
| ログイン中に、急にログイン画面に戻った | `ANALYTICS_ALLOWED_EMAILS` から外された。必要ならリストに戻す |
| 「認証サーバーに接続できませんでした。」と出る | Supabase につながらない。時間をおいて試す。続くときは `NEXT_PUBLIC_SUPABASE_URL` が正しいか確かめる |
| ログイン後に「データを読み込めませんでした」と出る | `SUPABASE_SERVICE_ROLE_KEY` が無い・間違っている。画面には「リポジトリ直下の .env …を確認してください」と出るが、Community Cloud では Secrets の値を確かめる |
| アクセス解析に「GA_PROPERTY_ID が設定されていません」と出る | Secrets に `GA_PROPERTY_ID` を入れる |
| アクセス解析に「GA の鍵が設定されていません」と出る | Secrets に `GA_CREDENTIALS_JSON` を入れる |
| アクセス解析に「GA_CREDENTIALS_JSON を JSON として読めません」と出る | 鍵ファイルの中身の貼り付けが崩れている。`'''` で前後を囲んでいるか、中身を途中まで・余分な文字ごとコピーしていないか確かめ、貼り直す |
| アクセス解析に「GA_CREDENTIALS_JSON に必要な項目がありません」「サービスアカウントの鍵ではありません」と出る | 別のファイルの中身を貼っている。GA4 用のサービスアカウントの鍵ファイル（JSON）の中身を貼り直す |
| 開くと「Yes, get this app back up!」のようなボタンが出る・開くまで時間がかかる | しばらく使われずに休止していた。ボタンを押し、起動するまで待つ。続けて使っている間は速い |
| 予期しないエラーが出た | 画面にはエラーの詳しい内容を出さない設定にしているので、右下の **Manage app** を押して出る記録（ログ）で内容を確かめる |
| 「分析 ↗」を押すと別のページ・エラーが出る | アプリの URL が `https://ei8htplants-analytics.streamlit.app` になっているか確かめる（「1. できあがりの形」の注） |

## 7. 更新のしかた

- 分析ダッシュボードのプログラム（`analytics/`）を直したら、`main` ブランチにプッシュする。Community Cloud が自動で作り直す。反映されたかは、アプリを開いて確かめる
- 反映されていないときは、右下の **Manage app** → メニュー（︙）の **Reboot app** で起動し直す
- 使うライブラリを変えたときは `analytics/requirements.txt` を直す（作り直すときに入れ直される）
- 画面の色・エラー表示などの設定（`.streamlit/config.toml`）は、リポジトリ直下と `analytics/` の中の**2か所にある**。変えるときは両方をそろえる（リポジトリ直下が公開用、`analytics/` の中が自分の PC 用）

## 8. やめるとき

1. https://share.streamlit.io を開き、アプリの一覧で分析ダッシュボードの右のメニュー（︙）から **Delete** を押す
2. サイト本体・Supabase のデータには影響しない
3. 削除したあとは、管理画面の「分析 ↗」が開けなくなるので、メニューから外すよう開発担当に依頼する

## 9. 移行: Render の分析サービスを削除する

Render で動かしていた分析ダッシュボードのサービス（`ei8htplants-analytics`）は、Community Cloud に移ったあとは使わない。動かしたままだと無料枠の時間を使い続けるので削除する。

1. この資料の 3〜5 の手順で Community Cloud のアプリを作り、「5. 公開できたかの確認」がすべて済んだことを確かめる
2. 新しい管理画面（「分析 ↗」が `https://ei8htplants-analytics.streamlit.app` を開くもの）が本番に反映されていることを確かめる
3. Render の Dashboard で、分析ダッシュボードのサービス **`ei8htplants-analytics`** を開く（**サイト本体のサービスと取り違えないこと**）
4. **Settings** の一番下にある **Delete Web Service** を押し、画面の案内に従って削除する
5. 削除後、サイト本体（公開サイト・管理画面）がいつもどおり開けることを確かめる

- 分析サービスに入れていた環境変数・Secret Files（GA4 の鍵ファイル）は、サービスと一緒に消える
- サイト本体のサービスに、分析ダッシュボードのために Build Filters（変更があったフォルダだけで作り直す設定）を入れていた場合は、もう不要なので外してよい（入れたままでも動作に問題はない）
