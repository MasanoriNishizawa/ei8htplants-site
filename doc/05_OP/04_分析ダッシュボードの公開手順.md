# OP-04 — 分析ダッシュボードの公開手順

（2026-10-17 作成）

分析ダッシュボード（`analytics/` フォルダ。売上・収支・予約・注文・アクセス数をグラフで見る画面）を、Render の**別の Web サービス**として公開する手順。サイト本体のサービスとは別に作るので、サイト本体の設定には触らない。

画面の内容・ログインの動きは [FT-25 分析ダッシュボード](../01_BD/features/14_分析ダッシュボード.md) を参照。

---

## 1. できあがりの形

| 項目 | 内容 |
|---|---|
| 公開先の URL | `https://ei8htplants-analytics.onrender.com`（管理画面のメニュー「分析 ↗」がこの URL を開く） |
| 見られる人 | 管理画面と同じメールアドレス・パスワードでログインでき、`ANALYTICS_ALLOWED_EMAILS` に入っている人 |
| データ | 本番の Supabase を読むだけ（書き換え・削除はしない） |
| 料金の枠 | 無料枠。15 分ほど使われないと止まり、次に開いたときに起動するまで 1 分ほど待つ（Render の無料枠の仕様）。メモリは 512MB で余裕が小さい。メモリ不足で落ちる場合は有料枠にする |

> **URL について**: 管理画面の「分析 ↗」は `ei8htplants-analytics.onrender.com` を開くように作ってある。Render のサービス名を `ei8htplants-analytics` にすると、この URL になる。名前が使えず別の URL になったときは、`frontend/src/pages/admin/AdminLayout.tsx` の `ANALYTICS_URL` を直す必要がある（開発担当に依頼する）。

## 2. 事前に用意するもの

| もの | どこで確認するか |
|---|---|
| Render にログインできるアカウント | サイト本体と同じアカウント |
| Supabase の URL・anon キー・service_role キー | Supabase 管理画面 > Project Settings > API（サイト本体のサービスと同じ値） |
| 見てよい人のメールアドレス（`ANALYTICS_ALLOWED_EMAILS` に入れる。必ず用意する） | 運営メンバーで決める |
| （任意）GA4 のプロパティ ID と、読み取り用の鍵ファイル（JSON） | Google アナリティクスの管理 > プロパティの設定。鍵ファイルは Google Cloud のサービスアカウントで作り、GA4 で「閲覧者」の権限を付けたもの |

> キー・鍵ファイルの中身は、この資料・チャット・コミットに書かない。Render の画面にだけ入れる。

### Supabase で新規登録ができないことを確かめる

分析ダッシュボードには、Supabase にログインできるアカウントなら入れる（`ANALYTICS_ALLOWED_EMAILS` で絞る前提）。Supabase で誰でも新規登録できる設定のままだと、第三者がアカウントを作れてしまうので、公開の前に次を確かめる。

1. Supabase 管理画面 > **Authentication** > **Sign In / Providers**（画面によっては **Settings**）を開く
2. **Allow new users to sign up**（新規登録を許可する）が**オフ**になっていることを確かめる。オンならオフにして保存する
3. 管理者のアカウントを増やすときは、Supabase 管理画面から招待・追加する（[OP-02](02_運用・保守マニュアル.md) の「5-4. 管理者アカウントの追加・削除」）

---

## 3. Render でサービスを作る

1. Render の Dashboard で **New** → **Web Service** を押す
2. サイト本体と同じ GitHub のリポジトリ（ei8htplants-site）を選ぶ
3. 次の表のとおりに入力する

| 項目 | 入れる値 |
|---|---|
| Name | `ei8htplants-analytics` |
| Language（Runtime） | Python 3 |
| Branch | `main` |
| Root Directory | `analytics` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `streamlit run app.py --server.address 0.0.0.0 --server.port $PORT --server.headless true` |
| Instance Type | Free |
| Build Filters（Included Paths） | `analytics/**`（Settings の Build & Deploy にある。`analytics/` の中が変わったときだけ作り直すため） |

- Python のバージョンは `analytics/.python-version`（3.12.9）で決まるが、念のため 4 章の環境変数 `PYTHON_VERSION=3.12.9` も入れる
- Start Command の `--server.address 0.0.0.0 --server.port $PORT` は、Render から画面を見られるようにするための設定。`analytics/.streamlit/config.toml` に書いてある `localhost`（自分の PC だけで開く設定）を、ここで上書きしている。外さないこと
- Streamlit の安全のための既定の設定（XSRF 保護など）は変えない。Start Command に余計な設定を足さない

4. 下の「4. 環境変数を入れる」を済ませてから **Create Web Service**（または **Deploy**）を押す

---

## 4. 環境変数を入れる

サービスを作るときは、作成画面の下の **Environment Variables** に入れる（Secret Files は同じ画面の **Advanced** の中）。作ったあとで変えるときは、サービスの **Environment** の画面で変える。値はこの資料には書かない。

| 名前 | 必須 | 何に使うか |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 必須 | Supabase の URL（ログインとデータの読み取り） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 必須 | ログインの確認だけに使う公開用のキー |
| `SUPABASE_SERVICE_ROLE_KEY` | 必須 | データの読み取りに使う。強い権限のキーなので、ほかの場所には絶対に書かない |
| `ANALYTICS_ALLOWED_EMAILS` | 推奨（実質必須） | 見てよい人のメールアドレス。カンマ区切り（例: `a@example.com,b@example.com`）。大文字・小文字は区別しない。入れないと、Supabase にログインできる人は全員見られる。Supabase で新規登録ができる設定だと、第三者が登録して見られてしまうため、必ず設定する。リストから外した人は、次に画面を操作したときにログアウトされる |
| `PYTHON_VERSION` | 推奨 | `3.12.9`。Render が使う Python のバージョン（`.python-version` と同じ値。念のため入れる） |
| `GA_PROPERTY_ID` | 任意 | GA4 のプロパティ ID（数字だけ。`G-` で始まる測定 ID ではない）。アクセス解析の画面で使う |
| `GA_CREDENTIALS` | 任意 | GA4 の鍵ファイルの場所。下の「Secret Files」に置いたファイルの場所 `/etc/secrets/<ファイル名>` を入れる |

### GA4 の鍵ファイルを置く（アクセス解析を使うときだけ）

1. サービスの **Environment** の画面の **Secret Files** で **Add Secret File** を押す
2. Filename に鍵ファイルの名前（例: `ga-service-account.json`）を入れ、Contents に鍵ファイルの中身を貼り付けて保存する
3. `GA_CREDENTIALS` に `/etc/secrets/ga-service-account.json`（2 で付けた名前）を入れる

- 鍵ファイルはリポジトリに入れない（コミットしない）。`analytics/` 直下の JSON ファイルと `.streamlit/secrets.toml` は `.gitignore` で除外しているが、それでも鍵はリポジトリの外か Render の Secret Files に置く
- `GA_PROPERTY_ID`・`GA_CREDENTIALS` を入れないときは、アクセス解析の画面に設定の手順が表示されるだけで、ほかの画面は使える

### 環境変数を変えたとき

環境変数を保存すると Render がサービスを作り直す。作り直しが終わるまで（数分）待ってから確認する。

## 5. 公開できたかの確認

| 順 | すること | 確認すること |
|---|---|---|
| 1 | Render のサービスの **Events**（または **Logs**）を見る | デプロイが「Live」になっている。Logs にエラーが続けて出ていない |
| 2 | 管理画面にログインし、左のメニューの「分析 ↗」を押す | 新しいタブが開き、管理画面のタブはそのまま残る。新しいタブの URL が `https://ei8htplants-analytics.onrender.com` |
| 3 | 開いた画面を見る | 「ei8ht plants 分析」の見出しと、メールアドレス・パスワードの入力欄だけが出ている（グラフは出ていない）。止まっていたときは、表示まで 1 分ほどかかる |
| 4 | 間違ったパスワードで「ログイン」を押す | 「メールアドレスまたはパスワードが違います。」と出る |
| 5 | 管理画面と同じメールアドレス・パスワードで「ログイン」を押す | 「概要」の画面が表示され、左のメニューに「ログイン中: （メールアドレス）」と「ログアウト」が出る |
| 6 | 左のメニューで「イベント収支」「ワークショップ」「ショップ」「問い合わせ・記事」「予測・シミュレーション」を順に開く | 数字・グラフが表示される。「データを読み込めませんでした」が出ない |
| 7 | （GA4 を設定したとき）「アクセス解析」を開く | 訪問者数などの数字が出る。設定の手順や「Google アナリティクスのデータを読み込めませんでした」が出ない |
| 8 | `ANALYTICS_ALLOWED_EMAILS` に入っていないアカウントでログインする（試せるアカウントがあるとき） | 「このアカウントでは閲覧できません。」と出て、中に入れない |
| 9 | 「ログアウト」を押す | ログイン画面に戻る |
| 10 | ブラウザを再読み込みする | もう一度ログインが必要になる |

## 6. うまくいかないとき

| 症状 | 考えられる原因と対処 |
|---|---|
| 「ログインの設定がありません（NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY）。」と出る | Environment に `NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY` が無い、または空。入れて保存する |
| 正しいパスワードでも「メールアドレスまたはパスワードが違います。」と出る | 管理画面にはログインできるか確かめる。管理画面でも入れないなら、アカウントの問題（[OP-02 運用・保守マニュアル](02_運用・保守マニュアル.md) の「3-1. Admin にログインできない」）。管理画面には入れるなら、`NEXT_PUBLIC_SUPABASE_URL`・`NEXT_PUBLIC_SUPABASE_ANON_KEY` がサイト本体と同じ値か確かめる |
| 「このアカウントでは閲覧できません。」と出る | `ANALYTICS_ALLOWED_EMAILS` にそのメールアドレスが入っていない。見てよい人なら、そのメールアドレスを `ANALYTICS_ALLOWED_EMAILS` に足して保存する（リストそのものは消さない） |
| 「ログインの失敗が続いたため、しばらく待ってからもう一度お試しください。」と出る | 5 回続けて失敗した。60 秒待ってからもう一度試す |
| 正しいパスワードでも、しばらくログインできない | ほかの人（第三者を含む）のログインの失敗が続くと、Supabase の回数制限にかかることがある（ログインは Render のサーバーから Supabase に送るため、みんなで同じ制限を使う）。時間をおいてから試す |
| ログイン中に、急にログイン画面に戻った | `ANALYTICS_ALLOWED_EMAILS` から外された。必要ならリストに戻す |
| 「認証サーバーに接続できませんでした。」と出る | Supabase につながらない。時間をおいて試す。続くときは `NEXT_PUBLIC_SUPABASE_URL` が正しいか確かめる |
| ログイン後に「データを読み込めませんでした」と出る | `SUPABASE_SERVICE_ROLE_KEY` が無い・間違っている。画面には「リポジトリ直下の .env …を確認してください」と出るが、Render では Environment の値を確かめる |
| アクセス解析に「GA_PROPERTY_ID が .env にありません。」などと出る | Render では `.env` ではなく Environment の `GA_PROPERTY_ID`・`GA_CREDENTIALS` を確かめる。「鍵ファイルが見つかりません」なら、Secret Files のファイル名と `GA_CREDENTIALS` のパスが合っているか確かめる |
| 開くまでとても時間がかかる | 無料枠で止まっていたため。1 分ほど待つ。続けて使っている間は速い |
| 使っている途中で落ちる・Logs にメモリ不足（out of memory など）が出る | 無料枠のメモリ（512MB）が足りない。Render の有料枠（メモリの多い Instance Type）にする |
| 予期しないエラーが出た | 画面にはエラーの詳しい内容を出さない設定にしているので、Render の **Logs** で内容を確かめる |
| 「分析 ↗」を押すと別のページ・エラーが出る | サービスの URL が `https://ei8htplants-analytics.onrender.com` になっているか確かめる（「1. できあがりの形」の注） |

## 7. 更新のしかた

- 分析ダッシュボードのプログラム（`analytics/`）を直したら、`main` ブランチにプッシュする。Render の Auto-Deploy が有効なら自動で作り直される。反映されたかは、サービスの **Events** で確かめる
- Build Filters に `analytics/**` を入れているので、`analytics/` 以外だけを変えたプッシュでは作り直されない。サイト本体のサービスにも `frontend/**`・`backend/**` などの Build Filters を設定しておくと、分析ダッシュボードだけを変えたときにサイト本体まで作り直さずに済む
- 反映されていないときは、サービスの画面の **Manual Deploy** → **Deploy latest commit** で作り直す
- 使うライブラリを変えたときは `analytics/requirements.txt` を直す（Build Command で入れ直される）

---

## 8. やめるとき

Render のサービスの **Settings** の一番下にある **Delete Web Service** で削除する。サイト本体・Supabase のデータには影響しない。削除したあとは、管理画面の「分析 ↗」が開けなくなるので、メニューから外すよう開発担当に依頼する。
