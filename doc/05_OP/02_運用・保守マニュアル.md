# OP-02 — 運用・保守マニュアル (Operation Manual)

対象者: 開発者・保守担当者

---

## 1. 日常監視

### ログ確認

```bash
# uvicorn アクセスログ（リアルタイム）
uvicorn app.main:app --host 0.0.0.0 --port 8000 2>&1 | tee access.log

# アクセスログのフォーマット例
INFO:     127.0.0.1:54321 - "GET /api/events HTTP/1.1" 200 OK
INFO:     127.0.0.1:54321 - "POST /api/contact HTTP/1.1" 200 OK
INFO:     127.0.0.1:54321 - "POST /api/contact HTTP/1.1" 500 Internal Server Error
```

### 定期確認項目

| 頻度 | 確認項目 | 方法 |
|---|---|---|
| 毎日 | 新規お問い合わせ確認 | Admin `/admin/contacts` |
| 毎日 | 新規予約確認 | Admin `/admin/reservations` |
| 週次 | サーバーエラー（5xx）がないか | uvicorn ログ確認 |
| 月次 | Resend API 使用量 | Resend ダッシュボード |
| 月次 | Supabase DB 使用量 | Supabase ダッシュボード |

## 2. バックアップ

### Supabase 自動バックアップ

Supabase Pro プランでは毎日自動バックアップが取られる。

手動バックアップが必要な場合:
```
Supabase管理画面 → Settings → Database → Backups → Capture backup
```

### コードバックアップ

Git リポジトリが最新の状態であること（`git push` が完了していること）。

## 3. 障害対応

### Admin にログインできない

| 手順 | 操作 |
|---|---|
| 1 | パスワードを確認する（正しい認証情報を使用しているか） |
| 2 | Supabase管理画面 → Authentication → Users → 対象ユーザーの [Send reset email] でパスワードリセット |
| 3 | Supabase 自体の障害かどうか `status.supabase.com` で確認 |

### ページが表示されない（500エラー）

| 手順 | 操作 |
|---|---|
| 1 | uvicorn ログを確認してエラーメッセージを特定する |
| 2 | 環境変数（`.env`）が正しく設定されているか確認 |
| 3 | Supabase 接続情報が正しいか確認 |
| 4 | `curl /api/events` でAPIが応答するか確認 |

### お問い合わせメールが届かない

| 手順 | 操作 |
|---|---|
| 1 | Admin `/admin/contacts` でDBにデータが保存されているか確認 |
| 2 | Resend ダッシュボードで送信ログを確認 |
| 3 | 環境変数 `RESEND_API_KEY` / `CONTACT_TO_EMAIL` / `CONTACT_FROM_EMAIL` を確認 |
| 4 | Resend でドメイン認証が有効か確認 |

### サーバープロセスが停止した

```bash
# プロセス確認
ps aux | grep uvicorn

# 再起動
cd backend
source venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8000 &
```

## 4. セキュリティ対応

### API Key が漏洩した場合

| 漏洩キー | 即時対応 |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase管理画面 → Settings → API → Service Role Key の [Regenerate] でローテーション。`.env` を更新してサーバー再起動 |
| `RESEND_API_KEY` | Resend管理画面でキーを無効化し、新しいキーを発行。`.env` を更新 |
| `VITE_SUPABASE_ANON_KEY` | Supabase管理画面でローテーション可能（anon key は公開前提なので影響は低いが念のため更新） |

### 不審なアクセスがある場合

```bash
# アクセスログで特定IPからの大量リクエストを確認
grep "POST /api" access.log | awk '{print $1}' | sort | uniq -c | sort -rn

# FastAPI の CORS 設定で許可 Origin を本番ドメインに制限
# backend/app/main.py の allow_origins を更新
```

## 5. 保守作業

### 依存パッケージの更新

```bash
# バックエンド（セキュリティアップデート確認）
pip list --outdated

# フロントエンド
npm outdated
```

更新前に必ずローカルでテストしてから本番に反映する。

### Supabase クライアントの更新

supabase-py または @supabase/supabase-js のメジャーバージョンアップ時は、API変更点を確認してから更新する。

### 管理者アカウントの追加

```
Supabase管理画面 → Authentication → Users → [Invite user]
メールアドレスを入力して招待メールを送信
```

---

## 6. 連絡体制

| 状況 | 連絡先 |
|---|---|
| 障害発生（サイト停止） | 開発者に直接連絡（緊急） |
| 機能追加・修正依頼 | 開発者にメール or 口頭で依頼 |
| コンテンツ更新（イベント等） | 管理者が Admin 画面から自己対応 |
