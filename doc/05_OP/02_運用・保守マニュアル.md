# OP-02 — 運用・保守マニュアル (Operation Manual)

対象者: 開発者・保守担当者

---

## 1. 日常監視

### ログ確認

```bash
# uvicorn アクセスログ（リアルタイム確認）
tail -f /path/to/access.log

# systemd ジャーナル（systemd使用時）
journalctl -u ei8htplants -f

# 5xx エラーだけ抽出
grep " 5[0-9][0-9] " access.log | tail -50

# 1時間以内の POST エラーを確認
grep "POST" access.log | grep " [45][0-9][0-9] " | awk -v d="$(date -v-1H '+%H:%M')" '$0 >= d'
```

### 定期確認項目

| 頻度 | 確認項目 | 手順 |
|---|---|---|
| 毎日 | 新規お問い合わせ確認 | Admin → [お問い合わせ]。未読バッジを確認 |
| 毎日 | 新規予約確認 | Admin → [WS予約]。`pending` 件数を確認 |
| 週次 | サーバーエラー（5xx）がないか | アクセスログを grep |
| 月次 | Resend API 使用量 | Resend ダッシュボード → Emails sent |
| 月次 | Supabase DB 使用量 | Supabase → Settings → Usage |
| 随時 | ギャラリー画像の表示確認 | Admin → [ギャラリー]。「URL無効」バッジがないか確認 |

## 2. バックアップ

### Supabase 自動バックアップ

Supabase Pro プランは毎日自動バックアップ。Free プランは自動バックアップなし（手動が必要）。

**手動バックアップ（Supabase管理画面）:**

```
Supabase管理画面 → Settings → Database → Backups → Capture backup
```

**pg_dump を使った手動バックアップ（接続情報は Supabase → Settings → Database → Connection string）:**

```bash
pg_dump "postgresql://postgres.<project-id>:<password>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres" \
  > backup_$(date +%Y%m%d).sql
```

### コードバックアップ

Git リポジトリが最新の状態であること。

```bash
git status   # 未コミットの変更がないことを確認
git log --oneline -5
```

## 3. 障害対応

### 3-1. Admin にログインできない

**症状**: メール・パスワードを入力してもエラーになる、またはログインフォームから進めない。

| 手順 | 操作 |
|---|---|
| 1 | パスワードを確認（Caps Lock・全角入力になっていないか） |
| 2 | `https://status.supabase.com` でSupabase Auth の障害がないか確認 |
| 3 | Supabase管理画面 → Authentication → Users → 対象ユーザーの [...] → [Send password recovery] でパスワードリセットメールを送信 |
| 4 | フロントエンドの VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY が正しいか確認 |

---

### 3-2. Admin 操作が 401 Unauthorized になる

**症状**: Admin でログインできているのに、イベント追加・削除などの操作が失敗する。

**原因の特定:**

```bash
# ブラウザのDevTools → Network タブでリクエストを確認
# Authorization ヘッダーが付いているか、値が "Bearer <token>" になっているか確認
```

| 原因 | 対処 |
|---|---|
| セッションが切れている | Admin 画面でログアウト → 再ログイン |
| バックエンドの `auth.py` がSupabaseに接続できない | サーバーの `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` を確認 |
| Supabase Auth サービス障害 | `https://status.supabase.com` を確認。回復を待つ |

---

### 3-3. ページが表示されない（500エラー）

**症状**: ブラウザに 500 または「Internal Server Error」が表示される。

```bash
# 1. uvicorn ログでエラートレースを確認
journalctl -u ei8htplants -n 100 --no-pager | grep -A 10 "ERROR\|Exception"

# 2. 環境変数が読み込まれているか確認
cat /path/to/ei8htplants-site/.env | grep SUPABASE

# 3. Supabase 接続確認（Pythonで直接テスト）
cd backend
source venv/bin/activate
python -c "from app.db import supabase; print(supabase.table('events').select('id').limit(1).execute())"

# 4. フロントエンドのビルド成果物が存在するか確認
ls frontend/dist/
```

| 原因 | 対処 |
|---|---|
| `.env` が正しく設定されていない | 環境変数を再確認・再起動 |
| `frontend/dist/` が存在しない | `cd frontend && npm run build` でビルド |
| Supabase 接続エラー | Supabase ダッシュボードでプロジェクトの状態を確認 |
| Python 依存パッケージが不足 | `pip install -r requirements.txt` を再実行 |

---

### 3-4. お問い合わせ・予約確認メールが届かない

**症状**: フォーム送信は完了（200 OK）するが、メールが届かない。

```bash
# Resend API キーが設定されているか確認
grep RESEND_API_KEY .env

# バックエンドログでResendのエラーを確認
grep -i "resend\|email" access.log | tail -20
```

| 手順 | 確認内容 |
|---|---|
| 1 | Admin → [お問い合わせ] で **DBにデータが保存されているか** 確認（DBに保存されていれば受信はできている） |
| 2 | Resend ダッシュボード → Emails でメール送信ログを確認（Delivered / Failed） |
| 3 | 環境変数 `RESEND_API_KEY` / `CONTACT_TO_EMAIL` / `CONTACT_FROM_EMAIL` を確認 |
| 4 | Resend でドメイン認証（`ei8htplants.com`）が有効か確認。無効なら再認証 |
| 5 | 受信側の迷惑メールフォルダを確認 |

---

### 3-5. サーバープロセスが停止した

```bash
# プロセス確認
ps aux | grep uvicorn
systemctl status ei8htplants   # systemd使用時

# 手動再起動
cd /path/to/ei8htplants-site/backend
source venv/bin/activate
nohup uvicorn app.main:app --host 0.0.0.0 --port 8000 &

# systemd での再起動
sudo systemctl restart ei8htplants

# systemd での自動起動設定（未設定の場合）
sudo systemctl enable ei8htplants
```

## 4. セキュリティ対応

### 4-1. キーが漏洩した場合

| 漏洩キー | 即時対処 |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → Service Role Key の [Regenerate] でローテーション。サーバーの `.env` を更新してプロセスを再起動 |
| `RESEND_API_KEY` | Resend 管理画面でキーを削除し、新しいキーを発行。`.env` を更新 |
| `VITE_SUPABASE_ANON_KEY` | anon key は公開前提だが、念のため Supabase → Settings → API → [Regenerate] でローテーション可能。フロントエンドを再ビルド・再デプロイ |

### 4-2. 不審なアクセスの調査

```bash
# 特定IPからの大量リクエストを確認
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -20

# Admin API への不正アクセス試行（401 が増えていないか）
grep "401" access.log | wc -l
grep "401" access.log | awk '{print $1}' | sort | uniq -c | sort -rn

# 短時間での大量POSTを確認（フォームスパム）
grep "POST /api/contact" access.log | awk '{print $1}' | sort | uniq -c | sort -rn
```

**対処:**
- 特定IPからの大量アクセスが確認できた場合: nginxやファイアウォールでIP遮断
- `backend/app/main.py` の `allow_origins` を本番ドメインのみに制限（現在は `localhost:5173` のみ許可済み。本番ドメインを追加する場合は `https://ei8htplants.com` を追加）

## 5. 保守作業

### 5-1. アプリケーションの更新デプロイ

```bash
# コードを取得
git pull origin main

# フロントエンド再ビルド
cd frontend
npm install
npm run build

# バックエンド依存関係更新（必要な場合）
cd ../backend
source venv/bin/activate
pip install -r requirements.txt

# サーバー再起動
sudo systemctl restart ei8htplants
```

### 5-2. DBマイグレーション（新しいマイグレーションがある場合）

```
1. backend/migrations/ の最新ファイルを確認
2. Supabase 管理画面 → SQL Editor でSQLを貼り付けて実行
3. アプリケーションを再起動（スキーマ変更後）
```

### 5-3. 依存パッケージの更新

```bash
# バックエンド（セキュリティアップデート確認）
cd backend
source venv/bin/activate
pip list --outdated
# 更新例
pip install --upgrade <package>==<new_version>
pip freeze > requirements.txt

# フロントエンド
cd frontend
npm outdated
npm update   # minor/patch のみ自動更新
```

> **注意**: メジャーバージョンアップ（特に supabase-py / @supabase/supabase-js）は API が変わる可能性がある。変更履歴を確認してからローカルでテスト後に反映する。

### 5-4. 管理者アカウントの追加・削除

**追加:**
```
Supabase 管理画面 → Authentication → Users → [Invite user]
メールアドレスを入力して招待メールを送信
```

**削除:**
```
Supabase 管理画面 → Authentication → Users → 対象ユーザーの [...] → [Delete user]
```

## 6. 連絡体制

| 状況 | 連絡先 | 目安対応時間 |
|---|---|---|
| サイト停止・致命的障害 | 開発者に直接連絡（緊急） | 即時対応 |
| 機能不具合・表示崩れ | 開発者にメール or 口頭 | 1〜3営業日 |
| コンテンツ更新（イベント等） | 管理者が Admin 画面から自己対応 | 即時 |
| 機能追加依頼 | 開発者に相談 | 要見積もり |
