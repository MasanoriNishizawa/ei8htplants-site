## 1. 管理画面へのアクセス

1. ブラウザで **https://ei8htplants.com/admin** を開く
2. 「ID」の欄に登録済みのメールアドレス、「パスワード」の欄にパスワードを入れて **[ログイン]** をクリック
3. 左のサイドメニューが出たらログイン完了。最初に **ダッシュボード** が開く（見方は「3. ダッシュボードの見方」）

> パスワードを忘れた場合は「24. 困ったときは」を参照。  
> スマホでは、左上のメニューボタン（☰）を押すとサイドメニューが開く。

## 3. ダッシュボードの見方（2026-10-21 追加）

管理画面にログインすると最初に開く画面。サイドメニューの **[ダッシュボード]** でいつでも戻れる。上から次の順に並ぶ。

1. **件数のカード**: 未読お問い合わせ・未発送の注文・公開中のイベントの数。押すとそれぞれの管理画面が開く
2. **出店料の支払い**: まだ払っていない出店料の一覧
3. **今後の搬入予定**: これから始まるイベントの搬入・搬出・ホテルの一覧
4. **管理メニュー**: 各管理画面へのカード

「出店料の支払い」「今後の搬入予定」は、イベントの **管理情報**（イベント一覧の **[管理情報]** から入力する、出店料・支払い期限・搬入・ホテルなど）をもとに作る。管理情報を入れておくと、イベントを1つずつ開かなくてもここでまとめて確かめられる。

### 出店料の支払い

**出るイベント**: 管理情報の「支払い済み」にチェックが入っていないイベントのうち、出店料（0円より多い）か支払い期限が入っているもの。終わったイベントでも、未払いなら残る。

**払い終わったら**: その行を押して管理情報の確認画面を開き、**[編集]** → 「支払い済み」にチェック → **[保存する]**。次にダッシュボードを開いたときから出なくなる。

**並び順と色**（急ぐものが上）

| 順 | 状態 | 見た目 |
|---|---|---|
| 1 | 支払い期限を過ぎた | 薄い赤の背景に「期限切れ」。支払い期限の横に「3日超過」のように過ぎた日数 |
| 2 | 支払い期限まで7日以内（今日が期限の日も含む） | 薄い黄色（クリーム色）の背景に「期限間近」。支払い期限の横に「あと3日」「今日まで」 |
| 3 | 支払い期限まで8日以上 | 白い背景。支払い期限の横に「あと20日」のように残りの日数 |
| 4 | 支払い期限が入っていない | 白い背景に「期限未設定」。支払い期限は「未入力」 |

同じ状態の中では、支払い期限の早い順に並ぶ。

各行には、イベント名・開催日・出店料・支払い方法・支払い期限が出る。

### 今後の搬入予定

**出るイベント**: 今日から60日先までに始まるイベント（開始日の早い順）。すでに始まったイベントは出ない。

各行には、イベント名・開催日・会場・搬入日時・搬出日時・ホテル名が出る。

### 2つの一覧で共通のこと

- 行を押すと、そのイベントの **管理情報の確認画面** が開く。**[← 戻る]** でダッシュボードに戻る
- 入っていない項目は、薄い色で「未入力」と出る。必要なら管理情報の編集画面で入れる
- 1件も無いときは「未払いの出店料はありません」「今日から60日以内に始まるイベントはありません」と出る
- 「今日」は使っているパソコン・スマホの日付で決まる
- スマホでも、各行は画面の幅に合わせて折り返して表示される

## 4. 分析ダッシュボードを見る（2026-10-17 追加）

売上・収支・ワークショップの予約・ショップの注文・問い合わせ・サイトのアクセス数を、グラフでまとめて見られる。見るだけの画面なので、ここで操作してもデータは変わらない。

1. 管理画面のサイドメニューの **[分析 ↗]**（「ダッシュボード」のすぐ下）をクリック
2. 新しいタブで分析ダッシュボードが開く（管理画面のタブはそのまま残る）。しばらく使っていないと休止していて、起動を待つ必要がある。英語で「Yes, get this app back up!」のようなボタンが出たときは押して、ログイン画面が出るまで待つ
3. 管理画面と同じメールアドレスとパスワードを入力して **[ログイン]** をクリック（管理画面にログインしていても、こちらで改めてログインする）
4. 左のメニューから見たい画面を選ぶ

   | 画面 | 見られる内容 |
   |---|---|
   | 概要 | 売上・収支・出店回数・WS 予約人数、月ごとの推移、今後のイベント |
   | イベント収支 | イベントごとの収支の順位、損益分岐点、支出の内訳、ブランド別などの比較 |
   | ワークショップ | 予約数、キャンセル率、時間枠の埋まり具合、予約のタイミング、リピーター |
   | ショップ | 注文数・売上、在庫（注文が 5 件以上たまると、商品の順位なども表示） |
   | 問い合わせ・記事 | 問い合わせの件数と未読数、記事の公開本数 |
   | アクセス解析 | サイトの訪問者数・よく見られているページ・どこから来たか |
   | 予測・シミュレーション | 今期の売上の見込み、出店するかどうかの試算 |

5. 左のメニューの **[会計年度]** で期間（4月〜翌3月）を絞り込める
6. 最新の内容にしたいときは左のメニューの **[データを再読み込み]** をクリック（押さなくても 10 分ごとに読み直す）
7. 終わったら左のメニューの **[ログアウト]** をクリック。ブラウザを再読み込みしたときも、もう一度ログインが必要になる

> 5 回続けてログインに失敗すると、60 秒はログインできない。

### アクセス解析に管理者の閲覧は入らない（2026-10-17 追加）

「アクセス解析」の訪問者数・ページビューには、管理者自身がサイトを見た分をなるべく入れないようにしている。

- 管理画面（/admin）を開いた分は、もともと数えていない
- 管理画面にログインしたままのブラウザで公開サイト（トップページやショップなど）を見た分も数えない。管理画面の **[ログアウト]** をすると、次に開いたページから数えるようになる（分析ダッシュボードの [ログアウト] では変わらない）
- 次の場合は、一般の訪問者と同じように数えられる
  - 管理画面にログインしていないスマホやパソコンで見たとき（ログアウトした後や、一度もログインしていない端末）
  - `ei8htplants.com` と `www.ei8htplants.com` は、ブラウザの中では別のサイトとして扱われる。管理画面にログインしたのと違う方のアドレスで公開サイトを見たとき

### 「予測・シミュレーション」の今期の売上の見込みの見方（2026-10-19 追加）

「予測・シミュレーション」の一番上の「今期のイベント売上の着地見込み」では、今期（4月〜翌3月）のイベント売上が年度末にいくらぐらいになりそうかを見られる。売上を入力したイベントが 5 回たまるまでは表示されない。

**4つの金額**

| 表示 | 意味 |
|---|---|
| ここまでの実績 | 今期すでに売上を入力したイベントの合計 |
| 控えめな見込み（下位10%） | うまくいかなかった場合の目安。10 回に 1 回はこれより低くなる |
| ふつうの見込み（中央値） | いちばんありそうな年度末の合計 |
| 良い見込み（上位10%） | うまくいった場合の目安。10 回に 1 回はこれより高くなる |

**どうやって見込んでいるか**

- 今期の、まだ売上を入力していないイベント（これからの予定と、開催したけれど入力していない回）1回ずつについて、売上を過去の実績からくじのように引いて足す。これを 5,000 回くり返し、結果のばらつきをグラフ（分布）にしている
- 過去にも出店した**同じイベント**（「vol.5」「第3回」「2026」などの回の番号を除いた名前が同じもの）は、その過去の売上を重視する。同じイベントの実績が多いほど重視する割合が上がる（実績1回で約33%、2回で50%、4回で約67%）。残りの割合は、全イベントの売上から引く
- 年に何回か開催するイベントは、**開催月が近い回**の売上ほど重視する（同じ月の回をいちばん重く、半年ずれた回はほぼ使わない）
  - 例: 春と秋に開催するマルシェで、過去に4月の回（10万円）と10月の回（30万円）があるとき、来年4月の回は、約33%の確率で4月の回の 10万円、残りは全イベントの売上から見込む。10月の回の 30万円はほぼ使わない
- 同じイベントの実績が無いイベントは、全イベントの売上だけで見込む

**「残りのイベントと参考にした実績」の表**

グラフの下に、まだ売上が入っていないイベントが1行ずつ並ぶ。

| 列 | 見方 |
|---|---|
| 同じイベントの過去の回数 | 同じイベントとしてまとめた過去の回の数 |
| 時期を考慮した実質の回数 | 開催月が近い回を 1、離れた回ほど小さく数えた回数（同じ月の回が2回なら 2.0） |
| 過去の売上の中央値 | 同じイベントの過去の売上の真ん中の値（開催月が近い回を重く見る）。「なし（全体の実績で見込み）」は、同じイベントの実績が無い・時期が離れた回しか無いため、全イベントの売上で見込んだという意味 |
| 同じイベントの重み | そのイベントの見込みを、同じイベントの過去の売上から引く割合 |
| まとめた過去の回 | 同じイベントとしてまとめた回の名前・開催した年月・重み。**ここで別のイベントがまとまっていないか、まとまるはずの回が抜けていないかを確かめる** |

**見込みを正確にするための入力のコツ**

1. **開催したら売上を入れる**: 管理画面のサイドメニューの **[イベント]** で該当イベントの **[収支]** を押し、「売上」を入力して **[保存]** をクリックする。売上が 0 円のままの回は「まだ入力していない」とみなされ、実績として使われない
2. **今後の出店予定を登録する**: 今期これから出店するイベントを、決まった時点で管理画面に登録しておく（「5-1. イベントを追加する」）。登録されていないイベントは見込みに入らない（見込みが低めに出る）
3. **同じイベントは、回の番号以外の名前をそろえる**: 「奇天烈 vol.5」と「奇天烈 vol.6」のように、番号（vol.5・第3回・6th・2026 など）以外を毎回同じ名前にする。「奇天烈 vol.5」と「奇天烈マーケット vol.6」のように名前が変わると、別のイベントとして扱われる。スペース・記号・英字の大文字小文字・全角半角の違いは気にしなくてよい
   - 「Vol.1」「Vol.2」のように番号だけの名前は、別々のイベントとして扱われる。イベント名を入れる

> 見込みは過去の実績から計算した目安で、売上を約束するものではない。実績が少ないうちは幅が広く出る。

## 5. イベント

サイドメニューの **[イベント]** を押すと「イベント管理」の画面が開く。「今後のイベント」（開始日の早い順）と「過去のイベント」（新しい順）に分かれて並ぶ。終了日（無ければ開始日）が過ぎると、自動で「過去のイベント」に移る。

### 5-1. イベントを追加する

1. 右上の **[+ 新規追加]** を押す
2. 「新規イベント」の画面で、次の項目を入れる

   | 項目 | 必須 | 入力内容・例 |
   |---|---|---|
   | イベント名 | 必須 | 「PLANTSALE 2026」 |
   | URL スラッグ | 任意 | イベント専用ページのアドレスの最後の部分（英小文字・数字・ハイフンだけ）。例 `plant-market-2026` にすると `ei8htplants.com/events/plant-market-2026` になる。新しく作るときは、イベント名を入れるとそれに合わせて自動で入る（日本語だけの名前では空のままなので、自分で入れる）。この欄を自分で書き換えると、その後はイベント名を変えても変わらない。**[自動生成]** を押すとイベント名から作り直し、また名前に合わせて変わるようになる。すでにスラッグが入っているイベントを編集するときは、名前を変えてもスラッグは変わらない |
   | 開始日 | 必須 | カレンダーから選ぶ。下に「確認: 2026-05-01」と出るので、年が正しいか確かめる（2020年より前だと赤字になる） |
   | 終了日 | 任意 | 2日以上続くイベントのときだけ入れる |
   | 開催時間 | 任意 | 開始と終了の時刻をそれぞれ選ぶ（30分ごと）。2日以上のイベントでは **「日ごとに異なる」** にチェックを入れると、日付ごとに時刻を選べる |
   | 会場名 | 必須 | 「東京ビッグサイト」 |
   | ブース番号 | 任意 | 「A-123」 |
   | 住所 | 任意 | 「東京都江東区有明3-11-1」（検索結果にイベント情報を出すのに使うので、なるべく入れる） |
   | 公式サイトURL | 任意 | `https://...` の形で入れる |
   | 販売ブランド | 任意 | 出展するブランドにチェック |
   | 画像（複数可） | 任意 | 点線の **[＋ 追加]** の枠を押して、パソコン・スマホの写真を選ぶ（一度に何枚でも選べる）。右上の赤い **[×]** で外せる |
   | ワークショップあり | 任意 | ワークショップを開くときにチェック |
   | 予約必要 | 任意 | 「ワークショップあり」にチェックすると出る（最初からチェック済み）。チェックがあると、公開ページに予約ボタンが出る |

3. 「ワークショップあり」にチェックすると、**WSセッション（各回の時間・定員）** の欄が出る
   - **[+ 追加]**: 1回分の行が増える。時間（例「10:00〜11:30」）と定員（人数）を入れる。右の **[×]** で消せる
   - **[自動設定]**: 開催時間が入っているときに押せる。開始の1時間後から終了の1時間前まで、1時間ごと・定員4名の回をまとめて作る（今ある行は置き換わる）
   - 1回も無いときは「時間指定なしで予約受付」になる
4. **[保存する]** を押す（写真のアップロード中は「アップロード中...」と出て押せない）。イベント一覧に戻る
5. 公開ページの `/events` に出ていることを確かめる

### 5-2. イベント一覧のボタン

各イベントの右に次のボタンが並ぶ。

| ボタン | 何をするか |
|---|---|
| **[編集]** | 「イベント編集」の画面を開く。中身は「5-1」と同じ。いちばん下の **[管理情報を編集]** から管理情報も開ける |
| **[管理情報]** | 搬入・搬出・宿泊・出店料・出店要項・メモの確認画面を開く（5-5） |
| **[画像DL]** | イベントに登録した写真を1枚ずつ保存する画面を開く（5-6） |
| **[収支]** | 売上・支出を入れる「収支管理」の画面を開く（5-3） |
| **[サイト]** | イベント専用ページの中身を編集する「サイト編集」の画面を開く（5-4） |
| **[予約 N件]** | 「ワークショップあり」のイベントだけに出る。N はキャンセル以外の予約の件数。押すと「WS予約」の画面が、そのイベントに絞り込んだ状態で開く（8章） |
| **[予約管理（印刷・CSV）]** | 「ワークショップあり」のイベントだけに出る。そのイベントだけの予約画面を開く。印刷・CSV の保存・予約ページのリンクのコピーができる（8-5。2026-10-22 追加） |
| **[複製]** | すぐに同じ内容のイベントを1件作る（名前の後ろに「(コピー)」が付く）。日付・開催時間・会場・ブース番号・住所・公式サイトURL・ブランド・写真・「ワークショップあり」「予約必要」が写る。日ごとの開催時間・WSセッション・収支・管理情報・サイトの中身・URL スラッグは写らないので、複製したイベントの **[編集]** で直す |
| **[削除]** | 確認が出るので **[OK]** を押すと消える |

> 削除したデータは管理画面からは元に戻せない。誤って削除したときは開発者に連絡する。

> **[複製]**・**[削除]** を押してから終わるまでは、どの行の **[複製]**・**[削除]** も押せない（2回押して2件できるのを防ぐ）。

### 5-3. 収支（イベントごと）

イベント一覧の **[収支]**（または「全体の収支」の **[編集]**）で開く。

- **収入**: 売上。ワークショップありのイベントでは「WS参加人数」も入れる（WS売上 = 人数 × 1,000円 が自動で出る）
- **手伝いあり（支払い計算モード）**: オンにすると、手伝いの人への支払い金額を「(売上 − WS売上 − 支出) × 20% + WS売上 × 70%」で計算して、収支から引く（赤字のときはマイナスになる）
- **支出**: 出店料・距離（片道）・ガソリン単価・高速代・宿泊費・その他支出。移動費は「往復の距離 ÷ 10km × ガソリン単価」で自動で出る。ワークショップの材料費（人数 × 700円）も自動で引かれる
- **メモ**: 自由に書ける
- **[保存]** を押すと保存され、開いた元の画面（イベント管理・全体の収支）に戻る

> 出店料と宿泊費は、管理情報（5-5）と同じ値を使う。収支で保存すると管理情報の出店料・宿泊料金が、管理情報で保存すると収支の出店料・宿泊費が、同じ値に書き換わる。

### 5-4. サイト（イベント専用ページの中身）

- 保存したあとに公開ページを開くと、URL スラッグのアドレス・イベント ID のアドレスのどちらで開いても、保存した最新の中身が出る（同じブラウザで開いたとき）

### 5-5. 管理情報（搬入・宿泊・出店料など）

## 8. ワークショップ予約（WS予約）

### 8-1. 予約を見る

1. サイドメニューの **[WS予約]** を押す
2. 上のタブで **[今後の開催]**・**[過去の開催]** を切り替える
3. 右上のプルダウンでイベントを選ぶと、そのイベントの予約だけになる（**[すべてのイベント]** で全部）。今日ワークショップを開いているイベントがあると、最初からそのイベントに絞り込まれる
4. 予約は希望日・時間の順に並ぶ。上に「全N件 / N名」が出る。この件数と人数には **キャンセルした予約は入らない**（2026-10-22 変更。それまでは入っていた。イベント別の予約画面と同じ数え方にした）

予約者の名前の横に赤い **「メール未送信」** の印があるときは、予約の確認メールが送れなかった（送信に失敗した、または相手に届かなかった）。予約は受け付けているので、電話番号などで本人に連絡する。

スマホでは予約がカードで並ぶ。カードを押すと、下から詳しい内容（受付日・メール・電話・希望日・時間・人数・持込・備考）が出る。

### 8-2. 予約のステータス

ステータスは次の2つだけ。

| ステータス | 意味 |
|---|---|
| 受付済（緑） | 予約を受け付けた状態。予約が入るとこの状態になる |
| キャンセル（赤） | キャンセルされた予約 |

- お客様は、予約の確認メールのリンクから自分でキャンセルできる。そのときは自動で「キャンセル」になる
- 管理者がキャンセルにするときは、パソコンでは表の「ステータス」のプルダウン、スマホではカードを押して出る画面のプルダウンで **「キャンセル」** を選ぶ。**選んだ時点でお客様にキャンセルのお知らせメールが送られる**ので、間違えないように気をつける
- キャンセルにすると、その回の空き（残りの枠）が1件分戻る

> 予約が入ると、お客様に確認メール（キャンセル用のリンク付き）、Habitat Oides の管理者に通知メールが自動で送られる。

### 8-3. 当日参加を追加する

ワークショップの当日に、予約なしで来た人を記録する。

1. **[今後の開催]** のタブで **[当日参加を追加]** を押す
2. イベント（今日開催のイベントが1つなら自動で選ばれる）・参加日・時間枠（「残N枠」と出る）・参加人数を選ぶ
3. **[登録]** を押す

名前は「当日参加」として、ステータスは「受付済」で入る。メールは送られない。

### 8-4. 印刷する

右上の **[PDF で印刷]** を押すと、今表示している予約の一覧が印刷用に新しいウィンドウで開く。イベントを選んでいるときは、時間枠ごと・日付ごとに分かれ、空いている枠の行も出る。印刷の画面で「PDF に保存」を選ぶと PDF にできる。

- 時間枠ごとの「予約人数 / 定員」と空いている枠の行の数は、キャンセルした予約を除いて数える（キャンセルした予約の行は一覧には出る。2026-10-22 変更）
- いちばん上の「予約件数」「合計人数」は、印刷した予約をすべて数える（キャンセルも含む）。画面の「全N件 / N名」と数が違うことがある

### 8-5. イベント別の予約画面（CSV・予約リンクのコピー）

イベントごとの予約画面もある。イベント一覧（5-2）の **[予約管理（印刷・CSV）]** を押して開く（2026-10-22 追加。「ワークショップあり」のイベントだけに出る）。左上の **[← イベント管理]** でイベント一覧に戻る。

| ボタン | 何をするか |
|---|---|
| **[予約ページリンクをコピー]** | お客様向けの予約ページのアドレス（`https://ei8htplants.com/reserve?event_id=…`）をコピーする。2秒間「コピーしました」と出る。SNS やメールに貼って使う。ブラウザの設定などでコピーできなかったときは「リンクをコピーできませんでした。次の URL を選択してコピーしてください: （アドレス）」と出るので、アドレスを選んで自分でコピーする |
| **[当日参加を追加]** | 8-3 と同じ。時間枠を選ばずに時間を手で入れることもできる |
| **[印刷]** | 予約の一覧を印刷用に新しいウィンドウで開く |
| **[CSV]** | 予約の一覧を CSV ファイル（Excel で開ける表）で保存する |

時間枠が登録されているイベントでは、**[全て]** と時間枠ごとのボタンで絞り込める。印刷と CSV は、絞り込んだ内容で出る。

- 上の「全N件 / N名」はキャンセルを除いた数。印刷のいちばん下の「合計 N 件 / N 名」は、印刷した予約をすべて数える（キャンセルも含む）
- 読み込み・状態の変更・当日参加の追加に失敗したときは、赤い枠でわけを出す。状態の変更に失敗したときは元の状態のまま変わらない（満席の回の予約を「受付済」に戻そうとしたときは「満席のため受付済に戻せません。元の状態のままです」）

- **[編集]** でそのイベントの収支の画面（5-3）が開く。収支をまだ入れていないイベントは「—」と出る
- スマホでは表が横にスクロールする。**[編集]** の列は右端に止まったまま見える（2026-10-23）

**収支合計の内訳の見方**（2026-10-23 追加）: 合計の下に「収支合計 = 売上 ◯円 − 支出 ◯円 − WS 資材費 ◯円 − 手伝いへの支払い ◯円」のような式が小さく出る。「売上 − 支出」だけでは収支合計と合わないことがあるため、引いている項目と金額を示している。

- 0円の項目（WS 資材費・手伝いへの支払い）は式に出さない
- 手伝いのあるイベントが赤字だと、手伝いの人が赤字を分担するので、その分は「＋ 手伝いの赤字の分担 ◯円」として足す
- WS 売上は売上に含めて入力しているので、式には別に出さない。手伝いへの支払いは「支払対象: あり」のイベントの分

### 14-2. 支払い集計

「手伝いあり」のイベントについて、売上の利益分（(売上 − WS売上 − 支出) × 20%）を年度ごとに足した金額を出す。

- 年度ごとに、イベント別の内訳・年間合計・**翌年度の月額支払い**（年間合計 ÷ 12）が出る
- ワークショップの分は入らない（14-3 で管理する）

### 14-3. ワークショップ集計

ワークショップありで参加人数を入れたイベントを年度ごとに並べ、手伝いの人への支払い（700円 × 参加人数）を管理する。

- 各イベントの「件数」（参加人数）・「金額」が出る
- 支払ったら「支払い済み」にチェックを入れる（すぐ保存される。外すと未払いに戻る）
- 下の合計の行に、合計人数・合計金額・支払い済みの金額が出る

> 参加人数は、各イベントの収支の画面（5-3）の「WS参加人数」から取る。

## 22. 保存していない変更の確認（2026-10-21 追加。2026-10-23 に対象の画面を増やした）

次の画面で入力を変えて、まだ保存していないとき（入力欄に書きかけがあるとき）に、別の画面へ移ろうとすると確認が出る。

| 画面 | 確認の対象 |
|---|---|
| イベントの追加・編集（5-1） | すべての入力欄・写真・WS セッション・日ごとの開催時間 |
| イベントの管理情報の編集（5-5） | すべての入力欄・出店要項の写真 |
| イベントの収支（5-3） | すべての入力欄 |
| イベントのサイト編集（5-4） | すべての入力欄 |

| チャットQ&A（19章） | 追加・編集の欄を開いて内容を変えたとき |
| 取扱店（7章） | 追加の欄に何か入れているとき、編集の画面で内容を変えたとき |
| 販売価格計算（15章） | 植物名・仕入れ値などに何か入れているとき（ブランドのタブを切り替えるときも確認が出る） |
| 記事管理・商品管理の編集の画面 | 開いたときから内容を変えたとき |
| お問い合わせの返信の画面 | 件名・本文を変えたとき |

確認が出る操作:

- サイドメニュー（スマホでは左上のメニューボタンで開くメニュー）のリンク、**[ログアウト]** を押したとき
- 画面の中の **[キャンセル]**・**[← 戻る]**・**[管理情報を編集]**（イベントの編集画面）を押したとき
- 次の方法で編集の画面を閉じようとしたとき（「保存していない変更があります。破棄して閉じますか？」と出る）
  - 記事・商品の編集、お問い合わせの返信、取扱店の編集の画面: **[キャンセル]**・**[×]**（ある画面だけ）・画面の外側・Esc キーのどれで閉じるときも
  - チャットQ&A: フォームの **[キャンセル]**・Esc キー、別の Q&A の **[編集]**、**[+ 追加]**
  - 保存中・送信中は、これらの操作をしても画面は閉じない
- ページの再読み込み・タブを閉じるとき（ブラウザの確認が出る。文言はブラウザが決める）

| 押すボタン | どうなるか |
|---|---|
| **[OK]** | 入力した内容を捨てて、押したページへ移る（ログアウトのときはログアウトする） |
| **[キャンセル]** | 移動しない。画面と入力した内容はそのまま残る。続けて保存できる |

「書きかけ」かどうかの決め方（2026-10-23）:

- 空欄は、もともと空だった欄も、入力してから消した欄も、同じ「未入力」として扱う（入力して消しただけでは確認は出ない）
- ブランドや関連商品のチェックは、選んだ順番が違うだけなら変更とみなさない

次のときは確認は出ない。

- 保存に成功したあと
- **[分析 ↗]** を押したとき（新しいタブで開くので、今の画面はそのまま残る）
- 今いる画面と同じメニューを押したとき
- Ctrl（Mac では Command）などのキーを押しながらメニューを押して、新しいタブで開いたとき
- 注文の発送情報（配送会社・追跡番号）、WS予約の予約の詳細と当日参加の入力、ギャラリーの ALT テキストは対象外（書きかけのまま離れると消える。予約の詳細・当日参加の画面は Esc キーでは閉じない）
- ブラウザの「戻る」ボタンで移ったとき（下の注意）

> **注意**: 確認が出るのは、サイドメニュー・画面の中のリンクやボタン・ページの再読み込み・タブを閉じるときだけ。ブラウザの「戻る」ボタン（スマホの戻る操作も）で離れたときは、確認が出ずに入力が消える（仕様）。画面から離れる前に、必ず保存する。
