# OP-03 — ユーザーマニュアル (User Manual)

対象者: ei8ht plants 管理者（サイトオーナー）  
前提: Google Chrome または Safari の最新版を使用

---

## 1. 管理画面へのアクセス

1. ブラウザで **https://ei8htplants.com/admin** を開く
2. 登録済みのメールアドレスとパスワードを入力して [ログイン] をクリック
3. サイドバーに管理メニューが表示されたらログイン完了

> パスワードを忘れた場合は「11. 困ったときは」を参照。

---

## 2. イベントを追加する

1. サイドバーの **[イベント]** をクリック
2. 右上の **[+ 新規イベント]** ボタンをクリック
3. フォームに入力する

   | 項目 | 必須 | 入力内容・例 |
   |---|---|---|
   | イベント名 | 必須 | 「PLANTSALE 2026」|
   | 開始日 | 必須 | カレンダーから選択 |
   | 終了日 | 任意 | 複数日開催の場合のみ |
   | 時間 | 任意 | 「11:00〜17:00」|
   | 会場名 | 必須 | 「東京ビッグサイト」|
   | ブース番号 | 任意 | 「A-123」|
   | 住所 | 任意 | 「東京都江東区有明3-11-1」|
   | 公式サイトURL | 任意 | `https://...` の形式で入力 |
   | 販売ブランド | 任意 | 出展するブランドにチェック |
   | ワークショップあり | 任意 | WS開催の場合にチェック |
   | 予約必要 | 任意 | 「ワークショップあり」をチェックした場合に表示。予約フォームを公開する場合はチェック |
   | 過去のイベント | 任意 | 終了したイベントをアーカイブする場合にチェック |
   | 画像URL | 任意 | 画像の URL を入力（複数枚可。入力するたびに新しい行が追加される） |

4. [保存する] をクリック
5. 公開ページの `/events` に表示されていることを確認する

---

## 3. イベントを編集・削除する

**編集:**
1. [イベント] 一覧で対象イベントの **[編集]** をクリック
2. 内容を変更して **[保存する]**

**削除:**
1. 対象イベントの **[削除]** をクリック
2. 確認ダイアログで **[OK]**

> 削除したデータは復元できません。誤って削除した場合は開発者に連絡してください。

---

## 4. ギャラリー画像を追加・削除する

**追加:**
1. サイドバーの **[ギャラリー]** をクリック
2. 上部フォームに画像 URL を入力（URL の取得方法は「9. 画像URLの取得方法」参照）
3. ALT テキスト（検索エンジン向けの説明文、任意）を入力
4. ブランドを選択（任意。ブランドページのギャラリーに反映される）
5. **[追加]** をクリック

**削除:**
1. 削除したい画像の右上 **[×]** をクリック

> 画像の右上に「URL無効」バッジが表示されている場合は、URL が正しくないか画像の共有設定が変わっています。削除して正しい URL で追加し直してください。

---

## 5. 取扱店を管理する

**追加:**
1. **[取扱店]** をクリック
2. フォームに店舗名・エリア・住所・URL を入力
3. 取扱ブランドにチェック
4. **[追加]** をクリック

**編集:**
1. 対象店舗の **[編集]** をクリック
2. ポップアップで内容を変更して **[保存]**

**削除:**
1. 対象店舗の **[削除]** をクリック

---

## 6. ワークショップ予約を確認する

1. サイドバーの **[WS予約]** をクリック
2. 予約一覧が **受付日の新しい順** で表示される
3. ステータスを変更する場合は、ステータス列のプルダウンから選択する

   | ステータス | 意味 |
   |---|---|
   | 未確認（黄） | 予約を受け付けたが、まだ確認していない初期状態 |
   | 確認済み（緑） | 予約を確認し、お客様に案内済み |
   | キャンセル（赤） | キャンセルされた予約 |

> 予約が入ると、お客様に自動で確認メールが送信されます（Resend 経由）。

---

## 7. お問い合わせを確認・対応する

1. サイドバーの **[お問い合わせ]** をクリック
2. 未読のお問い合わせがある場合、ヘッダーに **「未読 N」** バッジが表示される
3. 行をクリックするとメッセージ内容が展開される
4. **[既読にする]** をクリックして対応済みにマークする
5. **[返信する (メールアドレス)]** をクリックするとメールアプリが起動し、返信先が自動入力される

> お問い合わせ送信時に管理者メール（CONTACT_TO_EMAIL）に通知が届きます。

## 8. コラボレーション記事を管理する

**追加:**

2. フォームにタイトル・コラボ相手・開催日・画像 URL・動画 URL・説明文を入力
3. **[追加]** をクリック

**削除:**

## 9. 画像のアップロード方法

管理画面の各フォームには **[ファイル]** ボタンが用意されています。

### ファイルアップロードで追加する（推奨）

1. 画像 URL 入力欄の右にある **[ファイル]** ボタンをクリック
2. ローカルの画像ファイルを選択（JPEG / PNG / WebP / GIF、10 MB 以内）
3. アップロードが完了すると URL 欄に自動入力される
4. そのまま **[追加]** または **[保存する]** をクリック

> アップロードされた画像は Supabase Storage（`images` バケット）に保存されます。削除する場合は対象レコードを管理画面から削除してください（ストレージ上のファイルは別途管理が必要です）。

### URL 直接入力で追加する

外部サービスで公開済みの画像 URL がある場合は、URL 欄に直接入力することもできます。  
URL が失効すると画像が表示されなくなるため、重要な画像はファイルアップロードを使うことを推奨します。

## 11. 困ったときは

| 症状 | 対処 |
|---|---|
| ログインできない（パスワードを忘れた） | 開発者に連絡。Supabase管理画面からパスワードリセットメールを送信してもらう |
| ログインできない（エラーが出る） | メールアドレスのスペルミス・Caps Lock を確認。解決しない場合は開発者に連絡 |
| 変更が公開ページに反映されない | ブラウザを強制リロード（Ctrl+Shift+R / Cmd+Shift+R）。それでも反映されない場合は開発者に連絡 |
| 画像が「URL無効」と表示される | 画像 URL が失効している可能性があります。対象画像を一度削除し、ファイルアップロードで再登録してください |
| イベントを誤って削除した | 削除したデータは管理画面から復元できません。開発者に連絡（Supabase バックアップから復旧可能な場合あり） |
| メールが届かない | 迷惑メールフォルダを確認。それでも届かない場合は開発者に連絡 |
| 「分析 ↗」を押しても画面がなかなか出ない・英語の画面とボタンが出る | しばらく使われていないと休止する仕組みのため。「Yes, get this app back up!」のようなボタンが出たら押し、ログイン画面が出るまで待つ（2026-10-17 追加・更新） |
| 分析ダッシュボードで「ログインの失敗が続いたため…」と出る | 5 回続けて失敗した。60 秒待ってからもう一度ログインする（2026-10-17 追加） |
| 分析ダッシュボードで「このアカウントでは閲覧できません。」と出る | 見てよい人に入っていない。開発者に連絡（2026-10-17 追加） |
| 分析ダッシュボードで、ログイン中に急にログイン画面に戻った | 見てよい人から外された可能性がある。開発者に連絡（2026-10-17 追加） |
| 分析ダッシュボードでログインに失敗すると、入力欄が空になる | パスワードを画面に残さないため。メールアドレスとパスワードをもう一度入れる（2026-10-17 追加） |
| その他 | 開発者（masanorinishizawa）に連絡 |

## 12. 分析ダッシュボードを見る（2026-10-17 追加）

売上・収支・ワークショップの予約・ショップの注文・問い合わせ・サイトのアクセス数を、グラフでまとめて見られる。見るだけの画面なので、ここで操作してもデータは変わらない。

1. 管理画面のサイドバーの **[分析 ↗]**（「ダッシュボード」のすぐ下）をクリック
2. 新しいタブで分析ダッシュボードが開く（管理画面のタブはそのまま残る）。しばらく使っていないと休止していて、起動を待つ必要がある。英語で「Yes, get this app back up!」のようなボタンが出たときは押して、ログイン画面が出るまで待つ
3. 管理画面と同じメールアドレスとパスワードを入力して **[ログイン]** をクリック（管理画面にログインしていても、こちらで改めてログインする）
4. 左のメニューから見たい画面を選ぶ

   | 画面 | 見られる内容 |
   |---|---|
   | 概要 | 売上・収支・出店回数・WS 予約人数、月ごとの推移、今後のイベント |
   | イベント収支 | イベントごとの収支の順位、損益分岐点、支出の内訳、ブランド別などの比較 |
   | ワークショップ | 予約数、キャンセル率、時間枠の埋まり具合、予約のタイミング、リピーター |
   | ショップ | 注文数・売上、在庫（注文が 5 件以上たまると、商品の順位なども表示） |
   | 問い合わせ・記事 | 問い合わせの件数と未読数、記事の公開本数 |
   | アクセス解析 | サイトの訪問者数・よく見られているページ・どこから来たか |
   | 予測・シミュレーション | 今期の売上の見込み、出店するかどうかの試算 |

5. 左のメニューの **[会計年度]** で期間（4月〜翌3月）を絞り込める
6. 最新の内容にしたいときは左のメニューの **[データを再読み込み]** をクリック（押さなくても 10 分ごとに読み直す）
7. 終わったら左のメニューの **[ログアウト]** をクリック。ブラウザを再読み込みしたときも、もう一度ログインが必要になる

> 5 回続けてログインに失敗すると、60 秒はログインできない。

### アクセス解析に管理者の閲覧は入らない（2026-10-17 追加）

「アクセス解析」の訪問者数・ページビューには、管理者自身がサイトを見た分をなるべく入れないようにしている。

- 管理画面（/admin）を開いた分は、もともと数えていない
- 管理画面にログインしたままのブラウザで公開サイト（トップページやショップなど）を見た分も数えない。管理画面の **[ログアウト]** をすると、次に開いたページから数えるようになる（分析ダッシュボードの [ログアウト] では変わらない）
- 次の場合は、一般の訪問者と同じように数えられる
  - 管理画面にログインしていないスマホやパソコンで見たとき（ログアウトした後や、一度もログインしていない端末）
  - `ei8htplants.com` と `www.ei8htplants.com` は、ブラウザの中では別のサイトとして扱われる。管理画面にログインしたのと違う方のアドレスで公開サイトを見たとき

### 「予測・シミュレーション」の今期の売上の見込みの見方（2026-10-19 追加）

「予測・シミュレーション」の一番上の「今期のイベント売上の着地見込み」では、今期（4月〜翌3月）のイベント売上が年度末にいくらぐらいになりそうかを見られる。売上を入力したイベントが 5 回たまるまでは表示されない。

**4つの金額**

| 表示 | 意味 |
|---|---|
| ここまでの実績 | 今期すでに売上を入力したイベントの合計 |
| 控えめな見込み（下位10%） | うまくいかなかった場合の目安。10 回に 1 回はこれより低くなる |
| ふつうの見込み（中央値） | いちばんありそうな年度末の合計 |
| 良い見込み（上位10%） | うまくいった場合の目安。10 回に 1 回はこれより高くなる |

**どうやって見込んでいるか**

- 今期の、まだ売上を入力していないイベント（これからの予定と、開催したけれど入力していない回）1回ずつについて、売上を過去の実績からくじのように引いて足す。これを 5,000 回くり返し、結果のばらつきをグラフ（分布）にしている
- 過去にも出店した**同じイベント**（「vol.5」「第3回」「2026」などの回の番号を除いた名前が同じもの）は、その過去の売上を重視する。同じイベントの実績が多いほど重視する割合が上がる（実績1回で約33%、2回で50%、4回で約67%）。残りの割合は、全イベントの売上から引く
- 年に何回か開催するイベントは、**開催月が近い回**の売上ほど重視する（同じ月の回をいちばん重く、半年ずれた回はほぼ使わない）
  - 例: 春と秋に開催するマルシェで、過去に4月の回（10万円）と10月の回（30万円）があるとき、来年4月の回は、約33%の確率で4月の回の 10万円、残りは全イベントの売上から見込む。10月の回の 30万円はほぼ使わない
- 同じイベントの実績が無いイベントは、全イベントの売上だけで見込む

**「残りのイベントと参考にした実績」の表**

グラフの下に、まだ売上が入っていないイベントが1行ずつ並ぶ。

| 列 | 見方 |
|---|---|
| 同じイベントの過去の回数 | 同じイベントとしてまとめた過去の回の数 |
| 時期を考慮した実質の回数 | 開催月が近い回を 1、離れた回ほど小さく数えた回数（同じ月の回が2回なら 2.0） |
| 過去の売上の中央値 | 同じイベントの過去の売上の真ん中の値（開催月が近い回を重く見る）。「なし（全体の実績で見込み）」は、同じイベントの実績が無い・時期が離れた回しか無いため、全イベントの売上で見込んだという意味 |
| 同じイベントの重み | そのイベントの見込みを、同じイベントの過去の売上から引く割合 |
| まとめた過去の回 | 同じイベントとしてまとめた回の名前・開催した年月・重み。**ここで別のイベントがまとまっていないか、まとまるはずの回が抜けていないかを確かめる** |

**見込みを正確にするための入力のコツ**

1. **開催したら売上を入れる**: 管理画面のサイドバーの **[イベント]** で該当イベントの **[収支]** を押し、「売上」を入力して **[保存]** をクリックする。売上が 0 円のままの回は「まだ入力していない」とみなされ、実績として使われない
2. **今後の出店予定を登録する**: 今期これから出店するイベントを、決まった時点で管理画面に登録しておく（「2. イベントを追加する」）。登録されていないイベントは見込みに入らない（見込みが低めに出る）
3. **同じイベントは、回の番号以外の名前をそろえる**: 「奇天烈 vol.5」と「奇天烈 vol.6」のように、番号（vol.5・第3回・6th・2026 など）以外を毎回同じ名前にする。「奇天烈 vol.5」と「奇天烈マーケット vol.6」のように名前が変わると、別のイベントとして扱われる。スペース・記号・英字の大文字小文字・全角半角の違いは気にしなくてよい
   - 「Vol.1」「Vol.2」のように番号だけの名前は、別々のイベントとして扱われる。イベント名を入れる

> 見込みは過去の実績から計算した目安で、売上を約束するものではない。実績が少ないうちは幅が広く出る。
