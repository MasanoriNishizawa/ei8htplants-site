### Step 1: Supabase DB マイグレーション

Supabase 管理画面 > SQL Editor で、以下を番号順に実行する。

```sql
-- 001: 初版スキーマ（events / gallery_images / stockists / workshop_reservations テーブル等）
-- backend/migrations/001_initial.sql の内容を貼り付けて実行

-- 002: Admin機能追加（collaborations / contacts テーブル、brands カラム等）
-- backend/migrations/002_admin_features.sql の内容を実行

-- 003: RLS 修正（contacts の不要な anon INSERT ポリシー削除）
-- backend/migrations/003_fix_rls.sql の内容を実行
DROP POLICY IF EXISTS "anon insert contacts" ON contacts;
```

> 冪等性: 各ファイルは `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` を使用。重複実行しても安全。

### Step 4: バックエンド起動

```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 本番起動（foreground）
uvicorn app.main:app --host 0.0.0.0 --port 8000

# systemd でプロセス管理する場合の例
# /etc/systemd/system/ei8htplants.service を作成:
# [Unit]
# Description=ei8ht plants API
# After=network.target
#
# [Service]
# User=<user>
# WorkingDirectory=/path/to/ei8htplants-site/backend
# ExecStart=/path/to/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
# Restart=always
#
# [Install]
# WantedBy=multi-user.target
```

```bash

# Admin API 認証確認（ログイン後のトークンで操作可能なこと）

```

## 3. サーバー移行手順（将来）

既存サーバーから新サーバーへ移行する場合。

### データバックアップ

```bash
# Supabase管理画面 > Settings > Database > Backups から手動バックアップを取得
# または pg_dump（Supabase Direct Connection）:
pg_dump "postgresql://postgres.<project-id>:<password>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres" > backup.sql
```

### 切り替え手順

```
1. 新サーバーで本番デプロイ手順（Step 1〜4）を実施
2. ドメインのDNSレコードを新サーバーIPに変更
3. 旧サーバーへのアクセスが減少したことを確認
4. 旧サーバーの停止
```

### ロールバック方針

本番切り替え後に重大な問題が発生した場合:
1. DNS を旧サーバーに戻す（TTL次第で1〜24時間）
2. 問題を修正後、再度切り替え

## 4. DB マイグレーション管理方針

| 項目 | 方針 |
|---|---|
| マイグレーションファイル | `backend/migrations/` に連番で管理（例: `001_initial.sql`, `002_admin_features.sql`） |
| 実行方法 | Supabase SQL エディタで手動実行 |
| 冪等性 | `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` を使用して重複実行を安全にする |
| 本番反映 | デプロイ前に必ずマイグレーションを実行する |
