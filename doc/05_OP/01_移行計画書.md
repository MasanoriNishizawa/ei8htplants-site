# OP-01 — 移行計画書・手順書 (Migration Plan)

## 1. 移行概要

本システムは新規構築のため、旧システムからのデータ移行はない。  
本書では**初回本番デプロイ（新規リリース）**の手順と、将来のサーバー移行手順を記載する。

---

## 2. 初回本番デプロイ手順

### 事前準備

| 確認項目 | 内容 |
|---|---|
| Supabase プロジェクト | 本番用プロジェクトが作成済みであること |
| Supabase 管理者アカウント | Admin ログイン用ユーザーが作成済みであること（Supabase Auth > Users） |
| 本番サーバー | Python 3.12+、Node.js 18+ が利用可能であること |
| ドメイン | デプロイ先ドメインが取得済みであること（任意） |
| Resend | 送信ドメインが認証済みであること |

### Step 1: Supabase DB マイグレーション

```sql
-- Supabase 管理画面 > SQL Editor で実行
-- 1. 初版スキーマ（既に実行済みの場合はスキップ）
-- 2. 追加マイグレーション
-- backend/migrations/002_admin_features.sql の内容を実行
```

### Step 2: 環境変数設定

```bash
# backend/.env（本番用）
NEXT_PUBLIC_SUPABASE_URL=https://<project-id>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>   # 絶対に公開しない
RESEND_API_KEY=<resend-api-key>
CONTACT_TO_EMAIL=info@ei8htplants.com
CONTACT_FROM_EMAIL=noreply@ei8htplants.com     # Resend認証済みドメイン

# frontend/.env（本番用）
VITE_SUPABASE_URL=https://<project-id>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-key>
```

### Step 3: フロントエンドビルド

```bash
cd frontend
npm install
npm run build
# → frontend/dist/ に成果物が生成される
```

### Step 4: バックエンド起動

```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 本番起動
uvicorn app.main:app --host 0.0.0.0 --port 8000
# またはプロセス管理ツール（systemd / supervisor / PM2）を使用
```

### Step 5: 動作確認

| 確認項目 | 方法 |
|---|---|
| トップページ表示 | ブラウザで `https://<ドメイン>/` にアクセス |
| API疎通 | `curl https://<ドメイン>/api/events` |
| Admin ログイン | `https://<ドメイン>/admin` |
| お問い合わせ送信 | フォームから送信し、メールが届くことを確認 |

### Step 6: UAT 実施

`doc/TEST/05_受入テスト仕様書.md` に従ってサイトオーナーが確認。

## 3. サーバー移行手順（将来）

既存サーバーから新サーバーへ移行する場合。

### データバックアップ

```bash
# Supabase管理画面 > Settings > Database > Backups から手動バックアップを取得
# または pg_dump（Supabase Direct Connection）:
pg_dump "postgresql://postgres.<project-id>:<password>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres" > backup.sql
```

### 切り替え手順

```
1. 新サーバーで本番デプロイ手順（Step 1〜4）を実施
2. ドメインのDNSレコードを新サーバーIPに変更
3. 旧サーバーへのアクセスが減少したことを確認
4. 旧サーバーの停止
```

### ロールバック方針

本番切り替え後に重大な問題が発生した場合:
1. DNS を旧サーバーに戻す（TTL次第で1〜24時間）
2. 問題を修正後、再度切り替え

## 4. DB マイグレーション管理方針

| 項目 | 方針 |
|---|---|
| マイグレーションファイル | `backend/migrations/` に連番で管理（例: `001_initial.sql`, `002_admin_features.sql`） |
| 実行方法 | Supabase SQL エディタで手動実行 |
| 冪等性 | `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` を使用して重複実行を安全にする |
| 本番反映 | デプロイ前に必ずマイグレーションを実行する |
