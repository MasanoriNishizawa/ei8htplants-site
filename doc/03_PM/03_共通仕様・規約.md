# PM-03 — 共通仕様・規約 (Coding & Design Guidelines)

## 1. コーディング規約

### TypeScript / React

| 項目 | 規約 |
|---|---|
| コンポーネント形式 | 関数コンポーネント（`export default function Name()`） |
| 型定義 | インターフェースは `lib/api.ts` に集約 |
| スタイリング | インラインスタイル優先。Tailwindクラスは補助的に使用 |
| state 管理 | ローカルstate（useState）のみ。Redux等の状態管理ライブラリ不使用 |
| 副作用 | `useEffect` で管理。依存配列を必ず明示。公開ページの API の読み込みは共通のフック `hooks/useApi.ts` を使う（失敗を「0件」と見せないため、データ・読み込み中・失敗を分けて持つ） |
| コメント | すべてのソースに日本語で詳しく書く（関数・部品は何をするか・引数・戻り値を JSDoc で、処理の中は「1. 〜 2. 〜」の手順、変数・state・定数は何を入れているか）。2026-10-22 にリポジトリのルール（`CLAUDE.md`）に合わせて直した |
| 絵文字 | コード・コミット・ドキュメントで使用しない |
| ファイル名 | 部品は PascalCase（`EventPreview.tsx`）。ページは大文字開始。部品を含まない関数・定数だけのファイルは小文字開始（`format.ts`・`docLinks.ts`） |
| 部品と関数のファイルを分ける | 部品（`.tsx`）のファイルからは部品だけを書き出し、フック・定数・関数は別のファイルに置く（開発中の画面の自動更新（Fast Refresh）が効くようにするため。2026-10-22 に `lang`・`cart`・`UnsavedChanges`・`eventTime`・`eventImageFiles` を分けた） |
| 共通の値・関数 | 金額の表記は `lib/format.ts`、日付は `lib/localDate.ts`、ブランドの名前・Instagram・ロゴは `lib/brands.ts`、参加費などの数値は `lib/constants.ts`、収支の計算は `lib/finance.ts` を使い、画面ごとに同じ値を書かない（2026-10-22 追加。一覧は [DD-01 モジュール構成](../02_DD/01_モジュール構成.md) の「共通の関数・定数」） |
| 管理画面の失敗の文言 | `pages/admin/errorMessage.ts` の `failMessage('〜に失敗しました', e)` で作る（2026-10-22 追加。[DD-07](../02_DD/07_エラーハンドリング.md)） |
| 静的チェック（ESLint） | `cd frontend && npm run lint`（`eslint .`）。設定は `frontend/eslint.config.js`。TypeScript の推奨ルール、フックの使い方のルール（`useApi` の依存配列も確認する）、部品のファイルから部品以外を書き出したときの警告、使っていない変数のエラー（名前が `_` で始まるものは許す）。2026-10-22 導入 |

### 入力カーソル（| の点滅）の表示（2026-10-15 追加）

公開サイト・管理画面のどちらでも、入力欄以外の場所（文章・見出し・画像の余白など）をクリックしたときに、入力カーソル（| の点滅）が出ないようにしている。

| 場所 | 入力カーソル | 文字の選択・コピー |
|---|---|---|
| 入力欄以外（文章・見出し・ボタンなど） | 出ない | これまでどおりできる |
| 1行の入力欄（`input`） | 出る | できる |
| 複数行の入力欄（`textarea`） | 出る | できる |
| 直接文字を編集できる領域（`contenteditable`） | 出る | できる |

- 設定場所: `frontend/src/index.css`。ページ全体（`body`）でカーソルの色を透明（`caret-color: transparent`）にし、入力欄だけ通常の色（`caret-color: auto`）に戻している
- 文字の選択を禁止する設定（`user-select: none`）は使っていない。そのため、住所や説明文などをドラッグで選んでコピーすることはこれまでどおりできる
- 新しく入力欄を作るときは `input`・`textarea` を使えば自動でカーソルが表示される。それ以外の要素を入力欄として使う場合は `contenteditable` を付けること（付けないとカーソルが見えない）
- 確認テスト: `frontend/e2e/caret.spec.ts`（テスト ID E2E-G-01〜06。[テストケース一覧](../04_TEST/07_テストケース一覧.md) を参照）

### スマホでの入力欄の文字の大きさ（2026-10-16 追加）

iPhone（Safari）では、文字の大きさが 16px より小さい入力欄を選ぶと、画面が自動で拡大されてしまい、元に戻すのに指で縮める必要がある。これを防ぐため、画面幅が 767px 以下（スマホ幅）のときは、入力欄の文字をすべて 16px にそろえている。

| 対象 | スマホ幅（767px 以下）での文字の大きさ |
|---|---|
| 1行の入力欄（`input`。チェックボックス・ラジオボタン・スライダー・ファイル選択は除く） | 16px |
| 複数行の入力欄（`textarea`） | 16px |
| 選択欄（`select`） | 16px |

- 公開サイト・管理画面のどちらにも当てはまる
- パソコンなど画面幅が 768px 以上のときは、各画面で決めた大きさのまま変わらない
- 設定場所: `frontend/src/index.css`。各画面が入力欄ごとに文字の大きさを直接指定しているため、それを上書きできるよう `!important` を付けている
- 新しく入力欄を作るときも、スマホ幅では自動で 16px になる。スマホ幅で 16px より小さくしたい場合でもこの設定に上書きされる点に注意

## 3. Git 規約

### コミットメッセージ

```
<type>: <subject>

types:
  feat    新機能の追加
  fix     バグ修正
  style   UIスタイル変更
  refactor リファクタリング
  docs    ドキュメント変更
  chore   ビルド・設定変更
```

例:
```
feat: add collaboration admin page with CRUD
fix: correct reservation URL from /api/reservations to /api/reserves
style: home next-event card matches events page layout exactly
docs: add detailed design documents (DD)
```

### 禁止事項

- `.env` ファイルのコミット
- `SUPABASE_SERVICE_ROLE_KEY` / `RESEND_API_KEY` を含むファイルのコミット
- `--no-verify` によるフック回避
- `main` ブランチへの `--force` push

## 5. 国際化（i18n）規約

サイトは日本語（ja）と英語（en）のバイリンガル対応。

| 項目 | 規約 |
|---|---|
| 言語管理 | `frontend/src/lib/lang.ts` の `LangProvider` / `useLang()` / `useT()`。画面からは必ず `lib/lang` から読み込む（2026-10-22 に `lang.ts`（フック）・`LangProvider.tsx`（部品）・`langContext.ts`（共有の入れ物と最初の言語の決め方）の3つに分けた。開発中の画面の自動更新が効くようにするため。使い方は変わらない） |
| 言語の決定 | `localStorage['site-lang']` を優先し、未保存の場合は `navigator.language` で判定（`ja` で始まる → 日本語、それ以外 → 英語） |
| 翻訳の書き方 | `const t = useT()` → `t('日本語テキスト', 'English text')` |
| 言語切り替え | `useLang().toggle()` で `ja` ↔ `en` を切り替え。`localStorage['site-lang']` に保存。切り替えボタンはヘッダー（PC はナビの右端、スマホはメニューの中） |
| 読み込み中・失敗の文言 | 公開ページの「読み込み中...」も `t('読み込み中...', 'Loading...')` のように日英で書く（2026-10-22 にそろえた）。読み込みの失敗は共通の `components/LoadError.tsx` で日英の案内を出す |
| 日付・曜日 | 日付の表示は `lib/localDate.ts` の関数を使う（`formatDateRange`・`formatMonthKey` は言語を受け取り、英語では「May 1, 2026」「May 2026」の形）。曜日も英語表示では英語にする |
| バックエンドへの言語送信 | 予約フォームは `lang` フィールドに現在の言語（`'ja'` または `'en'`）を付与して送信。バックエンドはこれに基づきメールの言語を切り替える |
| バックエンドのメール言語 | `lang = 'en'` の場合は英語メール、それ以外（`'ja'` または NULL）は日本語メール |
