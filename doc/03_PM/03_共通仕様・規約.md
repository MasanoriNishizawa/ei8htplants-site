# PM-03 — 共通仕様・規約 (Coding & Design Guidelines)

## 1. コーディング規約

### TypeScript / React

| 項目 | 規約 |
|---|---|
| コンポーネント形式 | 関数コンポーネント（`export default function Name()`） |
| 型定義 | インターフェースは `lib/api.ts` に集約 |
| スタイリング | インラインスタイル優先。Tailwindクラスは補助的に使用 |
| state 管理 | ローカルstate（useState）のみ。Redux等の状態管理ライブラリ不使用 |
| 副作用 | `useEffect` で管理。依存配列を必ず明示 |
| コメント | 原則不要。自明でない処理にのみ簡潔に記述 |
| 絵文字 | コード・コミット・ドキュメントで使用しない |
| ファイル名 | PascalCase（`EventCard.tsx`）。ページは大文字開始 |

### Python / FastAPI

| 項目 | 規約 |
|---|---|
| ルーター | 機能単位でファイル分割（`routes/` 配下） |
| Pydantic | リクエストボディは必ず `BaseModel` で定義 |
| DB操作 | `supabase`（読み取り）と `admin_supabase`（書き込み）を使い分ける |
| エラー | `HTTPException` を使用。スタックトレースは uvicorn に任せる |
| 型ヒント | Python 3.12 の型ヒント構文を使用 |
| ファイル名 | snake_case（`contact.py`） |

### 入力カーソル（| の点滅）の表示（2026-10-15 追加）

公開サイト・管理画面のどちらでも、入力欄以外の場所（文章・見出し・画像の余白など）をクリックしたときに、入力カーソル（| の点滅）が出ないようにしている。

| 場所 | 入力カーソル | 文字の選択・コピー |
|---|---|---|
| 入力欄以外（文章・見出し・ボタンなど） | 出ない | これまでどおりできる |
| 1行の入力欄（`input`） | 出る | できる |
| 複数行の入力欄（`textarea`） | 出る | できる |
| 直接文字を編集できる領域（`contenteditable`） | 出る | できる |

- 設定場所: `frontend/src/index.css`。ページ全体（`body`）でカーソルの色を透明（`caret-color: transparent`）にし、入力欄だけ通常の色（`caret-color: auto`）に戻している
- 文字の選択を禁止する設定（`user-select: none`）は使っていない。そのため、住所や説明文などをドラッグで選んでコピーすることはこれまでどおりできる
- 新しく入力欄を作るときは `input`・`textarea` を使えば自動でカーソルが表示される。それ以外の要素を入力欄として使う場合は `contenteditable` を付けること（付けないとカーソルが見えない）
- 確認テスト: `frontend/e2e/caret.spec.ts`（テスト ID E2E-G-01〜06。[テストケース一覧](../04_TEST/07_テストケース一覧.md) を参照）

## 3. Git 規約

### コミットメッセージ

```
<type>: <subject>

types:
  feat    新機能の追加
  fix     バグ修正
  style   UIスタイル変更
  refactor リファクタリング
  docs    ドキュメント変更
  chore   ビルド・設定変更
```

例:
```
feat: add collaboration admin page with CRUD
fix: correct reservation URL from /api/reservations to /api/reserves
style: home next-event card matches events page layout exactly
docs: add detailed design documents (DD)
```

### 禁止事項

- `.env` ファイルのコミット
- `SUPABASE_SERVICE_ROLE_KEY` / `RESEND_API_KEY` を含むファイルのコミット
- `--no-verify` によるフック回避
- `main` ブランチへの `--force` push

## 5. 国際化（i18n）規約

サイトは日本語（ja）と英語（en）のバイリンガル対応。

| 項目 | 規約 |
|---|---|
| 言語管理 | `frontend/src/lib/lang.tsx` の `LangProvider` / `useLang()` / `useT()` |
| 言語の決定 | `localStorage['site-lang']` を優先し、未保存の場合は `navigator.language` で判定（`ja` で始まる → 日本語、それ以外 → 英語） |
| 翻訳の書き方 | `const t = useT()` → `t('日本語テキスト', 'English text')` |
| 言語切り替え | `useLang().toggle()` で `ja` ↔ `en` を切り替え。`localStorage['site-lang']` に保存 |
| バックエンドへの言語送信 | 予約フォームは `lang` フィールドに現在の言語（`'ja'` または `'en'`）を付与して送信。バックエンドはこれに基づきメールの言語を切り替える |
| バックエンドのメール言語 | `lang = 'en'` の場合は英語メール、それ以外（`'ja'` または NULL）は日本語メール |
