# PM-03 — 共通仕様・規約 (Coding & Design Guidelines)

## 1. コーディング規約

### TypeScript / React

| 項目 | 規約 |
|---|---|
| コンポーネント形式 | 関数コンポーネント（`export default function Name()`） |
| 型定義 | インターフェースは `lib/api.ts` に集約 |
| スタイリング | インラインスタイル優先。Tailwindクラスは補助的に使用 |
| state 管理 | ローカルstate（useState）のみ。Redux等の状態管理ライブラリ不使用 |
| 副作用 | `useEffect` で管理。依存配列を必ず明示 |
| コメント | 原則不要。自明でない処理にのみ簡潔に記述 |
| 絵文字 | コード・コミット・ドキュメントで使用しない |
| ファイル名 | PascalCase（`EventCard.tsx`）。ページは大文字開始 |

### Python / FastAPI

| 項目 | 規約 |
|---|---|
| ルーター | 機能単位でファイル分割（`routes/` 配下） |
| Pydantic | リクエストボディは必ず `BaseModel` で定義 |
| DB操作 | `supabase`（読み取り）と `admin_supabase`（書き込み）を使い分ける |
| エラー | `HTTPException` を使用。スタックトレースは uvicorn に任せる |
| 型ヒント | Python 3.12 の型ヒント構文を使用 |
| ファイル名 | snake_case（`contact.py`） |

## 3. Git 規約

### コミットメッセージ

```
<type>: <subject>

types:
  feat    新機能の追加
  fix     バグ修正
  style   UIスタイル変更
  refactor リファクタリング
  docs    ドキュメント変更
  chore   ビルド・設定変更
```

例:
```
feat: add collaboration admin page with CRUD
fix: correct reservation URL from /api/reservations to /api/reserves
style: home next-event card matches events page layout exactly
docs: add detailed design documents (DD)
```

### 禁止事項

- `.env` ファイルのコミット
- `SUPABASE_SERVICE_ROLE_KEY` / `RESEND_API_KEY` を含むファイルのコミット
- `--no-verify` によるフック回避
- `main` ブランチへの `--force` push

## 4. API設計規約

| 項目 | 規約 |
|---|---|
| URLパス | 小文字 kebab-case（`/api/collaborations`） |
| HTTPメソッド | `GET`=取得, `POST`=作成, `PUT`=全置換, `PATCH`=部分更新, `DELETE`=削除 |
| レスポンス形式 | JSON |
| エラー形式 | `{"detail": "メッセージ"}` |
| 一覧取得 | `display_order` または `created_at` 順（用途による） |
| IDパラメータ | UUID文字列 |

---

## 5. 環境変数規約

| 規約 | 詳細 |
|---|---|
| フロントエンド | `VITE_` プレフィックス必須（Vite で公開される） |
| バックエンド | プレフィックスなし（サーバー側のみ） |
| デフォルト値 | `config.py` で `os.getenv('KEY', '')` でデフォルト空文字 |
| 秘匿情報 | `SERVICE_ROLE_KEY` / `RESEND_API_KEY` は絶対に公開しない |
