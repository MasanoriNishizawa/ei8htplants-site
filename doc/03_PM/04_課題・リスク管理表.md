## 2. リスク管理（Risk）

| ID | リスク | 発生確率 | 影響度 | 対策 |
|---|---|---|---|---|
| R-01 | Supabase 障害によるサイト全停止 | 低 | 高 | Supabase は99.9% SLA。重大障害時は一時的にメンテナンスページへ切り替え |
| R-02 | SERVICE_ROLE_KEY の漏洩 | 低 | 致命的 | `.gitignore` 管理を徹底。漏洩時は即座にSupabase管理画面でキーをローテーション |
| R-03 | Resend API 上限超過によるメール不達 | 低 | 中 | 月次の問い合わせ件数を確認し、上限接近時はプランアップグレード |
| R-04 | 写真が表示できなくなる | 低 | 低 | 2026-07-22 から写真は管理画面でアップロードして Supabase Storage（`images`）に置くので、外部のサービスの都合では切れない。Storage のファイルが消えた・古い外部 URL の写真が残っているときは、ギャラリーの「URL無効」の印で気づき、写真を選び直して登録する |
| R-05 | 管理者パスワード忘れ | 低 | 高 | Supabase管理画面からパスワードリセット可能。手順を [運用・保守マニュアル](../05_OP/02_運用・保守マニュアル.md) の 3-1 に記載 |
| R-06 | 単一開発者による引き継ぎリスク | 中 | 高 | 設計書（RD/BD/DD）の整備により、第三者への引き継ぎを可能にする |
| R-07 | Render の無料枠（全サービスで月 750 時間）を使い切ってサイトが止まる | 低 | 高 | サイト本体だけを Render に置く（I-09 で分析ダッシュボードを移した）。Render の請求・使用時間の画面をときどき確かめる |
