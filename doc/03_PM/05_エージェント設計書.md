# PM-05 — エージェント設計書

## 目的と正本

この設計書は、Claude Code と Codex が共有する役割定義と、各環境でエージェントを連携させる構成を記録する。開発手順、担当の詳細責務、テスト条件、設計書更新、レビュー、コミット・プッシュ条件の正本はリポジトリ直下の [`CLAUDE.md`](../../CLAUDE.md)。この設計書や `AGENTS.md` に運用手順を重複して定義しない。

## エージェント構成

```text
ユーザー
  │
  ▼
PM（各環境のメインセッション）
  ├── frontend       画面・CSS
  ├── backend        API・DB
  ├── test-engineer  自動テスト
  ├── qa             実装レビュー
  ├── docs           設計書・テストケース一覧
  └── docs-reviewer  設計書レビュー
```

各担当の目的・変更可能範囲・報告事項は `.claude/agents/*.md` を共有定義として使う。PMはタスクに必要な担当を選び、依存関係を明示して割り当て、結果を統合する。役割間の工程順と完了条件は `CLAUDE.md` に従う。

## Claude Code と Codex の連携

### Claude Code

Claude Code は `.claude/agents/` の担当定義を読み、Task/Agent 機能で専門担当を起動する。PM役はメインセッションが担う。

### Codex

Codex はリポジトリルートの `AGENTS.md` を作業開始時の入口として読み、そこから `CLAUDE.md` 全文と、割り当てる担当の `.claude/agents/<役割>.md` を読む。利用可能な Codex のマルチエージェント機能で担当を起動し、独立した調査・作業は並行して進める。担当間で同じ作業領域を共有するときは、変更範囲と依存関係を分け、別担当の未コミット変更を取り消さない。

起動できる担当数や機能は実行環境によって異なる。上位の指示で起動が制限される場合や必要な機能が使えない場合は、制限をPMからユーザーへ報告し、許可された範囲で進める。役割定義を読み替えたり、担当の完了を確認せずに工程を省略したりしない。

### 担当ファイルの共有

`CLAUDE.md` と `.claude/agents/*.md` はClaude CodeとCodexが参照する共有ルールとしてGitで管理する。Codex向けの入口である `AGENTS.md` は `CLAUDE.md` を正本として案内し、運用ルールを複製しない。端末ローカルの `.claude/settings*.json` と `.codex/` はGitに含めない。

## 役割の境界

| 担当 | 主な変更範囲 | 制約 |
|---|---|---|
| PM | 全体の依頼整理、割当、統合、最終報告 | コミット・プッシュはPMだけが行う |
| `frontend` | `frontend/src/` | アプリ画面・CSSの実装。コミット・プッシュはしない |
| `backend` | `backend/app/` | API・DBの実装。必要なSQLを提示し、Supabase実行は人が行う。コミット・プッシュはしない |
| `test-engineer` | `frontend/src/**/__tests__/`、`frontend/e2e/`、`backend/tests/` | テストの追加・変更・実行。アプリ本体は直さない |
| `qa` | 読み取り専用レビュー | 指摘を報告し、実装を直接直さない |
| `docs` | `doc/` | 設計書・テストケース一覧を実装と照合して更新する。コミット・プッシュはしない |
| `docs-reviewer` | 読み取り専用レビュー | 設計書の正確さと表示を確認し、指摘を報告する |

`.claude/agents/pm.md` はPMの補助的な担当定義であり、PMは必ずメインセッションが担う。`deploy.md` はリリース確認の補助に限る。コミット・プッシュは `CLAUDE.md` の条件を満たした後にPMが実施する。
