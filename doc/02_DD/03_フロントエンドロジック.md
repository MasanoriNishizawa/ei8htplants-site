## 0. ホスト名によるサイト選択（2026-10-26 追加）

`App.tsx` は `window.location.hostname` を `siteForHost()` に渡し、表示するサイトを決める。`ei8htplants.com` と `www.ei8htplants.com`（および未登録ホスト）は既存の ei8ht plants サイト、Habitat Oides の2ホストは専用サイト、HUE の2ホストはHUE専用サイトとして扱う。

| ホスト名 | サイト設定 | 表示レイアウト |
|---|---|---|
| `ei8htplants.com`・`www.ei8htplants.com` | `ei8htplants/site.ts` | 既存 `Layout`・`StoreLayout`。管理画面もここ |
| `habitatoides.com`・`www.habitatoides.com` | `habitat-oides/site.tsx` | `BrandSiteLayout`。`/`・`/workshop`・`/collaborations` |
| `huebyei8htplants.com`・`www.huebyei8htplants.com` | `hue/site.tsx` | `BrandSiteLayout`。トップ `/` |

Habitat Oides・HUE で `/admin` または `/admin/*` を開いたときは、同じパス・クエリ・ハッシュを付けて `https://ei8htplants.com` へブラウザ転送する。Habitat Oides サイトで `/hue` 以下を開いた場合は `window.location.replace()` でHUEのトップへ移動する。ブランドヘッダー・フッターのブランド切替リンクにも別ドメインへのリンクを置き、新しいタブで開く。サーバー側の301転送と、旧PWAキャッシュの解除は [DD-04](04_バックエンドロジック.md) を参照。

```
    ├─ checking=true → null（空白）をレンダリング
    │
    ├─ authed=false → <LoginForm /> をレンダリング
    │   フォーム送信 (login関数)
    │     │
    │     └─ supabase.auth.signInWithPassword({ email, password })
    │           │

```

### 開発用のログイン省略モード（`lib/devAuth.ts`、2026-10-20 追加）

画面テスト（Playwright）で管理画面を開くための、開発中だけの仕組み。

- `SKIP_ADMIN_AUTH` は次の3つがすべてそろったときだけ true になる
  1. 開発サーバーで動いている（`import.meta.env.DEV`）
  2. モードが `production` ではない（`import.meta.env.MODE !== 'production'`）
  3. `VITE_SKIP_ADMIN_AUTH` が `'true'`（`npm run mock:e2e` で設定される）
- true のときにすること
  - `AdminLayout` はログイン画面を出さずに管理画面を表示する
  - `lib/api.ts` の認証つき呼び出し（`authRequest`・`upload`・`uploadVideo`）は、ログインしていなくてもダミーのトークン `dev-skip-admin-auth`（`DEV_SKIP_AUTH_TOKEN`）を付けて送る。これでテスト用のモック（MSW）までリクエストが届き、モックのデータが画面に出る
- 安全のための決まり
  - 本番ビルド（`npm run build`）では少なくとも 2 が満たされない（ビルド時に NODE_ENV=development が残っていて 1 が満たされる場合も含む）ので、`VITE_SKIP_ADMIN_AUTH` を何に設定しても働かない
  - 本物のバックエンドはダミーのトークンを受け付けず `401` を返す
  - 管理画面の「チャット Q&A」「チャットログ」は自分でセッションを読んでいるため、ダミーのトークンは使わない

```
lib/api.ts の getAccessToken()（authRequest・upload・uploadVideo が共通で使う）
    │
    ├─ Supabase のセッションがある → そのトークンを返す
    ├─ セッションが無く SKIP_ADMIN_AUTH=true → 'dev-skip-admin-auth' を返す
    └─ どちらでもない → 「401 Unauthorized」のエラー（送信しない）
```

### シーケンス図

```

  │                  │                    │
  │  mount           │                    │
  │─────────────────►│                    │
  │                  │ getSession()       │
  │                  │───────────────────►│
  │                  │◄───────────────────│ {session}
  │                  │ setAuthed/checking │
  │                  │                    │
```


#### 前へ・次へボタンの位置（2026-10-20 修正）

前へ（❮）・次へ（❯）のボタンは、写真の入れ物（`position: relative`）の中に `position: absolute` で重ねて置く。縦の位置は次のとおり。

| 設定 | 意味 |
|---|---|
| `top: '50%'` | ボタンの上端を写真の高さのちょうど半分の位置に合わせる |
| `transform: 'translateY(-50%)'` | ボタン自身の高さの半分だけ上に戻す。これでボタンの中心が写真の上下の真ん中にそろう |

以前は `top: 40`（写真の上端から 40px）に固定されていたため、写真の高さが変わってもボタンは上のほうにあり、上寄りに見えていた。同じ書き方を次の3か所に入れている。

| ファイル | 使われている画面 | ボタンの大きさ |
|---|---|---|
| `components/EventPreview.tsx` | /official/events 一覧のカード、ホームの Next Event の大きいカード | 26px |
| `pages/EventSite.tsx` | イベント専用ページ `/official/events/:id`（写真は横幅いっぱい・高さは写真の縦横比どおり） | 30px |

画面テスト `frontend/e2e/event-image-arrows.spec.ts`（E2E-N）で、スマホ幅とパソコン幅の両方について、ボタンの縦の中心が写真の縦の中心と ±2px 以内でそろうことを確かめている。

ライトボックスは共通部品 `components/ImageLightbox.tsx`（`EventPreview.tsx`・`EventSite.tsx`・`Gallery.tsx` で使用）。閉じ方は「✕ ボタン」「画像の外側（黒い背景）を押す」「Esc キー」の3つ。✕ ボタンを押したときは、押したことが外側の背景に伝わらないようにしてから閉じる（2026-10-20 修正。以前は ✕ を押すと閉じる処理が2回動いていた）。

## 8. WS予約フォーム URLパラメータ連携（Reserve.tsx）

### 処理フロー

```
URLパラメータ: ?event_id=<uuid>

useEffect #1 — イベント取得（[eventId] 依存）:
    api.events.get(eventId) → setEvent(event)
    単日イベントの場合: setForm(prev => ({...prev, preferred_date: start_date}))
    複数日イベントの場合: 日付ラジオを表示（preferred_date は未選択）

useEffect #2 — セッション取得（[event, form.preferred_date] 依存）:
    event.has_workshop かつ preferred_date が確定した場合のみ実行
    setSessions([])  ← 前の結果をクリア
    api.events.getSessions(eventId, form.preferred_date) → setSessions(data)
    // preferred_date を渡すことで、その日の予約数を反映した reserved_count を取得

セッション選択後:
    setForm(prev => ({...prev, session_id: session.id}))
    参加人数セレクトを有効化（1〜残席数）

送信:
    api.reserve.create(form)
    成功 → status='done'
    409  → status='full'（「このセッションは満席になりました」表示）
```

### 2-useEffect 分割の理由

- #1 と #2 を1つにまとめると、日付を変えるたびにイベント再取得が走る。
- 日付変更→セッション再ロード → `setSessions([])` で前日の選択がリセットされる。
- 複数日イベントで1日目の混雑状況が2日目に漏れないよう、`?date=` パラメータで日付別集計を行う。

### 左カラムのイベント案内表示（`reserve/EventInfoPanel.tsx`、2026-10-29）

- `Reserve.tsx` は `useApi` によるイベント取得、時間枠取得、予約フォーム・送信状態の管理、および `api.reserve.create` による送信を引き続き担当する。
- 左カラムに表示していたイベント名・開催日・時間・会場、ワークショップ説明・参加費・詳細リンク、予約確認と問い合わせ案内の描画を `reserve/EventInfoPanel.tsx` に分離した。
- `EventInfoPanel` は親から `event` と翻訳関数 `t` を受け取り、表示だけを行う。API通信、フォームstate、予約送信は行わない。Habitat Oidesワークショップ詳細と公式お問い合わせへのリンク先も維持している。
- この分割で予約の取得・入力・送信の処理、表示文言・リンク先を含む画面挙動は変えていない。2026-10-29 18:10の関連実行でTypeScript 1/1・本番ビルド1/1・runner 50/50・Vitest 26/26・Playwright 11/11が成功した。Backend・Analyticsは関連なしとして省略。18:07の初回実行はVitest 25/26で1件失敗し、PlaywrightはWebServerの `listen EPERM` でspec開始前に失敗したため、18:10の再実行を最終確認とする。

## 11. 管理画面 — ギャラリーブランドフィルター（Gallery.tsx）

### 歓迎メッセージ（2026-10-23 変更）

```typescript
// state に入れず、描画のたびに今の言語で作る
const welcome: Message = {
    role: 'model',
    content: t('こんにちは。ei8ht plants のAIコンシェルジュです。...', 'Hello! ...'),
}

// 表示: いつも先頭に付ける
[welcome, ...messages].map(...)

// 送信: 送る履歴の先頭にも付ける
api.chat.send(toSendHistory([welcome, ...next]))
```

- 歓迎メッセージは `messages` に入れず、表示と送信のたびに `t()` で作って先頭に付ける。言語を切り替えると、表示されている歓迎メッセージも、次に送る履歴の先頭の歓迎メッセージも、今の言語になる
- それまでは最初の表示のときに1回だけ `setMessages([歓迎メッセージ])` で state に入れていたため、あとから言語を切り替えても歓迎メッセージは最初の言語のままだった
- 歓迎メッセージは AI の発言（`role: 'model'`）として送る履歴の先頭に入る。`toSendHistory` は先頭の AI の発言をそのまま残すので、送る履歴は「歓迎 → 質問 → 返事 → … → 今回の質問」の順になる

### 送信フロー

```
send()
    │
    ├─ input.trim() が空 or loading → 早期 return
    │
    ├─ userMsg = { role: 'user', content: input.trim() }
    ├─ next = [...messages, userMsg]   // 歓迎メッセージは入っていない
    ├─ setMessages(next)
    ├─ setInput('')
    ├─ setLoading(true)
    │
    ▼
api.chat.send(toSendHistory([welcome, ...next]))  → POST /api/chat（2026-10-22 から lib/api.ts を通す。応答はそのまま受け取る）
    │
    ├─ 429 → 送信回数の上限の案内を追加（localOnly: true）
    ├─ 422 → 「メッセージを送れませんでした。内容を短くするか、ページを開き直してください。」を追加（localOnly: true）
    ├─ その他の res.ok でない応答 → 下の「失敗」へ
    ├─ res.ok → data = await res.json()
    │     ├─ data.reply が文字列でない、または空白だけ
    │     │     → 「うまくお答えできませんでした。言い方を変えてもう一度お試しください。」を追加（localOnly: true）
    │     └─ それ以外 → setMessages([...next, { role: 'model', content: data.reply }])
    │
    └─ 失敗（通信の失敗・ほかのエラー） → 「申し訳ありません、エラーが発生しました。しばらく経ってからもう一度お試しください。」を追加（localOnly: true）
                （案内はすべて t() で日英。localOnly の案内は画面に出すだけで、次の送信の履歴には入らない）

    ▼（どの場合も最後に）
setLoading(false)
```

入力欄（textarea）には `maxLength={MAX_MESSAGE_CHARS}`（2,000）を付けており、2,000 文字を超えて入力できない（2026-10-20 追加）。

### 送る会話の整え方（`lib/chatHistory.ts`、2026-10-20 追加）

サーバー（`POST /api/chat`）の入力チェックに合わない会話を送ると `422` になるため、送る前に整える。

| 名前 | 内容 |
|---|---|
| `MAX_SEND_MESSAGES` | 送る会話の最大件数 = 40（サーバーの `MAX_MESSAGES` と同じ） |
| `MAX_MESSAGE_CHARS` | 1件の本文の最大文字数 = 2,000（サーバーの `MAX_MESSAGE_CHARS` と同じ。入力欄の上限にも使う） |
| `clampContent(content)` | 本文を 2,000 文字までに切る。絵文字なども 1 文字として数え（`Array.from` で分ける）、途中で壊れた文字にしない |
| `toSendHistory(history)` | 画面の会話から送る会話を作る（下の手順） |

`toSendHistory` の手順:

```
1. localOnly の案内・本文が空白だけのもの・本文が文字列でないものを外す
2. 利用者の発言のうち、すぐ後に AI の返事が無いものを外す（最後の 1 件 = 今回の質問は残す）
   → 利用者と AI の発言が交互になり、最後は今回の質問になる
3. 新しいほうから 40 件だけにする
4. 各本文を clampContent で 2,000 文字までに切り、{ role, content } だけにする（localOnly の印は送らない）
```

例: 「挨拶 → 質問a → エラーの案内（localOnly）→ 質問b」なら、送るのは「挨拶 → 質問b」。挨拶（歓迎メッセージ）は画面の `messages` には無く、送るときに `[welcome, ...next]` で先頭に付けたもの。

### 収支への同期（2026-10-16 変更）

- 管理情報を保存すると、収支の出店料・宿泊費も管理情報の値（出店料・宿泊料金）に合わせて保存する。空欄なら 0 にする
- 収支のほかの項目（売上・距離・メモなど）は、**保存の直前に取り直した最新の収支**の値をそのまま使う
- `toFinanceBody(fin)`: 収支の取得結果から、保存 API に送る 12 項目（sales・booth_fee・distance・gas_price・expressway_toll・accommodation・ws_participants・payment_flag・ws_payment_done・other_expenses・other_expenses_note・notes）だけを取り出す。`id`・`event_id`・`updated_at` は送らない。`payment_flag`・`ws_payment_done` が null（古いデータ）のときは false で補う（そのまま送るとサーバーの入力チェックで弾かれるため）
- 2026-10-16 より前は、画面を開いた時点で読み込んだ収支（`finData`）に出店料・宿泊費だけ差し替えて丸ごと保存していた。そのため、画面を開いた後に収支画面で保存した売上などを古い内容で上書きして消していた
- 残る制約: 収支画面と管理情報の編集画面を同時に開いたまま、別々に保存すると、出店料・宿泊費は最後に保存した画面の値になる（2つの画面で同じ値を互いに書き合う仕組みのため）。ほかの項目は消えない

- 保存成功の表示用の `saved` は 2026-10-16 に削除した（「保存しました」は確認画面が表示する）
- 画面内の値（state ではない）: `viewFrom`（確認画面に来る前の画面。`location.state.from`）、`viewPath`（確認画面の URL）、`isDirty`（未保存の変更があるか。上の処理フローを参照）

### 画像の拡大表示（ImageViewer、2026-10-16 追加）

`EventGuidelinesImages.tsx` から `AdminInfoParts.tsx` の共通 `ImageViewer` を呼び出し、出店要項の画像を画面いっぱいに表示する（`ImageViewer` は2026-10-16 に共通部品へ移し、確認画面と共用。2026-10-28 に編集画面側の表示接続を子コンポーネントへ分離）。拡大表示位置の state は引き続き親が管理する。

| 操作 | 動き |
|---|---|
| サムネイルを押す | その画像を拡大表示する |
| 「← 前へ」「次へ →」ボタン / 左右の矢印キー | 前後の画像に切り替える（2枚以上のときだけボタンを表示。端では何もしない） |
| 「閉じる」ボタン / 画像の外側を押す / Esc キー | 拡大表示を閉じる |

- 2枚以上のときは上部に「n / m」（何枚目 / 全体の枚数）を表示する
- 表示中は後ろのページがスクロールしないようにし、閉じると元に戻す
- 管理画面の枠の影響を受けないよう、ページの一番外側（body の直下）に表示する

### 遷移元・遷移先

- 確認画面（`/admin/events/:id/admin-info`）の「編集」ボタンから遷移する（2026-10-16 変更。それまではイベント一覧の「管理情報」ボタン・イベント編集画面のリンクから直接開いていた。今はどちらも確認画面を開く）
- 受け取る `location.state.from`（確認画面に来る前の画面）は使わずに持っておき、確認画面へ戻るときにそのまま渡す。これで確認画面の「← 戻る」が元の画面（イベント一覧など）に戻れる
- 「← 戻る」リンク: `viewPath`（確認画面）へ `replace` で移る。`state` は `{ from: viewFrom }`。未保存の変更があれば先に確認ダイアログを出す
- 保存成功: `viewPath` へ `replace` で移る。`state` は `{ from: viewFrom, saved: true }`
- どちらも `replace` なので、確認画面 → 編集画面 → 確認画面と移った後の履歴は「一覧 → 確認画面 → 確認画面」になる。確認画面でブラウザの戻るを押すと、1回目は前の確認画面、2回目でイベント一覧（イベント編集画面から開いた場合はイベント編集画面）に戻る。確認画面の「← 戻る」は履歴を戻る（navigate(-1)）のではなく `from` の画面へ移るリンクなので、1回でイベント一覧（イベント編集画面から開いた場合はイベント編集画面）に着く

```
1. isAnalyticsEnabled(location.hostname, import.meta.env.PROD) が false なら何もしない
   → 本番ビルドかつ ei8htplants.com / www.ei8htplants.com のときだけ true
   → 開発サーバー・Vitest・Playwright・Render の `*.onrender.com` の URL ではタグを読み込まず、外部送信もしない
1-2. 管理画面にログインしているブラウザか確かめる（2026-10-17 追加）
   isAdmin = hasAdminSession(window.localStorage)
   ※ window.localStorage を読むだけで例外が出る環境（Cookie を全てブロックしているなど）では
     try で受け止めて isAdmin = false（一般の訪問者として扱い、公開ページを止めない）
1-3. setAnalyticsDisabled(isAdmin)
   → window['ga-disable-G-HCVVDNYL94'] = isAdmin（Google 公式の送信停止の仕組み）
   isAdmin が true ならここで終わり（タグの読み込みもページビューの送信もしない）
2. loadGtag()（初回だけ）
   - window.dataLayer と window.gtag を用意し、gtag('config', 'G-HCVVDNYL94', { send_page_view: false })
   - config の page_location にも、秘密のクエリを外した今の URL を入れる
   - gtag.js を <script async> で読み込む
3. trackPageView(pathname, search, document.title)
   - isExcludedPath（/admin と /admin/〜）なら送らない
   - sanitizeSearch(search) で、送ってよいクエリだけを残す
   - gtag('set', { page_location })  ← GA が自動で送るスクロール・クリックなどにも同じ URL を使わせる
   - gtag('event', 'page_view', { page_location, page_path, page_title })
```

- SPA なので、GA の自動ページビュー（`send_page_view`）は止め、画面遷移のたびに自分で送る
- ページタイトルは各ページの `PageMeta`（React 19 の `<title>`）が画面確定時に反映済みなので、`document.title` をそのまま使う
  - ただし、データを読み込んでから `PageMeta` を出すページ（イベント詳細 `EventSite`・記事 `JournalArticle`・商品 `ShopProduct`）は、送る時点ではまだ題名が決まっていないため、page_title がサイト名（ei8ht plants）になる。GA ではパス（page_path）で集計できるので、そのままにしている
- **送ってよい URL のクエリは `page`（/official/events の過去イベント切り替え）・`event_id`（/official/reserve）・`utm_〜`（流入元の識別）だけ**。それ以外は外して送る
  - 予約キャンセルの URL（`/official/cancel?id=トークン`）のトークンがあると予約を取り消せるため、GA に残さない
  - ページで新しいクエリを使うときは、秘密の値でなければ `analytics.ts` の `ALLOWED_QUERY_KEYS` に足す
- **GA の管理画面で「拡張計測機能 → ページの変更（ブラウザの履歴イベントに基づく）」をオフにすること**。オンのままだと、GA 側の自動送信と二重に数えられる
- 測定 ID は公開してよい値なのでコードに直接書いている（秘密情報ではない）

### 管理者自身の閲覧を数えない（2026-10-17 追加）

管理画面（/admin）は以前から計測していない。それに加えて、管理画面にログインしているブラウザで公開サイトを見たときも GA4 に送らない。

| 関数（analytics.ts） | 動き |
|---|---|
| `hasAdminSession(storage)` | ブラウザの保存領域（localStorage）に、Supabase のログイン情報（キー名が `sb-<プロジェクト>-auth-token` の形で、値が空でないもの）があれば true。キーがあるかと値が空でないかだけを確かめ、ログイン情報の中身（トークンなど）を解析したり使ったりはしない。`-code-verifier` が付いたキーや、プロジェクト名の部分が空のキー（`sb--auth-token`）は対象外。保存領域が使えないとき（エラーになるとき）は false |
| `setAnalyticsDisabled(disabled)` | `window['ga-disable-G-HCVVDNYL94']` に true / false を入れる。Google 公式の送信停止の仕組みで、ページビューだけでなく、タグを読み込んだ後に GA が自動で送るスクロール・クリックなどの計測も止まる |

- 画面が切り替わるたびにログイン情報を確かめるので、公開サイトを見ている途中で管理画面にログインすると、その後の閲覧は送らない。ログアウトすると（Supabase がログイン情報を消すので）次の画面から送信を再開する
- 本番サイト以外では、ログインの確認もしない（1. の時点で終わる）
- 注意（運用）:
  - ei8htplants.com と www.ei8htplants.com はブラウザの保存領域が別。管理画面にログインしている方のドメインで見たときだけ数えなくなる（もう片方のドメインで見ると数えられる）
  - 管理画面にログインしていない端末（ログアウトしたスマホ、一度もログインしていない端末など）で見た分は、一般の訪問者と同じように数えられる

### 表示の決め方

| 表示 | 決め方 |
|---|---|
| 未入力 | 文字の項目は、空・null・空白と改行だけのとき「未入力」（`hasText()` で判定）。数値は null のとき |
| 「まだ管理情報が登録されていません」 | `isAdminInfoEmpty(info)`: 文字の項目（搬入日時・搬出日時・ホテル名・支払い方法・支払い期限・メモ・要項の文章）がすべて未入力、宿泊料金・出店料が null、支払い済みでない、要項の画像が0枚。収支から補う金額は判定に含めない |

| 要項の文章・メモ | 改行をそのまま表示する（`white-space: pre-wrap`）。長い URL なども枠からはみ出さず折り返す |
| 各項目の並び | 項目名（幅 120px）と値を横に並べ、幅が足りないとき（スマホなど）は値が項目名の下に回る（`flex-wrap`） |


## 31. 公開 — API の読み込みの共通フック（hooks/useApi.ts、2026-10-22 追加）

```

useEffect([...deps, enabled, reloadKey]):
    enabled が false → { data: null, loading: false, error: null }
    それ以外 → 直前の data を残したまま loading: true
               fetcher() の結果を反映。deps が変わった・画面を離れたあとの応答は捨てる（cancelled）
               失敗 → { data: null, loading: false, error }

```

### 計算の関数（lib/priceCalc.ts）

引数の「目標原価率」は 0.4 = 40% の形。省略すると `MAX_COST_RATE`（40%）で計算する。これは計算関数の共通フォールバックで、画面の初期値はブランド別（ei8ht plants は 33.4%、Habitat Oides・HUE は 40%）。

| 名前 | 中身 | 例 |
|---|---|---|
| `MAX_COST_RATE` | 目標原価率の既定値（0.4 = 40%） | — |
| `DEFAULT_COST_RATES` | ブランド別の画面既定値（ei8ht plants 0.334、Habitat Oides・HUE は 0.4） | `defaultCostRateInput('ei8htplants')` → `'33.4'` |
| `COST_RATE_STORAGE_KEY` / `costRateStorageKey(brand)` | ブランド別の入力を保存するキーの接頭辞と生成関数（`price-calc-cost-rate:{brand}`）。旧共通キーは読まない | `costRateStorageKey('hue')` → `'price-calc-cost-rate:hue'` |
| `PRICE_UNIT` | 推奨販売価格を切り上げる単位（100 円。金額の大きさに関係なくいつも 100 円単位） | — |
| `recommendPrice(元値, 目標原価率)` | 推奨販売価格。目安 = 元値 ÷ 目標原価率 を 100 円単位で切り上げる。最低でも 100 円（元値がごく小さくても 0 円にならない） | `recommendPrice(1500)` → 3800、`recommendPrice(300)` → 800、`recommendPrice(5000)` → 12500、`recommendPrice(30)` → 100、`recommendPrice(400)` → 1000、`recommendPrice(8000)` → 20000、`recommendPrice(1500, 0.35)` → 4300 |
| `costRate(元値, 販売価格)` | 原価率（元値 ÷ 販売価格） | `costRate(1500, 4000)` → 0.375 |
| `formatCostRate(原価率, 目標原価率)` | 「37.5%」の形（小数第1位まで。ふつうは四捨五入）にする。目標を超えているのに四捨五入すると目標以下に見えるとき（例: 目標 40% で 0.4004 → 「40.0%」）だけ、切り上げて「40.1%」にする（「40.0%」なのに注意が出る食い違いを防ぐ） | `formatCostRate(0.375)` → `37.5%`、`formatCostRate(0.4004, 0.4)` → `40.1%` |
| `exceedsMaxCostRate(元値, 販売価格, 目標原価率)` | 原価率が目標原価率を超えるか（ちょうど同じは超えない） | `exceedsMaxCostRate(1500, 3000)` → true、`exceedsMaxCostRate(400, 1000)` → false、`exceedsMaxCostRate(1500, 4000, 0.35)` → true |
| `formatRateLabel(目標原価率)` | 見出し・注意の文言用に「40%」「37.5%」の形にする（余計な 0 は付けない） | `formatRateLabel(0.4)` → `40%`、`formatRateLabel(0.35)` → `35%` |
| `parseCostRateInput(入力)` | 目標原価率の欄の文字（% の数）を率にする。1. 全角の数字と小数点（`．`・`。`）を半角にし、前後の空白を除く 2. ふつうの 10 進数の形（`40`・`37.5`・`.5`）だけ受け付ける（`40abc`・`1e2`・`0x28`・`-5`・空は `null`）3. 0 より大きく 100 以下だけ 4. 誤差を消す丸めで 0 になるほど小さい率（0.00004% など）は `null` | `parseCostRateInput('40')` → 0.4、`('37.5')` → 0.375、`('４０')` → 0.4、`('0')`・`('101')`・`('abc')`・`('')`・`('1e2')`・`('0.00004')` → null |
| `loadCostRateInput(brand)` | そのブランドの入力を読む。保存が無い・読めない・受け付けない値ならブランド別既定値（ei8ht plants `'33.4'`、ほかは `'40'`） | — |
| `saveCostRateInput(brand, 入力)` | そのブランドの入力を覚えさせる。受け付けない値は保存せず、前に覚えた値を残す。保存できない環境でも画面は止めない | — |

- 割り算の結果は小数第6位で四捨五入してから切り上げる。例えば 400 ÷ 0.4 が計算機の中でわずかに 1,000 を超えて、1,100 円に跳ね上がるのを防ぐため
- 切り上げなので、推奨販売価格の原価率は必ず目標原価率以下になる
- 3つのブランドで同じ計算関数を使い、ブランド別の目標原価率を渡す。それまで画面の中にあった倍率 `PRICE_MARKUP`（2倍）は消した。いったん作った金額ごとの単位（100・500・1,000 円）を決める `priceUnit` も、同じ日に 100 円単位に統一したので消した
