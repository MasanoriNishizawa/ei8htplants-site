## 1. 認証ガード（AdminLayout）

### 処理フロー

```
AdminLayout マウント
    │
    ├─ supabase が null ?
    │   YES → checking=false (未設定扱い)
    │   NO  → supabase.auth.getSession()
    │             │
    │             └─ session あり? → authed=true
    │                session なし? → authed=false
    │         checking=false
    │
    ├─ checking=true → null（空白）をレンダリング
    │
    ├─ authed=false → <LoginForm /> をレンダリング
    │   フォーム送信 (login関数)
    │     │
    │     ├─ supabase.auth.signInWithPassword({ email, password })
    │     │     │
    │     │     ├─ error → setError(error.message)
    │     │     └─ 成功  → setAuthed(true)
    │
    └─ authed=true → サイドバー + <Outlet />
        ログアウトボタン → supabase.auth.signOut() → setAuthed(false)
```

    // 入力: "YYYY-MM-DD"
    // 出力: "YYYY年M月D日"

    return `${y}年${Number(m)}月${Number(d)}日`

## 8. WS予約フォーム URLパラメータ連携（Reserve.tsx）

### 処理フロー

```
URLパラメータ: ?event_id=<uuid>

useEffect #1 — イベント取得（[eventId] 依存）:
    api.events.get(eventId) → setEvent(event)
    単日イベントの場合: setForm(prev => ({...prev, preferred_date: start_date}))
    複数日イベントの場合: 日付ラジオを表示（preferred_date は未選択）

useEffect #2 — セッション取得（[event, form.preferred_date] 依存）:
    event.has_workshop かつ preferred_date が確定した場合のみ実行
    setSessions([])  ← 前の結果をクリア
    api.events.getSessions(eventId, form.preferred_date) → setSessions(data)
    // preferred_date を渡すことで、その日の予約数を反映した reserved_count を取得

セッション選択後:
    setForm(prev => ({...prev, session_id: session.id}))
    参加人数セレクトを有効化（1〜残席数）

送信:
    api.reserve.create(form)
    成功 → status='done'
    409  → status='full'（「このセッションは満席になりました」表示）
```

### 2-useEffect 分割の理由

- #1 と #2 を1つにまとめると、日付を変えるたびにイベント再取得が走る。
- 日付変更→セッション再ロード → `setSessions([])` で前日の選択がリセットされる。
- 複数日イベントで1日目の混雑状況が2日目に漏れないよう、`?date=` パラメータで日付別集計を行う。

### 処理フロー

```

        api.events.get(id),          → setEvent(ev)
        api.events.getAdminInfo(id), → setForm(info)（出店要項がない古いデータは 文章 null・画像 [] で補う）

    管理情報の出店料・宿泊料金が空なら、収支の出店料・宿泊費を初期値として使う

    finally → setLoading(false)

    loadFailed が true なら何もせず終わる（2026-10-16 追加）

    2. await api.events.saveFinances(id, { ...収支, booth_fee: 出店料, accommodation: 宿泊料金 })

「画像を追加」でファイルを選んだとき (handleAddImages、2026-10-16 追加):
    選ばれたファイルを1枚ずつ順に処理する
        setUploadProgress({ current: 何枚目か, total: 選んだ枚数 })

            成功 → form.guidelines_image_urls の末尾に URL を追加、setImagesDirty(true)

    失敗があれば → setUploadError('次の画像をアップロードできませんでした: 名前1、名前2（JPEG・PNG・WebP・GIF、10MB まで）')
    finally → setUploadProgress(null)、ファイル選択欄を空に戻す（同じファイルを続けて選べるように）

画像の「削除」ボタン (handleRemoveImage、2026-10-16 追加):
    確認ダイアログ「この画像を出店要項から削除しますか？（保存ボタンを押すと確定します）」
        OK → form.guidelines_image_urls からその画像を外す、setImagesDirty(true)
    ※ Storage 上の画像ファイルは消さない。アップロード中は押せない
```

### state 一覧

| state | 型 | 説明 |

| `event` | `Event \| null` | イベント名・日付の表示用 |
| `form` | `EventAdminInfo` | フォームの入力値（出店要項の `guidelines_text`・`guidelines_image_urls` を含む） |

| `saving` | `boolean` | 保存処理中フラグ（ボタンを disabled にする） |
| `saved` | `boolean` | 保存成功時に3秒間 "保存しました" を表示するフラグ |

### 画像の拡大表示（ImageViewer、2026-10-16 追加）

同じファイル内の `ImageViewer` コンポーネントで、出店要項の画像を画面いっぱいに表示する。

| 操作 | 動き |
|---|---|
| サムネイルを押す | その画像を拡大表示する |
| 「← 前へ」「次へ →」ボタン / 左右の矢印キー | 前後の画像に切り替える（2枚以上のときだけボタンを表示。端では何もしない） |
| 「閉じる」ボタン / 画像の外側を押す / Esc キー | 拡大表示を閉じる |

- 2枚以上のときは上部に「n / m」（何枚目 / 全体の枚数）を表示する
- 表示中は後ろのページがスクロールしないようにし、閉じると元に戻す
- 管理画面の枠の影響を受けないよう、ページの一番外側（body の直下）に表示する

## 16. 管理画面 — イベント画像ダウンロード（EventImages.tsx、2026-10-16 追加）

### 実装ファイル

`frontend/src/pages/admin/EventImages.tsx`

### URL

`/admin/events/:id/images`（イベント一覧の各行の「画像DL」ボタンから開く。「← 戻る」は `location.state.from`、未設定時は `/admin/events` へ）

### 処理フロー

```
マウント時:
    Promise.all([
        api.events.get(id),                         → setEvent(ev)
        api.events.getAdminInfo(id).catch(() => null) → setAdminInfo(info)
    ])
    管理情報の取得に失敗しても null として続ける（出店要項のグループだけ出なくなる）
    イベントの取得に失敗 → setError('イベントの読み込みに失敗しました。')
    finally → setLoading(false)

表示するとき:
    groups = collectEventImages(event, adminInfo)
    全グループの枚数を足して「全 N 枚」と表示
    0 枚なら「このイベントには画像が登録されていません」
    通し番号はグループをまたいで 1 から振る

「ダウンロード」ボタン押下 (handleDownload):
    1. そのカードを「保存中...」にし、前回の失敗表示を消す
    2. downloadImage(url, イベント名, 通し番号)
         fetch(url) → 応答が正常でなければ失敗扱い
         blob（画像データ）にしてから一時的なリンクを作り、ファイル名を付けて保存させる
         （Supabase Storage の画像は別のドメインにあるため、リンクに download 属性を付けるだけでは保存されない）
         1秒後に一時的なリンクを片付ける
    3. 失敗 → そのカードに「ダウンロードに失敗しました。元画像を開くから保存してください。」を出す
    finally → 「保存中...」を解除
```

### 画像の集め方（collectEventImages）

次の順に候補を並べ、空の URL と、すでに前のグループで出た URL を取り除く。1枚も残らなかったグループは結果に入れない。

| 順 | グループ名 | 取り出し元 | 補足（caption） |
|---|---|---|---|
| 1 | イベント画像 | `event.images`（`display_order` の小さい順） | なし |
| 2 | イベントサイト：メイン画像 | `page_content.hero.image_url` | なし |
| 3 | イベントサイト：ラインナップ | `page_content.lineup[].image_url` | `title` |
| 4 | イベントサイト：ゲスト | `page_content.guests[].image_url` | `name` |
| 5 | イベントサイト：アーカイブ | `page_content.archive.gallery[]` | なし |
| 6 | 管理情報：出店要項 | `admin_info.guidelines_image_urls[]` | なし |

### ファイル名の決め方（buildImageFileName）

`イベント名_通し番号.拡張子`（例: `春の植物市_03.jpg`）

1. イベント名のうち `\ / : * ? " < > |` と改行を `_` に置き換える
2. 通し番号は2桁にそろえる（1 → `01`）
3. 拡張子は「URL の末尾」→「画像データの種類（jpeg / png / webp / gif）」→「`jpg`」の順に決める。URL の末尾が英数字1〜5文字でないときは拡張子とみなさない

### state 一覧

| state | 型 | 説明 |
|---|---|---|
| `event` | `Event \| null` | 対象イベント。読み込み前・失敗時は null |
| `adminInfo` | `EventAdminInfo \| null` | 管理情報（出店要項の画像に使う）。取得失敗時は null |
| `loading` | `boolean` | 読み込み中フラグ |
| `error` | `string \| null` | 読み込み失敗時のメッセージ |
| `downloading` | `Set<number>` | 保存中の画像の通し番号。そのカードのボタンを「保存中...」にして押せなくする |
| `failed` | `Set<number>` | 保存に失敗した画像の通し番号。そのカードに失敗の案内を出す |

| 関数 | メソッド | パス |
|---|---|---|
| `api.events.get(id)` | GET | `/api/events/{id}` |
| `api.events.getAdminInfo(id)` | GET | `/api/events/{id}/admin-info` |

## 17. 管理画面 — 収支入力と管理情報の同期（EventFinance.tsx）

### 実装ファイル

`frontend/src/pages/admin/EventFinance.tsx`

### 読み込み（マウント時）

```
Promise.all([
    api.events.get(id),
    api.events.getFinances(id),
    api.reserve.list(id),
    api.events.getAdminInfo(id),
])
成功 → setEvent / setAdminInfo / setForm（収支が 0 の出店料・宿泊費は管理情報の値を初期値にする）
どれか失敗 → setError('データの読み込みに失敗しました。ページを再読み込みしてください。')
             setLoadFailed(true)（2026-10-16 追加）
finally → setLoading(false)
```

### 保存時の処理（save）

```
0. loadFailed が true なら何もせず終わる（2026-10-16 追加。保存ボタンも押せない）
1. await api.events.saveFinances(id, form)
2. await api.events.saveAdminInfo(id, { ...adminInfo, booth_fee: 出店料, hotel_fee: 宿泊費 })
   （コード上は adminInfo があるときだけ呼ぶ確認も残っているが、読み込みに成功していれば
     管理情報は空でも {} として取得できるため、保存できるときは必ず同期される）
3. 成功 → 遷移元（収支一覧またはイベント一覧）へ戻る
   失敗 → setError('保存に失敗しました。もう一度お試しください。')
```

| state | 型 | 説明 |
|---|---|---|
| `adminInfo` | `EventAdminInfo \| null` | 読み込んだ管理情報。保存時に出店料・宿泊費だけを書き換えて送り返す（ほかの項目はそのまま残す） |
| `loadFailed` | `boolean` | 読み込み（イベント・収支・予約・管理情報）が1つでも失敗したとき true。true の間は保存ボタンを押せず（薄く表示）、保存処理も先頭で止める（2026-10-16 追加） |

- 読み込みに失敗した画面では、そもそも保存できない（2026-10-16 変更）。初期値（金額 0 など）のまま保存して既存の収支を上書きしたり、空の管理情報で搬入・宿泊・出店要項などを消したりしないため
- 2026-10-16 より前は、管理情報を読み込めていないときに空の初期値をもとに管理情報を保存していたため、入力済みの内容が消えるおそれがあった
- 管理情報の画面から保存したときは、反対に出店料・宿泊料金が収支に同期される（15節）
