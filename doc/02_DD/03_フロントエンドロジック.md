## 1. 認証ガード（AdminLayout）

### 処理フロー

```
AdminLayout マウント
    │
    ├─ supabase が null ?
    │   YES → checking=false (未設定扱い)
    │   NO  → supabase.auth.getSession()
    │             │
    │             └─ session あり? → authed=true
    │                session なし? → authed=false
    │         checking=false
    │
    ├─ checking=true → null（空白）をレンダリング
    │
    ├─ authed=false → <LoginForm /> をレンダリング
    │   フォーム送信 (login関数)
    │     │
    │     ├─ supabase.auth.signInWithPassword({ email, password })
    │     │     │
    │     │     ├─ error → setError(error.message)
    │     │     └─ 成功  → setAuthed(true)
    │
    └─ authed=true → サイドバー + <Outlet />
        ログアウトボタン → supabase.auth.signOut() → setAuthed(false)
```

### シーケンス図

```
Browser          AdminLayout        Supabase Auth
  │                  │                    │
  │  mount           │                    │
  │─────────────────►│                    │
  │                  │ getSession()       │
  │                  │───────────────────►│
  │                  │◄───────────────────│ {session}
  │                  │ setAuthed/checking │
  │                  │                    │
  │  submit login    │                    │
  │─────────────────►│                    │
  │                  │ signInWithPassword │
  │                  │───────────────────►│
  │                  │◄───────────────────│ {error?}
  │                  │ setAuthed(true)    │
  │◄─────────────────│                    │
  │  Admin UI 表示   │                    │
```

## 2. IntersectionObserver — ブランドサブナビゲーション

### 実装ファイル
`frontend/src/pages/brands/HabitatOides.tsx` (他ブランドページも同パターン)

### アルゴリズム

```
SECTIONS = ['concept', 'workshop', 'collaboration']

コンポーネントマウント時:
    IntersectionObserver を生成
        rootMargin: '-55% 0px -45% 0px'
        // ビューポートの中央10%帯域を交差判定ゾーンとする
        callback: entries.forEach(e => {
            if (e.isIntersecting) setActive(e.target.id)
        })

    SECTIONS.forEach(id => obs.observe(sectionRefs.current[id]))

アンマウント時:
    obs.disconnect()

scrollTo(id):
    document.getElementById(id)?.scrollIntoView({ behavior: 'smooth' })
```

### rootMargin の意味

```
ビューポート
┌─────────────────┐  ← 上端
│ (無視ゾーン 55%)│
├─────────────────┤  ← -55% ライン
│  判定ゾーン10%  │  ← ここに入ったセクションをアクティブ判定
├─────────────────┤  ← -45% ライン
│ (無視ゾーン 45%)│
└─────────────────┘  ← 下端
```

## 5. EventCard 画像スライドショー（EventCard.tsx）

### アルゴリズム

```
state: imgIdx = 0

images.length <= 1 → prev/nextボタン非表示

[<] ボタンクリック:
    setImgIdx(prev => (prev - 1 + images.length) % images.length)
    // 循環: 0 → images.length-1

[>] ボタンクリック:
    setImgIdx(prev => (prev + 1) % images.length)
    // 循環: images.length-1 → 0

表示: images[imgIdx].url を <img src> に反映
```

### formatDate 関数

```typescript
function formatDate(s: string): string {
    // 入力: "YYYY-MM-DD"
    // 出力: "YYYY年M月D日"
    const [y, m, d] = s.split('-')
    return `${y}年${Number(m)}月${Number(d)}日`
}
```


## 7. WS予約フォーム URLパラメータ連携（Reserve.tsx）

### 処理フロー

```
URLパラメータ: ?event_id=<uuid>

useEffect #1 — イベント取得（[eventId] 依存）:
    api.events.get(eventId) → setEvent(event)
    単日イベントの場合: setForm(prev => ({...prev, preferred_date: start_date}))
    複数日イベントの場合: 日付ラジオを表示（preferred_date は未選択）

useEffect #2 — セッション取得（[event, form.preferred_date] 依存）:
    event.has_workshop かつ preferred_date が確定した場合のみ実行
    setSessions([])  ← 前の結果をクリア
    api.events.getSessions(eventId, form.preferred_date) → setSessions(data)
    // preferred_date を渡すことで、その日の予約数を反映した reserved_count を取得

セッション選択後:
    setForm(prev => ({...prev, session_id: session.id}))
    参加人数セレクトを有効化（1〜残席数）

送信:
    api.reserve.create(form)
    成功 → status='done'
    409  → status='full'（「このセッションは満席になりました」表示）
```

### 2-useEffect 分割の理由

- #1 と #2 を1つにまとめると、日付を変えるたびにイベント再取得が走る。
- 日付変更→セッション再ロード → `setSessions([])` で前日の選択がリセットされる。
- 複数日イベントで1日目の混雑状況が2日目に漏れないよう、`?date=` パラメータで日付別集計を行う。

## 10. 管理画面 — 予約一覧とPDF印刷（Reservations.tsx）

### イベントフィルター

```
初期マウント時:
    api.events.list(false) + api.events.list(true) を並列取得
    → eventsMap（id→name）と eventsDataMap（id→Event）を構築
    → 各イベントのセッションを getSessions で取得し sessionsData（id→WsSession）を構築
    → reservations を全件取得

eventFilter 変更時:
    filtered = eventFilter === 'all'
        ? reservations
        : reservations.filter(r => r.event_id === eventFilter)
    filtered は preferred_date → preferred_time の順でソート
```

### ステータス更新

```
<select> onChange:
    if (updating !== null) return  // 重複更新防止

    setUpdating(id)
    api.reserve.updateStatus(id, value)
        成功 → setReservations(prev =>
                   prev.map(r => r.id === id ? {...r, status: value} : r)
               )
        finally → setUpdating(null)
```

### PDF 印刷（printReservations）

特定イベントを選択した状態でのみ「PDF で印刷」ボタンが表示される。

```
printReservations(rows, eventName, sessionsData, event):
    window.open('', '_blank') で新規ウィンドウ
    document.write(htmlString) でページ生成
    window.onload → window.print()

    日付ループ (getDateRange(start_date, end_date)):
        セッションループ:
            当該日×セッションの予約行を表示
            reservedCount = sessionRows.reduce((s, r) => s + r.participants, 0)
            空枠 = session.max_participants - reservedCount 行を破線行として追加

    日付ヘッダーは最初の日は break-before なし、2日目以降は break-before: page
    → @media print で各日付が必ずページ先頭に来る
```
