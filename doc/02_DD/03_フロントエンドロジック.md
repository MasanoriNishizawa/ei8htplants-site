# DD-03 — フロントエンドロジック

## 1. 認証ガード（AdminLayout）

### 処理フロー

```
AdminLayout マウント
    │
    ├─ supabase が null ?
    │   YES → checking=false (未設定扱い)
    │   NO  → supabase.auth.getSession()
    │             │
    │             └─ session あり? → authed=true
    │                session なし? → authed=false
    │         checking=false
    │
    ├─ checking=true → null（空白）をレンダリング
    │
    ├─ authed=false → <LoginForm /> をレンダリング
    │   フォーム送信 (login関数)
    │     │
    │     ├─ supabase.auth.signInWithPassword({ email, password })
    │     │     │
    │     │     ├─ error → setError(error.message)
    │     │     └─ 成功  → setAuthed(true)
    │
    └─ authed=true → サイドバー + <Outlet />
        ログアウトボタン → supabase.auth.signOut() → setAuthed(false)
```

### シーケンス図

```
Browser          AdminLayout        Supabase Auth
  │                  │                    │
  │  mount           │                    │
  │─────────────────►│                    │
  │                  │ getSession()       │
  │                  │───────────────────►│
  │                  │◄───────────────────│ {session}
  │                  │ setAuthed/checking │
  │                  │                    │
  │  submit login    │                    │
  │─────────────────►│                    │
  │                  │ signInWithPassword │
  │                  │───────────────────►│
  │                  │◄───────────────────│ {error?}
  │                  │ setAuthed(true)    │
  │◄─────────────────│                    │
  │  Admin UI 表示   │                    │
```

## 2. IntersectionObserver — ブランドサブナビゲーション

### 実装ファイル
`frontend/src/pages/brands/HabitatOides.tsx` (他ブランドページも同パターン)

### アルゴリズム

```
SECTIONS = ['concept', 'workshop', 'collaboration']

コンポーネントマウント時:
    IntersectionObserver を生成
        rootMargin: '-55% 0px -45% 0px'
        // ビューポートの中央10%帯域を交差判定ゾーンとする
        callback: entries.forEach(e => {
            if (e.isIntersecting) setActive(e.target.id)
        })

    SECTIONS.forEach(id => obs.observe(sectionRefs.current[id]))

アンマウント時:
    obs.disconnect()

scrollTo(id):
    document.getElementById(id)?.scrollIntoView({ behavior: 'smooth' })
```

### rootMargin の意味

```
ビューポート
┌─────────────────┐  ← 上端
│ (無視ゾーン 55%)│
├─────────────────┤  ← -55% ライン
│  判定ゾーン10%  │  ← ここに入ったセクションをアクティブ判定
├─────────────────┤  ← -45% ライン
│ (無視ゾーン 45%)│
└─────────────────┘  ← 下端
```

## 5. EventCard 画像スライドショー（EventCard.tsx）

### アルゴリズム

```
state: imgIdx = 0

images.length <= 1 → prev/nextボタン非表示

[<] ボタンクリック:
    setImgIdx(prev => (prev - 1 + images.length) % images.length)
    // 循環: 0 → images.length-1

[>] ボタンクリック:
    setImgIdx(prev => (prev + 1) % images.length)
    // 循環: images.length-1 → 0

表示: images[imgIdx].url を <img src> に反映
```

### formatDate 関数

```typescript
function formatDate(s: string): string {
    // 入力: "YYYY-MM-DD"
    // 出力: "YYYY年M月D日"
    const [y, m, d] = s.split('-')
    return `${y}年${Number(m)}月${Number(d)}日`
}
```

## 6. お問い合わせフォーム stateマシン（Contact.tsx）

### 状態遷移

```
idle
 │  送信ボタンクリック
 ▼
loading
 │  api.contact.send(form) await
 ├─ 成功 ──────────────────────────────► done
 │                                        ※ setForm(空文字クリア)
 └─ 失敗 ──────────────────────────────► error

done / error
 │  画面に残る（再送信可能にするため戻り先なし）
```

### レンダリング分岐

| status | 表示 |
|---|---|
| `idle` | フォーム |
| `loading` | フォーム + ボタンdisabled |
| `done` | "送信完了" メッセージ |
| `error` | フォーム + エラーメッセージ |

### シーケンス図

```
User          Contact.tsx        api.ts          FastAPI
 │               │                   │               │
 │  submit       │                   │               │
 │──────────────►│                   │               │
 │               │ setStatus('loading')              │
 │               │ api.contact.send(form)            │
 │               │──────────────────►│               │
 │               │                   │ POST /contact │
 │               │                   │──────────────►│
 │               │                   │◄──────────────│ {ok:true}
 │               │◄──────────────────│               │
 │               │ setStatus('done') │               │
 │               │ setForm({name:'',...})            │
 │◄──────────────│                   │               │
 │  完了メッセージ│                   │               │
```

## 7. WS予約フォーム URLパラメータ連携（Reserve.tsx）

### 処理フロー

```
URLパラメータ: ?event_id=<uuid>

コンポーネントマウント時 (useEffect):
    const params = new URLSearchParams(location.search)
    const eventId = params.get('event_id')

    if (eventId):
        api.events.get(eventId) → setEvent(event)
        setForm(prev => ({ ...prev, event_id: eventId }))

送信:
    api.reserve.create(form)
    成功 → status='done'
```

## 9. 管理画面 — 取扱店 編集モーダル（Stockists.tsx）

### 処理フロー

```
[編集] ボタンクリック:
    setEditing(stockist)
    setEditForm({
        name: stockist.name,
        area: stockist.area,
        address: stockist.address,
        url: stockist.url,
        brands: [...stockist.brands],
    })
    → モーダルオーバーレイ表示

ブランドチェックボックス操作 (BrandCheckboxes コンポーネント):
    チェックON:  setBrands(prev => [...prev, brand])
    チェックOFF: setBrands(prev => prev.filter(b => b !== brand))

[保存] クリック:
    api.stockists.patch(editing.id, editForm)
    成功 → 一覧再取得, setEditing(null)

[キャンセル] / オーバーレイクリック:
    setEditing(null) → モーダル非表示
```

## 10. 管理画面 — 予約ステータス更新（Reservations.tsx）

### 処理フロー

```
<select> onChange:
    if (updating !== null) return  // 重複更新防止

    setUpdating(id)
    api.reserve.updateStatus(id, value)
        成功 → setReservations(prev =>
                   prev.map(r => r.id === id ? {...r, status: value} : r)
               )
        finally → setUpdating(null)
```

### ステータスバッジ色定義

| status | 背景色 | 文字色 | 日本語ラベル |
|---|---|---|---|
| `pending` | `#fef9f0` | `#b8860b` | 未確認 |
| `confirmed` | `#f0fff4` | `#2e7d32` | 確認済 |
| `cancelled` | `#fff0f0` | `#c62828` | キャンセル |
| （その他） | `#f5f5f5` | `#555` | — |
