## 1. イベント作成 — 画像カスケード処理

### 処理フロー (`routes/events.py`)

```
POST /api/events  body: EventBody

create_event(body):
    1. body.model_dump(exclude={'image_urls'}) でimage_urlsを除いたdictを生成
    2. admin_supabase.table('events').insert(row) → result (UUIDが返る)
    3. _save_images(result['id'], body.image_urls) 呼び出し
    4. get_event(result['id']) を返す（imageを含む完全データ）

_save_images(event_id, urls):
    if not urls: return  # 画像なしは即リターン
    rows = [
        {'event_id': event_id, 'url': url, 'display_order': i}
        for i, url in enumerate(urls)
    ]
    admin_supabase.table('event_images').insert(rows).execute()
    // enumerate → display_order は 0-indexed
```

### イベント更新 — 画像全置換

```
PUT /api/events/{event_id}  body: EventBody

update_event(event_id, body):
    1. eventsテーブルを update
    2. event_images を DELETE WHERE event_id = event_id  (全削除)
    3. _save_images(event_id, body.image_urls)  (再挿入)
    4. get_event(event_id) を返す

// 差分更新ではなく全置換。画像の順序変更もこのフローで対応。
```

### イベント取得 — _attach_images

```
_attach_images(events: list[dict]) → list[dict]:
    if not events: return events

    ids = [e['id'] for e in events]

    // N+1を避けるため IN句で一括取得
    imgs = supabase.table('event_images')
                   .select('*')
                   .in_('event_id', ids)
                   .order('display_order')
                   .execute().data

    // event_idをキーにグルーピング
    img_map: dict[str, list] = {}
    for img in imgs:
        img_map.setdefault(img['event_id'], []).append(img)

    // 各イベントに images プロパティを付与
    for e in events:
        e['images'] = img_map.get(e['id'], [])

    return events
```

## 2. お問い合わせ — 二重書き込みフロー

### 処理フロー (`routes/contact.py`)

```
POST /api/contact  body: ContactBody

send_contact(body):
    1. 設定チェック
       if not RESEND_API_KEY or not CONTACT_TO_EMAIL:
           raise HTTPException(500, 'Mail not configured')

    2. DB保存 (admin_supabase 使用)
       admin_supabase.table('contacts').insert(body.model_dump()).execute()
       // body.model_dump() = {name, email, message}
       // is_read は DEFAULT false, created_at は DEFAULT now()

    3. メール送信 (Resend SDK)
       resend.api_key = RESEND_API_KEY
       resend.Emails.send({
           'from': CONTACT_FROM_EMAIL,
           'to': [CONTACT_TO_EMAIL],
           'reply_to': body.email,    // 返信先を問い合わせ者のメールに設定
           'subject': f'[ei8ht plants] お問い合わせ: {body.name}',
           'text': f'お名前: {body.name}\nメール: {body.email}\n\n{body.message}',
       })

    4. return {'ok': True}
```

### 注意点

- DB保存とメール送信はトランザクションで保護されていない。
- DB保存成功・メール失敗の場合: HTTP 500 が返るが DBにはレコードが残る。
  → 管理画面 `/admin/contacts` でレコードは確認できる。
- DB保存失敗の場合: Supabase例外がそのまま HTTP 500 となる。

## 3. ギャラリー — ブランドクエリフィルタ

### 処理フロー (`routes/gallery.py`)

```
GET /api/gallery?brand=<value>

list_gallery(brand: Optional[str] = None):
    q = supabase.table('gallery_images').select('*').order('display_order')

    if brand:                // brand が None または空文字でなければ
        q = q.eq('brand', brand)

    return q.execute().data
```

### クエリ生成パターン

| リクエスト | SQLクエリ |
|---|---|
| `GET /api/gallery` | `SELECT * FROM gallery_images ORDER BY display_order` |
| `GET /api/gallery?brand=ei8ht+plants` | `SELECT * FROM gallery_images WHERE brand='ei8ht plants' ORDER BY display_order` |
| `GET /api/gallery?brand=` (空文字) | `SELECT * FROM gallery_images ORDER BY display_order` (フィルタなし) |

## 4. display_order 採番ロジック

### 採番方法（gallery.py / stockists.py / collaborations.py 共通）

```python
count = supabase.table('<テーブル>').select('id', count='exact').execute().count or 0
// count='exact' で件数のみ取得（データ転送なし）
// .count は None の場合があるため or 0 でデフォルト値

insert({...body, 'display_order': count})

```

- 同時に2件追加された場合、同じ display_order が付与される可能性がある。
- 管理画面は単一ユーザー運用を想定しているため許容している。

## 5. 予約ステータス更新とキャンセルリンク送信

### 処理フロー (`routes/reserve.py`)

```
PATCH /api/reserves/{reservation_id}  body: ReserveStatusPatch

update_reservation_status(reservation_id, body):
    1. 現在の行を取得
    2. status が 'confirmed' かつ cancel_token が未設定の場合:
           cancel_token = _generate_cancel_token()  // 8桁数字
           update_data = {'status': 'confirmed', 'cancel_token': cancel_token}
       それ以外:
           update_data = {'status': body.status}
    3. workshop_reservations を update
    4. セッションあり → _sync_reserved_count(session_id)
    5. cancel_token を新規発行した場合 → _send_cancel_link_email(row, event, cancel_token)
    6. 更新後の行を返す
```

- キャンセルトークンは初回確定時のみ発行（再確定時は既存トークンを維持し、メール済みリンクが無効にならないようにする）。
- `status` の値はバックエンドでバリデーションしない（'pending'/'confirmed'/'cancelled'の3値をフロントエンドが保証）。

### キャンセルフロー

```
POST /api/reserve/cancel  body: CancelBody { token: string }

cancel_by_token(body):
    1. cancel_token で全行を取得（created_at 降順）
    2. 行なし → 404
    3. 最新の非キャンセル行を選択
       なし → 400（「すでにキャンセル済み」）
    4. status = 'cancelled' に更新
    5. セッションあり → _sync_reserved_count(session_id)
    6. 更新後の行を返す
```

## 6. Supabase クライアント 二重構成

### `backend/app/db.py`

```python
supabase = create_client(SUPABASE_URL, SUPABASE_ANON_KEY)
# → RLSが有効。"public read" ポリシーで SELECT のみ可能。

admin_supabase = create_client(SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY)
# → RLSをバイパス。全操作（SELECT/INSERT/UPDATE/DELETE）可能。
```

### 使い分け

| 操作 | クライアント | 理由 |
|---|---|---|
| イベント・ギャラリー・取扱店・コラボ一覧取得 | `supabase` | 公開データ。anonキーで十分 |
| イベント単件取得 | `supabase` | 同上 |
| INSERT / UPDATE / DELETE （全テーブル） | `admin_supabase` | RLSの書き込み制限をバイパス |
| contacts 一覧取得 | `admin_supabase` | service_role のみ読み取り許可 |
| workshop_reservations 一覧・更新 | `admin_supabase` | 同上 |
| display_order の count 取得 | `supabase` | 公開テーブルはanonで読める |

## 7. JST タイムゾーン処理（`routes/events.py`）

サーバーは UTC で動作するため、日本時間の日付判定には専用ヘルパーを使用する。

```python
from datetime import datetime, timezone, timedelta

_JST = timezone(timedelta(hours=9))

def _today_jst() -> str:
    return datetime.now(_JST).date().isoformat()
```

- `date.today()` は UTC 基準のため JST 深夜 0〜9 時の間に誤判定が発生する。
- `_today_jst()` を全ての日付比較（`is_past` 計算、`list_events` フィルタ、`get_event`）で使用する。

## 8. ドメインリダイレクト（`main.py`）

`ei8htplants.onrender.com` へのアクセスを `ei8htplants.com` へ 301 リダイレクトするミドルウェア。

```python
@app.middleware('http')
async def redirect_render_domain(request: Request, call_next):
    host = request.headers.get('host', '')
    if 'onrender.com' in host:
        url = str(request.url).replace(f'https://{host}', 'https://ei8htplants.com', 1)
        return RedirectResponse(url=url, status_code=301)
    return await call_next(request)
```

- `cache_control` ミドルウェアより前に登録する（HTTPミドルウェアは登録の逆順に実行）。

## 9. WSセッション予約数 — 日付別ライブ計算（`routes/events.py`）

```
GET /api/events/{event_id}/sessions?date=YYYY-MM-DD

get_sessions(event_id, date):
    1. ws_sessions を event_id でフェッチ（display_order 昇順）
    2. session_id_set / time_to_sid マップを構築
    3. workshop_reservations を event_id でフェッチ（status != 'cancelled'）
       → date 指定時は preferred_date でフィルタ
    4. 各予約を session_id で照合:
         session_id が None or session_id_set 外 → time_label で照合（fallback）
    5. count_map[session_id] に participants を加算
    6. 各 ws_sessions.reserved_count をライブ値で上書き
```

**fallback の必要性**: 管理画面でセッションを再保存すると DELETE + INSERT で UUID が変わる。
古い予約の `session_id` は無効になるが、`preferred_time` 文字列は維持されているため、
`time_to_sid` マップ（time_label → session_id）で照合する。

## 10. 予約定員チェック — スレッドロックによる原子化（`routes/reserve.py`）

同一セッションへの同時送信でオーバーブッキングが起きないよう、
セッション単位の `threading.Lock` でチェック→INSERTを直列化する。

```python
_session_locks: dict[str, threading.Lock] = {}
_session_locks_mu = threading.Lock()

def _session_lock(session_id: str) -> threading.Lock:
    with _session_locks_mu:
        if session_id not in _session_locks:
            _session_locks[session_id] = threading.Lock()
        return _session_locks[session_id]

def create_reservation(body):
    if body.session_id:
        with _session_lock(body.session_id):
            # capacity check (session_id + preferred_time fallback)
            if used + body.participants > session['max_participants']:
                raise HTTPException(409, 'このセッションは満席です')
            row = admin_supabase.table('workshop_reservations').insert(...).execute().data[0]
    else:
        row = admin_supabase.table('workshop_reservations').insert(...).execute().data[0]
```

**制約**: 単一プロセス内でのみ有効（Render 単一インスタンス構成を前提）。
マルチプロセス構成になった場合は DB レベルのロック（PostgreSQL Advisory Lock 等）が必要。

定員チェックは `participants` カラムの合計値（行数ではなく人数）で判定し、
`session_id` が無い古い予約は `preferred_time` フォールバックで加算する。

## 12. SPA フォールバック（本番）

### `backend/app/main.py`

```python
DIST = os.path.join(os.path.dirname(__file__), '../../frontend/dist')

if os.path.isdir(DIST):
    # 静的ディレクトリを個別マウント
    for _subdir in ['assets', 'img', 'favicon']:
        _path = os.path.join(DIST, _subdir)
        if os.path.isdir(_path):
            app.mount(f'/{_subdir}', StaticFiles(directory=_path), name=_subdir)

    # SPAフォールバック: 既存ファイルはそのまま返し、それ以外はindex.html
    @app.get('/{full_path:path}')
    def serve_spa(full_path: str):
        file_path = os.path.join(DIST, full_path)
        if os.path.isfile(file_path):
            return FileResponse(file_path)
        return FileResponse(os.path.join(DIST, 'index.html'))
```

- Vite ビルド済みSPAを FastAPI 単体で配信するための設定。
- `/{full_path:path}` はAPI routerより後に登録されているため、`/api/*` はAPIが処理する。
- `frontend/dist` が存在しない開発時はこのブロックは実行されない。
