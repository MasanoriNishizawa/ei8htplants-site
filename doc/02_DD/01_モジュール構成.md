
### 処理の流れ（app.py）

```
app.py
  0. st.set_option("client.showErrorDetails", "none")（予期しないエラーの詳細を画面に出さない。
     設定ファイルが読まれない起動の仕方でも効くように、ほかの import より前でコードでも入れる）
  1. st.set_page_config（タブのタイトル「ei8ht plants 分析」・横幅いっぱい）
  2. lib/secrets_env.py の load_secrets_into_env()（Secrets を環境変数に反映。secrets.toml が無いローカルでは何もしない）
  3. lib/auth.py の require_login()
       ├─ ログイン済み → パスワード欄の値（auth_password_input）を消す
       │                 → 許可リストを確かめ直す（is_allowed）
       │                    ├─ 許可 → メールアドレスを返して次へ
       │                    └─ 不許可 → logout() してログインフォームへ
       └─ 未ログイン   → ログインフォームを出して止まる（以降の画面・データ読み込みは行わない）
  4. st.navigation で画面の一覧を作る
       ├─ ダッシュボード: 概要 / イベント収支 / ワークショップ / ショップ / 問い合わせ・記事
       └─ 分析: アクセス解析 / 予測・シミュレーション
  5. サイドバー: 「ログイン中: メール」・「ログアウト」（render_sidebar）・「データを再読み込み」
  6. 選ばれた画面を表示（各画面は lib/context.py の get_context() でデータを受け取る）
```

### 依存関係

```
app.py ──► lib/secrets_env.py（Secrets → 環境変数）
   │
   ├──► lib/auth.py ──► Supabase Auth（POST /auth/v1/token?grant_type=password、anon キー）
   │
   └──► views/*.py ──► lib/context.py ──► lib/data.py ──► Supabase（GET /rest/v1/<テーブル>、service_role キー）
              │              ├──► lib/finance.py
              │              └──► lib/analysis.py
              ├──► lib/charts.py
              └──► lib/ga.py ──► GA4 Data API（views/traffic.py だけ）
```

- 接続情報は環境変数から読む。ローカルではリポジトリ直下の `.env`、Community Cloud ではアプリの Secrets（一番外側に書いた値が環境変数に入る。`lib/secrets_env.py`）。両方ある場合は Secrets の値が優先される
- `lib/data.py` は `@st.cache_data(ttl=600)` で 10 分間データを覚えておく。サイドバーの「データを再読み込み」で消せる
- `frontend/` と `backend/` のコードは使わない（収支の式だけは `frontend/src/lib/api.ts` の `computeFinances` と同じものを `lib/finance.py` に書いている）

### 主な関数（lib/auth.py）

| 関数 | 何をするか | 戻り値 |
|---|---|---|
| `authenticate(email, password, url, anon_key)` | Supabase Auth にメールアドレスとパスワードを送り、ログインできるか確かめる（待ち時間 10 秒） | 成功: `(True, Supabase が返したメール)`／失敗: `(False, 画面に出すメッセージ)` |
| `is_allowed(email, allowed_env)` | `ANALYTICS_ALLOWED_EMAILS` に入っているかを判定（空なら全員許可） | `True` / `False` |
| `is_locked(fail_count, last_fail_at, now)` | 失敗が 5 回以上で、最後の失敗から 60 秒たっていないか | `True`（ロック中）/ `False` |
| `require_login()` | ログイン済みならメールを返し、未ログインならフォームを出して止める。ログイン済みでも毎回 `is_allowed` を確かめ直し、許可されなければ `logout()` してフォームを出す。あわせて、パスワード欄（key: `auth_password_input`）の値を `session_state` から消す。フォームは送信後に入力欄を空に戻す（`clear_on_submit=True`） | ログイン中のメールアドレス |
| `render_sidebar(email)` | サイドバーに「ログイン中: メール」と「ログアウト」を出す | なし |
| `logout()` | ログイン状態（メールアドレス）を消す | なし |

ログイン状態はブラウザのタブごとの記憶（`st.session_state`）に持つ。置くのは次の3つだけで、パスワードとトークンは置かない（パスワード欄の値 `auth_password_input` は、ログイン後の最初の実行で消す）。

| キー | 中身 |
|---|---|
| `auth_email` | ログイン中のメールアドレス（未ログインならキーなし） |
| `auth_fail_count` | 続けて失敗した回数（ログインに成功したら消す） |
| `auth_last_fail_at` | 最後に失敗した時刻 |

### 主な関数（lib/secrets_env.py）

| 関数 | 何をするか | 戻り値 |
|---|---|---|
| `load_secrets_into_env()` | `st.secrets` を一度読み込む。Streamlit は読み込んだときに、Secrets の一番外側の値（文字列・整数・小数）を環境変数に入れる（見出しの下の値・真偽値は入れない。同じ名前の環境変数があれば Secrets の値で上書き）。`secrets.toml` が無い・書き方が誤っていて読めないときは何もしない。読み取れないとき（権限が無いなど）は、例外の種類だけをログに出す（値は出さない） | 読み込めたら `True`、無い・読めないときは `False` |

### 主な関数（lib/ga.py）

鍵は「場所」と「中身」のどちらでも受け取れる。キャッシュ（`st.cache_data`）の引数には鍵の中身を入れず、「どこから鍵を読むか」の目印だけを渡す（キャッシュのキーに秘密が入らないようにするため）。

| 名前 | 何をするか | 戻り値 |
|---|---|---|
| `ga_config()` | 環境変数から `GA_PROPERTY_ID` と鍵の設定を読み、足りないものを確かめる。プロパティ ID は空・`G-` で始まる・数字以外ならエラー。鍵は `GA_CREDENTIALS_JSON`（中身）があればそちらを優先して `parse_credentials_json` で確かめ、無ければ `GA_CREDENTIALS`（ファイルの場所）にファイルがあるかを確かめる | `(GaConfig, None)` または `(None, 足りないものの説明)` |
| `GaConfig` | 接続設定。`property_id`（プロパティ ID）と `credentials_path`（鍵ファイルの場所。中身で渡すときは `None`） | — |
| `GaConfig.credentials_ref` | 「鍵をどこから読むか」の目印。鍵ファイルの場所、または `env:GA_CREDENTIALS_JSON`（中身を環境変数から読む印） | 文字列（秘密の値は含まない） |
| `parse_credentials_json(text)` | `GA_CREDENTIALS_JSON` の文字列を鍵の辞書にする。文字列の中の改行も受け付ける。JSON として読めない・`{ … }` の形でない・`type` が `service_account` でない・`client_email`・`private_key`・`token_uri` のどれかが無いときは `CredentialsError`（メッセージは行・文字の位置や足りない項目名だけで、鍵の中身は含めない） | 鍵の辞書 |
| `load_credentials(credentials_ref)` | 目印から読み取り専用の権限（`analytics.readonly`）の認証情報を作る。`GA_CREDENTIALS_JSON` 方式なら、ここで初めて環境変数から中身を読む | 認証情報 |
| `run_report(property_id, credentials_ref, …)` | GA4 のレポートを取得する（10 分キャッシュ） | 表（DataFrame） |

### 設定ファイル（`.streamlit/config.toml`）が2つある理由

| ファイル | 読まれる場面 | 書いてあること |
|---|---|---|
| `.streamlit/config.toml`（リポジトリ直下） | Community Cloud で公開しているとき（Community Cloud は作業フォルダが常にリポジトリ直下で、この場所の設定しか読まない）。リポジトリ直下から `streamlit run analytics/app.py` で起動したときも | `[theme]`（明るいテーマ・管理画面と同じ緑）・`[client]`（エラーの詳細を出さない）・`[browser]`（利用状況を送らない）。`[server]` は書かない（アドレス・ポートは Community Cloud が決める） |
| `analytics/.streamlit/config.toml` | 自分の PC で `analytics` フォルダから起動したとき | 上と同じ `[theme]`・`[client]`・`[browser]` に加えて、`[server]`（`localhost:8501`。自分の PC からだけ開く） |

- `[theme]`・`[client]`・`[browser]` を変えるときは、**両方をそろえる**
- どちらのファイルでも、XSRF 保護・CORS など Streamlit の既定の安全設定は無効にしない
