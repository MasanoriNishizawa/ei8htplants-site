# RD-04 — 非機能要件 (Non-Functional Requirements)

IPA「非機能要求グレード」の6分類に沿って定義する。

---

## 1. 可用性 (Availability)

| 項目 | 目標値・方針 |
|---|---|
| サービス稼働時間 | 24時間365日（SaaS依存） |
| 計画外停止目標 (RTO) | 4時間以内に復旧（本番サーバー障害時） |
| データ損失許容時間 (RPO) | Supabaseのバックアップ周期に依存（最大24時間分）。運用フェーズで方針確定 |
| 単一障害点 | Supabaseへの依存度が高い。Supabase障害時はサイト全体が停止する（許容範囲） |
| 本番構成 | FastAPI単一プロセス + Supabase（外部DB）構成。冗長化は現フェーズスコープ外 |

---

## 2. 性能・拡張性 (Performance & Scalability)

| 項目 | 目標値・方針 |
|---|---|
| ページ初期表示 | 3秒以内（LTE相当環境）を目標 |
| API応答時間 | 通常時 500ms以内（Supabase + FastAPI） |
| 同時接続数 | 小規模サイト想定。50同時接続以下を現フェーズのターゲットとする |
| スケールアップ対応 | Supabaseプランのアップグレードで対応可能。アプリコードの変更は不要 |
| 画像配信 | 自社サーバーでは配信しない。外部URL（Google Drive等）を直接参照 |
| フロントエンドビルド | Viteによる最適化ビルド。コード分割・ツリーシェイキング適用 |

---

## 3. 運用・保守性 (Maintainability)

| 項目 | 方針 |
|---|---|
| コンテンツ更新 | 管理者が非エンジニアでも操作できるAdmin画面を提供。開発者不在でも更新可能 |
| コード管理 | Gitで管理。mainブランチが本番対応コード |
| ログ | uvicornアクセスログ（リクエスト・ステータス）を標準出力に出力 |
| エラー監視 | 現フェーズではエラー監視ツールなし。uvicornログを手動確認 |
| 依存パッケージ | `requirements.txt` / `package.json` でバージョン固定。定期的なセキュリティアップデートを推奨 |
| ドキュメント | `doc/` 以下に設計書（RD/BD/DD）を整備し、引き継ぎを容易にする |

---

## 4. 移行性 (Portability)

| 項目 | 方針 |
|---|---|
| デプロイ先変更 | FastAPIはDockerコンテナ化に対応可能。Supabaseへの接続情報を `.env` で管理しているため、クラウド移行も容易 |
| フロントエンド | Viteビルド成果物（静的ファイル）であれば、任意のCDNやホスティングサービスに移行可能 |
| データ移行 | Supabase PostgreSQLのpg_dumpでエクスポート可能。新DBへの移行手順は `doc/OP/01_移行計画書.md` を参照 |
| 外部依存 | Resend（メール）はAPIキー変更のみで他サービス（SendGrid等）に切り替え可能（`contact.py` 修正が必要） |

---

## 5. セキュリティ (Security)

| 項目 | 方針 |
|---|---|
| 秘匿情報管理 | `.env` ファイルで管理。`.gitignore` に含まれており、リポジトリには絶対にコミットしない |
| 公開クライアントへの情報露出 | フロントエンドには `VITE_SUPABASE_ANON_KEY`（公開安全なanon key）のみ公開。`SERVICE_ROLE_KEY` はバックエンド限定 |
| 管理者認証 | Supabase Auth（メール + パスワード）によるセッション管理。JWTトークンをSupabaseが発行 |
| API認証 | 管理系APIにはバックエンド認証なし（現フェーズ）。Admin操作は管理者がログイン後にブラウザから行う想定。将来的にはAPI Keyまたはセッショントークン検証の追加を検討 |
| XSS対策 | Reactの仮想DOM標準機能によりXSS防止。innerHTML等の危険な操作は使用しない |
| SQLインジェクション対策 | Supabase Python SDK経由のパラメータバインディングにより防止 |
| CORS設定 | 開発時は `localhost:5173` のみ許可。本番では適切なドメインに制限する |
| HTTPS | 本番デプロイ先のSSL設定に委ねる（Supabase URL は常にHTTPS） |

---

## 6. システム環境 (System Environment)

### フロントエンド実行環境

| 項目 | 内容 |
|---|---|
| 対応ブラウザ | Chrome・Safari・Firefox の最新版 |
| モバイル対応 | レスポンシブデザイン（スマートフォン・タブレット対応） |
| JavaScript | 必須（React SPAのため）|

### バックエンド実行環境

| 項目 | 内容 |
|---|---|
| OS | Linux（本番）/ macOS（開発） |
| Python | 3.12.9 以上 |
| フレームワーク | FastAPI 0.115.5 + uvicorn 0.32.1 |
| ポート | 8000（開発時）、本番はリバースプロキシ経由 |

### 開発環境

| 項目 | 内容 |
|---|---|
| フロントエンド | Node.js + Vite dev server（port 5173） |
| バックエンド | Python venv + uvicorn --reload（port 8000） |
| DB | Supabase（クラウド）を開発・本番共通で使用 |

### インフラ・外部サービス依存

| サービス | 用途 | SLA |
|---|---|---|
| Supabase | DB + Auth | 99.9%（Proプラン） |
| Resend | メール送信 | サービス約款に準拠 |
