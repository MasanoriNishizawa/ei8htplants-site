# RD-01 — ビジネス要件 (Business Requirements)

## 1. 開発背景

植物セレクトショップ「ei8ht plants」は、異なるコンセプトを持つ3つのブランドラインを運営しているが、各ブランドの情報発信・イベント告知・予約受付が分散しており、顧客への一元的な情報提供が困難な状況だった。

また、イベント情報やお問い合わせの管理がメール・SNSのみに依存しており、担当者が変わった場合の引き継ぎや、問い合わせ履歴の管理が課題となっていた。

## 2. 開発目的

| 目的 | 詳細 |
|---|---|
| ブランド情報の一元化 | 3ブランドの情報を単一サイトで提供し、ユーザーが迷わず各ブランドへ到達できる導線を構築する |
| イベント情報の自動更新 | 管理者がAdminページからイベントを追加・更新することで、開発者不在でもサイト情報を最新に保てる |
| 予約・問い合わせのデジタル管理 | ワークショップ予約とお問い合わせをDBに蓄積し、管理画面で一元管理できるようにする |
| ブランドイメージの向上 | 高品質なビジュアルと洗練されたUIで、ブランドの世界観を表現する |

## 3. ステークホルダー

| 役割 | 詳細 |
|---|---|
| サイトオーナー | ei8ht plants 運営者。コンテンツ更新・予約管理を行う管理者でもある |
| エンドユーザー | 植物愛好家・潜在顧客。イベント情報の閲覧・予約・お問い合わせを行う |
| 開発者 | サイト構築・機能追加・保守を担当 |

## 4. ブランド構成

| ブランド | パス | コンセプト |
|---|---|---|
| ei8ht plants | `/ei8htplants` | アガベ専門ライン |
| Habitat Oides | `/habitatoides` | ハビタットスタイルライン（ワークショップあり） |
| HUE by ei8ht plants | `/hue` | カラープランツセレクション |

## 5. 投資対効果 (ROI)

| 効果 | 定性評価 |
|---|---|
| 問い合わせ対応工数の削減 | 管理画面での既読管理・履歴閲覧により、メール追跡が不要になる |
| 予約管理工数の削減 | WS予約がDB管理になり、Excelや紙での管理が不要になる |
| イベント告知の即時性向上 | 開発者への依頼なく、管理者が即時に情報を更新できる |
| ブランド認知向上 | 統一されたWebプレゼンスにより、SNSからの流入が来店・購入につながりやすくなる |

## 6. スコープ外

| 項目 | 理由 |
|---|---|
| オンラインショップ（カート・決済） | Square（外部サービス）へリンクする形で対応。自社構築はスコープ外 |
| 会員登録・マイページ | 顧客向けアカウント機能は現フェーズのスコープ外 |
| メール自動返信（予約確認メール） | 現フェーズでは予約はDB保存のみ。管理者がメール返信 |
| 多言語対応 | 日本語のみ対応 |
