# RD-02 — 業務要件 (Operational Requirements)

## 1. 現行業務フロー (As-Is)

### イベント告知

```
担当者
  │  イベント情報を作成
  ├─► Instagram / SNS 投稿（個別）
  └─► 開発者に依頼 → コードを修正 → デプロイ
         （時間がかかる・担当者不在時は更新不可）
```

### ワークショップ予約

```
顧客
  │  Instagram DMまたはメールで問い合わせ
  ▼
担当者
  │  手動で受付・日程調整
  │  Excelまたはメモで管理
  └─► 予約確認メールを手動送信
```

### お問い合わせ

```
顧客
  │  メールで問い合わせ
  ▼
担当者メールボックス
  │  受信・返信を手動で管理
  └─► 問い合わせ履歴は検索・共有が困難
```

## 2. 今の業務フロー (To-Be。2026-10-22 時点の運用)

管理画面の操作の詳しい手順は [ユーザーマニュアル](../05_OP/03_ユーザーマニュアル.md) を参照。

### イベント告知

```
担当者
  │  管理画面の [イベント] → [+ 新規追加]
  ├─► イベント名・日付・会場・写真（ファイルを選ぶ）などを入れて [保存する]
  ├─► 必要なら [サイト] でイベント専用ページ（/events/スラッグ）の中身を入れる
  └─► すぐに公開（デプロイ不要）
         ↓
       お客様が /events・イベント専用ページで見る（SNS で共有するとタイトル・写真が出る）
```

### ワークショップ予約

```
お客様
  │  /events などの予約ボタン → /reserve
  │  時間枠を選び、名前・メール・人数・持込などを入れて送信
  │  → DB に「受付済」（status='pending'）で保存
  │  → お客様に確認メール（キャンセル用のリンク付き）、Habitat Oides の管理者に通知メールを自動で送る
  │  （キャンセルするときは、メールのリンクから自分で取り消す → 自動で「キャンセル」になる）
  ▼
担当者
  │  管理画面の [WS予約] で確認（今後・過去の切り替え、イベントの絞り込み）
  │  「メール未送信」の印がある予約は、電話などで連絡
  │  キャンセルの連絡を受けたら、ステータスを「キャンセル」に変える
  │  （お客様にキャンセルのお知らせメールが自動で送られる）
  ├─► 当日、予約なしで来た人は [当日参加を追加] で記録
  └─► [PDF で印刷] で当日の受付表を印刷
```

### お問い合わせ

```
お客様
  │  /contact → フォームに入れて送信
  │  DB に保存 + 管理者に通知メール（Resend）
  ▼
担当者
  ├─► 通知メールで気づく
  ├─► 管理画面の [お問い合わせ] で一覧を見る（未読 N の表示）
  │  行を押して本文を読む
  └─► [返信] で件名・本文を入れて [送信する]
         → 送信専用のアドレスからお客様にメールが届き、自動で既読になる
```

### オンラインショップ

```
お客様
  │  /shop で商品を選ぶ → /checkout で届け先を入れ、カードで支払う（Square）
  │  → 注文を DB に「支払済」で保存し、在庫を減らす
  │  → お客様に注文の確認メール、管理者に通知メールを自動で送る
  ▼
担当者
  │  管理画面の [注文管理] で確認（ダッシュボードの「未発送の注文」にも数が出る）
  │  商品を発送したら、ステータスを「発送済」にして配送会社・追跡番号を入れる
  └─► お客様に発送のお知らせメールが自動で届く
```

### イベントの出店準備と収支

```
担当者
  ├─► 出店が決まったら [管理情報] に搬入・宿泊・出店料・支払い期限・出店要項を入れる
  │     → ダッシュボードの「出店料の支払い」「今後の搬入予定」にまとめて出る
  ├─► 出店料を払ったら、管理情報の「支払い済み」にチェック
  ├─► 開催後に [収支] で売上・支出・WS 参加人数を入れる
  │     → [全体の収支]・[支払い集計]・[ワークショップ集計] に反映
  └─► 分析ダッシュボード（[分析 ↗]）でグラフ・今期の売上の見込みを見る
```

## 3. アクター（利用権限）

| アクター | 認証 | アクセス可能範囲 |
|---|---|---|
| 一般ユーザー | 不要 | 全公開ページ（閲覧・フォーム送信・予約・予約のキャンセル・ショップでの購入・AI チャット） |
| 管理者 | Supabase Auth（メール+パスワード） | 管理画面の全画面・分析ダッシュボード（分析ダッシュボードは、見てよい人に登録されたアカウントだけ） |

**権限の分離方針**:
- 公開ページのデータ取得は Supabase の公開用のキー（anon。RLS で読み取りだけ許可）またはバックエンドの公開 API
- 管理用の API は、バックエンドでログインの確認（`require_auth`。Supabase のログインの証明書を確かめる）をしてから、管理用のキー（service_role。RLS を通らない）で読み書きする
- フロントエンドに service_role キーは出さない

## 4. 業務上の制約条件

| 制約 | 詳細 |
|---|---|
| 管理者は非エンジニア | 管理画面は直感的な操作で使えること |
| 画像管理 | 管理画面でファイルを選んでアップロードし、Supabase Storage（写真は `images`、動画は `videos`）に保存する。写真は 10MB、動画は 500MB まで |
| 自動メール | 予約の確認・キャンセルのお知らせ・管理者への通知、注文の確認・発送のお知らせは自動で送る。お問い合わせへの返信は管理画面から送る |
| 単一管理者 | 同時に複数の管理者が操作することは想定しない |
