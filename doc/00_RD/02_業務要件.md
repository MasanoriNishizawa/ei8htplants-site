# RD-02 — 業務要件 (Operational Requirements)

## 1. 現行業務フロー (As-Is)

### イベント告知

```
担当者
  │  イベント情報を作成
  ├─► Instagram / SNS 投稿（個別）
  └─► 開発者に依頼 → コードを修正 → デプロイ
         （時間がかかる・担当者不在時は更新不可）
```

### ワークショップ予約

```
顧客
  │  Instagram DMまたはメールで問い合わせ
  ▼
担当者
  │  手動で受付・日程調整
  │  Excelまたはメモで管理
  └─► 予約確認メールを手動送信
```

### お問い合わせ

```
顧客
  │  メールで問い合わせ
  ▼
担当者メールボックス
  │  受信・返信を手動で管理
  └─► 問い合わせ履歴は検索・共有が困難
```

## 2. 改善後業務フロー (To-Be)

### イベント告知

```
担当者
  │  ブラウザで /admin/events を開く
  ├─► イベント情報・画像URLを入力 → [追加]ボタン
  └─► 即時公開（デプロイ不要）
         ↓
       ユーザーが /events で確認可能
```

### ワークショップ予約

```
ユーザー
  │  /events → 予約ボタン → /reserve
  │  フォーム入力（名前・メール・参加人数）
  │  送信 → DBに status='pending' で保存
  ▼
担当者
  │  /admin/reservations を確認
  │  ステータスを 'confirmed' に変更
  └─► メールで予約確認を返信（現フェーズは手動）
```

### お問い合わせ

```
ユーザー
  │  /contact → フォーム入力 → 送信
  │  DBに保存 + Resend経由でメール通知
  ▼
担当者
  ├─► 通知メール受信 → 即時把握
  ├─► /admin/contacts で一覧確認（未読バッジ）
  │  アコーディオン展開で本文確認
  │  既読マーク → 対応済みを管理
  └─► mailto: リンクから返信
```

## 3. アクター（利用権限）

| アクター | 認証 | アクセス可能範囲 |
|---|---|---|
| 一般ユーザー | 不要 | 全公開ページ（閲覧・フォーム送信） |
| 管理者 | Supabase Auth（メール+パスワード） | Admin全画面（コンテンツ管理・予約管理） |

**権限の分離方針**:
- 公開ページのデータ取得はSupabase anon キー（RLS: SELECT のみ）
- Admin操作はバックエンドの service_role キー経由（RLS バイパス）
- フロントエンドに service_role キーは公開しない

---

## 4. 業務上の制約条件

| 制約 | 詳細 |
|---|---|
| 管理者は非エンジニア | Adminページは直感的な操作で使えること |
| 画像管理 | 画像ファイルのアップロード機能は持たない。外部URL（Google Drive等）を入力する形式 |
| 予約確認メール | 現フェーズでは自動送信なし。管理者が手動で対応 |
| 単一管理者 | 同時に複数の管理者が操作することは想定しない |
