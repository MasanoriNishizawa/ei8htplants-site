# システム構成

## アーキテクチャ概要

```
ブラウザ
  └─ React SPA (Vite)
        └─ /api/* → FastAPI (Python)
              ├─ Supabase (PostgreSQL)  ← データ読み書き
              └─ Resend API             ← メール送信
```

- **開発時**: Vite dev server (port 5173) + uvicorn (port 8000) の2プロセス構成。Viteのproxyで `/api` をバックエンドに転送。
- **本番**: Viteビルド成果物をFastAPIからStaticFilesで配信。単一プロセス。

## 環境変数

### `frontend/.env`
| 変数名 | 説明 |
|---|---|
| `VITE_SUPABASE_URL` | Supabase プロジェクトURL |
| `VITE_SUPABASE_ANON_KEY` | Supabase 匿名キー（公開可） |

### `backend/.env`
| 変数名 | 説明 |
|---|---|
| `SUPABASE_URL` | Supabase プロジェクトURL |
| `SUPABASE_ANON_KEY` | 匿名キー（公開読み取り用） |
| `SUPABASE_SERVICE_ROLE_KEY` | サービスロールキー（**秘匿必須**） |
| `RESEND_API_KEY` | Resend APIキー（**秘匿必須**） |
| `CONTACT_TO_EMAIL` | お問い合わせ受信メールアドレス |
| `CONTACT_FROM_EMAIL` | お問い合わせ送信元メールアドレス |

> **注意**: `.env` ファイルは `.gitignore` に含まれており、リポジトリにコミットしてはならない。

## Supabase 認証フロー（Admin）

1. `/admin` アクセス → `AdminLayout` が `supabase.auth.getSession()` でセッション確認
2. 未認証 → ログインフォーム表示
3. ログイン → `supabase.auth.signInWithPassword()` → セッション確立
4. 認証済み → Admin UIを表示し、各管理APIにアクセス

バックエンドAPIのAdmin操作は `SUPABASE_SERVICE_ROLE_KEY` を使う `admin_supabase` クライアントで実行（RLSをバイパス）。
