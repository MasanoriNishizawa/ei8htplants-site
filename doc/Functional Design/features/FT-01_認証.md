# FT-01 — 認証

## 概要

Supabase Auth を用いたAdmin画面のログイン・セッション管理・ログアウト機能。  
`AdminLayout.tsx` に集約されており、全管理ページで共通して適用される。

## 実装ファイル

`frontend/src/pages/admin/AdminLayout.tsx`

## 処理フロー

```
/admin にアクセス
    │
    ▼
AdminLayout マウント
    │
    ├─ supabase.auth.getSession() ────→ セッションあり ──→ Admin UI を表示（Outlet）
    │
    └─ セッションなし ──→ ログインフォームを表示
                              │
                         フォーム送信
                              │
                    supabase.auth.signInWithPassword()
                              │
                    ├─ 成功 ──→ setAuthed(true) → Admin UI を表示
                    └─ 失敗 ──→ エラーメッセージ表示
```

## 状態

| state | 型 | 初期値 | 説明 |
|---|---|---|---|
| `checking` | boolean | true | セッション確認中フラグ（確認中はnullを返す） |
| `authed` | boolean | false | 認証済みフラグ |
| `email` | string | '' | ログインフォームのメール入力 |
| `password` | string | '' | ログインフォームのパスワード入力 |
| `error` | string | '' | ログイン失敗時のエラーメッセージ |

## Supabase クライアント

```ts
const supabase = createClient(VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY)
```

- Anon キーを使用（Auth のみ）
- `checking` 中は `null` を返してフラッシュを防止

## ログアウト

`supabase.auth.signOut()` → `setAuthed(false)` → ログインフォームへ戻る

## バックエンドとの関係

Admin操作（DB書き込み）はバックエンド経由で行い、バックエンド側が `SUPABASE_SERVICE_ROLE_KEY` を持つ `admin_supabase` クライアントで処理する。  
フロントエンドのSupabaseクライアントは **Auth専用**（RLSを迂回しない）。
