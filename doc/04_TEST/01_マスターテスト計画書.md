# TEST-01 — マスターテスト計画書 (Master Test Plan)

## 1. テストの全体方針

本プロジェクトは小規模1人開発のため、正式なテストフェーズを分離せず、実装と並行してテストを実施する。各フェーズのテストの目的と合否基準を本書に定義する。

ロジック関数・API エンドポイントは自動テストで継続的に検証する。変更のたびに、変えたものに関連するテストを流し、プッシュの前に「最後の変更のあとに流した関連するテストが成功していること」を確認する（全部を流すのは、全体に関わる変更のときだけ。2026-10-25 変更）。UI の視覚的確認は Playwright によるブラウザ確認で補完する。

### テストの実行（`scripts/run_tests.py`）

テストは `scripts/run_tests.py` で実行し、結果を [08_テスト実行ログ](08_テスト実行ログ.md) に追加する。1つでも失敗があれば終了コード 1（コミットしてはいけない合図）。

**流すのは、変えたものに関連するテストだけ**（2026-10-25 から。すべては流さない）。どれを流すかは次の表で選ぶ（`CLAUDE.md` の「どのテストを流すか」と同じ）。迷ったら広めに選び、何を流したかは報告に書く。

| 変えたもの | 流すテスト |
|---|---|
| 1つの画面・機能の中だけ（例: 販売価格計算の計算式） | その機能のテスト＋その画面の E2E ＋型チェック・ビルド |
| 共通の部品（`api.ts`・MSW のモック・共通コンポーネントなど） | その部品を使う画面のテストまで広げる |
| バックエンドの API | その API の pytest ＋それを呼ぶ画面のテスト |
| 認証・ルーティング・ビルドの設定など、全体に関わるもの | 全部 |

```bash
# 関連するテストだけ（--vitest・--e2e は frontend/ から、--pytest は backend/ から見たパス）
python scripts/run_tests.py --note "何を変えたか" \
  --vitest src/lib/__tests__/priceCalc.test.ts src/pages/admin/__tests__/PriceCalc.test.tsx \
  --e2e e2e/admin-unsaved-pages.spec.ts \
  --pytest tests/test_price_calc_entries.py

# 全体に関わる変更のときだけ、何も絞らずに全部
python scripts/run_tests.py --note "何を変えたか"
```

- `--vitest`・`--e2e`・`--pytest`・`--analytics` のどれか1つでも指定すると「絞った実行」になる。指定しなかったテストは流さず、ログには「省略（関連なし）」と残る。ログの見出しは「関連する部分だけ実行」になり、流したファイルが残る
- `--no-e2e` だけを指定した場合は、Vitest・バックエンド pytest を全件実行し、分析ダッシュボード pytest も `.venv` がある環境では全件実行する（`.venv` がなければスキップ）。Playwright は「省略（--no-e2e）」として記録する。E2E以外を全件実行しても部分実行扱いとし、「全部成功」と誤認させない
- `--no-e2e` とテスト絞り込みを併用した場合は、指定したテスト枠だけを実行し、Playwrightを含む未実行枠と理由を記録する
- `--no-e2e` と `--e2e` は同時に指定できない。矛盾する指定はテストを開始する前に引数エラーとして終了する
- 型チェック（1）と本番ビルド（2）は、絞った実行でも必ず流す（全体の食い違いを拾うため）
- 何も指定しなければ、下の7つをすべて流す

全部を流すときは、次の7つを順に実行する。

| 順 | テスト | 実行するコマンド |
|---|---|---|
| 1 | TypeScript チェック（tsc） | `cd frontend && npx tsc --noEmit -p tsconfig.app.json`（2026-10-21 に `-p tsconfig.app.json` を追加。それまでは何も検査せずに成功していた） |
| 2 | 本番ビルド（tsc -b ＋ vite build。2026-10-21 追加） | `cd frontend && npx tsc -b` → `npx vite build --outDir <一時フォルダ> --emptyOutDir` |
| 3 | テストランナー回帰テスト（unittest） | `python -m unittest discover -s scripts/tests` |
| 4 | フロントのロジック（Vitest） | `cd frontend && npx vitest run` |
| 5 | 画面テスト（Playwright。API は MSW モック） | `cd frontend && npx playwright test` |
| 6 | バックエンド（pytest） | `cd backend && python -m pytest` |
| 7 | 分析ダッシュボード（pytest。2026-10-17 追加） | `cd analytics && .venv/bin/python -m pytest tests`（`analytics/.venv` が無い環境ではスキップと記録する） |

**2 の本番ビルドの確認（2026-10-21 追加）**

- `npm run build` と同じ手順（`tsc -b` の型チェック → `vite build`）が通るかを確かめる。`tsc -b` はテストファイルも含めて型を検査するので、1 では見ない範囲の型エラーも見つかる
- 出力は一時フォルダにして、作業後に消す。コミットする `frontend/dist` は書き換えない
- 出力した JavaScript に、開発用のログイン省略のダミートークン（`dev-skip-admin-auth`）の文字が残っていないことも確かめる。残っていたら失敗にする
- `tsc -b` が失敗したら型エラー（最大 10 件）、`vite build` が失敗したら「vite build が失敗しました」をログに出す

## 5. MSW (Mock Service Worker) について

フロントエンド単独での動作確認を可能にするため MSW を導入している。

| ファイル | 用途 |
|---|---|
| `frontend/src/mocks/data.ts` | モックデータ定義（イベント・ギャラリー・商品など） |
| `frontend/src/mocks/handlers.ts` | API ハンドラー（`http.get('/api/events', ...)` 等） |
| `frontend/src/mocks/browser.ts` | ブラウザ用ワーカー（`setupWorker`）|
| `frontend/src/mocks/node.ts` | Vitest 用サーバー（`setupServer`）|
| `frontend/public/mockServiceWorker.js` | ブラウザに登録されるサービスワーカースクリプト |

`main.tsx` は `DEV && VITE_MSW=true` のときのみワーカーを起動する。本番ビルドでは MSW は一切動作しない。

**モックの決まり（2026-10-23 追記）**

- ハンドラーは、画面の操作で呼ぶ API（イベント・ギャラリー・取扱店・商品・記事・コラボ・メディア・鉢作家・価格計算・チャットQ&A・チャット履歴・予約の一覧と状態の変更・当日参加・キャンセル・注文・お問い合わせの返信・アップロード・AI チャットなど）を、`data.ts` の固定データかメモリ上のデータで返す。保存した内容は、そのページを開いている間だけ残る
- 収支が未登録のイベントの `GET /api/events/:id/finances` は、本番（`backend/app/routes/events.py`）と同じ既定値（金額はすべて 0、ガソリン単価 170 円/L、手伝い・WS 支払いはなし）に `event_id` を付けて返す
- 上のどれにも当たらない `/api/*` の通信は、最後の `http.all('/api/*')` で止めて `501`（`MSW のモックに無い API です: メソッド パス`）を返す。開発用のモック（`npm run mock`）で、Vite の中継先（本物のバックエンド、ポート 8000）へ流れないようにするため。モックに足りない API があれば、その上にハンドラーを足す
- ブラウザ用（`main.tsx`）は、`/api/` 以外の通信（画像など）をそのまま通す（`onUnhandledRequest: 'bypass'`）。Vitest 用（`src/test/setup.ts`）は、ハンドラーの無い通信を警告で知らせる（`onUnhandledRequest: 'warn'`）

## 8. 合否基準（総合）

qa エージェントが以下を順に実行し、全て PASS であることを確認する:

1. `npx tsc --noEmit -p tsconfig.app.json` がエラーなし（型チェック）、本番ビルド（`tsc -b` ＋ `vite build`）が通る（2026-10-21 追加）

4. `npm run test:e2e`（Playwright）が全ケース PASS（ST）

6. 秘匿情報（`.env`, `secret_key.json`）がリポジトリに含まれていないこと
7. 管理者認証が正常に機能すること
