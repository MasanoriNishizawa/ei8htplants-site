# TEST-01 — マスターテスト計画書 (Master Test Plan)

## 1. テストの全体方針

本プロジェクトは小規模1人開発のため、正式なテストフェーズを分離せず、実装と並行してテストを実施する。各フェーズのテストの目的と合否基準を本書に定義する。

ロジック関数・API エンドポイントは自動テストで継続的に検証し、プッシュ前に必ず全テストが通ることを確認する。UI の視覚的確認は Playwright によるブラウザ確認で補完する。

---

### 全テストのまとめて実行（`scripts/run_tests.py`）

`python scripts/run_tests.py --note "何を変えたか"` で、次の6つを順に実行し、結果を [08_テスト実行ログ](08_テスト実行ログ.md) に追加する。1つでも失敗があれば終了コード 1（コミットしてはいけない合図）。

| 順 | テスト | 実行するコマンド |
|---|---|---|
| 1 | TypeScript チェック（tsc） | `cd frontend && npx tsc --noEmit -p tsconfig.app.json`（2026-10-21 に `-p tsconfig.app.json` を追加。それまでは何も検査せずに成功していた） |
| 2 | 本番ビルド（tsc -b ＋ vite build。2026-10-21 追加） | `cd frontend && npx tsc -b` → `npx vite build --outDir <一時フォルダ> --emptyOutDir` |
| 3 | フロントのロジック（Vitest） | `cd frontend && npx vitest run` |
| 4 | 画面テスト（Playwright。API は MSW モック） | `cd frontend && npx playwright test` |
| 5 | バックエンド（pytest） | `cd backend && python -m pytest` |
| 6 | 分析ダッシュボード（pytest。2026-10-17 追加） | `cd analytics && .venv/bin/python -m pytest tests`（`analytics/.venv` が無い環境ではスキップと記録する） |

**2 の本番ビルドの確認（2026-10-21 追加）**

- `npm run build` と同じ手順（`tsc -b` の型チェック → `vite build`）が通るかを確かめる。`tsc -b` はテストファイルも含めて型を検査するので、1 では見ない範囲の型エラーも見つかる
- 出力は一時フォルダにして、作業後に消す。コミットする `frontend/dist` は書き換えない
- 出力した JavaScript に、開発用のログイン省略のダミートークン（`dev-skip-admin-auth`）の文字が残っていないことも確かめる。残っていたら失敗にする
- `tsc -b` が失敗したら型エラー（最大 10 件）、`vite build` が失敗したら「vite build が失敗しました」をログに出す

| 環境 | 詳細 |

| 本番テスト | 本番 Supabase（UAT 時のみ）。書き込みを伴うテスト後は手動でデータ削除 |

## 5. MSW (Mock Service Worker) について

フロントエンド単独での動作確認を可能にするため MSW を導入している。

| ファイル | 用途 |
|---|---|
| `frontend/src/mocks/data.ts` | モックデータ定義（イベント・ギャラリー・商品など） |
| `frontend/src/mocks/handlers.ts` | API ハンドラー（`http.get('/api/events', ...)` 等） |
| `frontend/src/mocks/browser.ts` | ブラウザ用ワーカー（`setupWorker`）|
| `frontend/src/mocks/node.ts` | Vitest 用サーバー（`setupServer`）|
| `frontend/public/mockServiceWorker.js` | ブラウザに登録されるサービスワーカースクリプト |

`main.tsx` は `DEV && VITE_MSW=true` のときのみワーカーを起動する。本番ビルドでは MSW は一切動作しない。

## 8. 合否基準（総合）

qa エージェントが以下を順に実行し、全て PASS であることを確認する:

1. `npx tsc --noEmit -p tsconfig.app.json` がエラーなし（型チェック）、本番ビルド（`tsc -b` ＋ `vite build`）が通る（2026-10-21 追加）
2. `npm test`（Vitest）が全ケース PASS（UT / IT — FE）
3. `python -m pytest` が全ケース PASS（UT / IT — BE）
   - 分析ダッシュボード（`analytics/`）の pytest も全ケース PASS（2026-10-17 追加）
4. `npm run test:e2e`（Playwright）が全ケース PASS（ST）
5. UAT で致命的な操作不能事象がないこと
6. 秘匿情報（`.env`, `secret_key.json`）がリポジトリに含まれていないこと
7. 管理者認証が正常に機能すること
