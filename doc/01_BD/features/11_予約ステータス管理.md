# FT-11 — 予約ステータス管理

## 概要

ワークショップ予約一覧の表示と、ステータスのインライン変更機能。ステータスはカラーバッジで視覚化し、セレクトボックスからワンクリックで更新できる。キャンセルトークンは予約作成時（`POST /api/reserve`）に発行され、受付メールにキャンセルリンクが含まれる。管理者がステータスを `cancelled` に変更すると、予約者へキャンセル完了メールが送信される。

## ステータス定義

| 値 | 表示ラベル | バッジ背景 | バッジ文字色 | 備考 |
|---|---|---|---|---|
| `pending` | 受付済 | `#d4edda` | `#155724` | アクティブな予約の唯一のステータス |
| `confirmed` | 受付済 | `#d4edda` | `#155724` | 後方互換エイリアス（見た目は `pending` と同一） |
| `cancelled` | キャンセル | `#f8d7da` | `#721c24` | ユーザーまたは管理者によるキャンセル後 |

`confirmed` は過去データとの後方互換のために残されているが、新規予約には付与されない。実質的なアクティブステータスは `pending` のみ。

## 更新フロー

```
セレクトボックス変更（onChange）
    │
    ▼
setUpdating(id) → セレクトを disabled に
    │
    ▼
api.reserve.updateStatus(id, status)    （PATCH /api/reserves/{id} { status }）
    │
    ├─ 成功 ──→ setRows: サーバー応答でローカル state を更新
    │
    └─ 失敗 ──→ 画面の状態は変えず、上に赤い枠でエラーを出す（2026-10-22 変更）
                 ・409（満席の回をキャンセルから受付済に戻そうとした）
                   →「満席のため受付済に戻せません。元の状態のままです（理由）」
                 ・それ以外 →「ステータスの変更に失敗しました。元の状態のままです（理由）」
        ※ それまでは失敗しても画面の上だけ状態を変えていた（楽観的更新）。
          実際には変わっていないのに変わったように見えたため、やめた
```

## ステータス変更時のサーバー側処理（副作用）

`PATCH /api/reserves/{id}` でステータス更新:

1. DBの `status` カラムを更新
2. `session_id` がある場合 → `_sync_reserved_count(session_id)` でデノーマライズ値を更新
3. `status = 'cancelled'` の場合 → `_send_cancel_confirmation()` でキャンセル完了メールを送信

キャンセルトークンはステータス変更では生成しない（予約作成時に生成済み）。

## キャンセル完了メール仕様（ステータスを cancelled に変更した際）

- **from**: `Habitat Oides <{HABITAT_SENDER}>`
- **subject**: `[Habitat Oides] ワークショップ予約をキャンセルしました: {イベント名}`
- **本文**: {name} 様へのキャンセル完了通知 + イベント名・開催日・会場

| カラム | 説明 |
|---|---|

## EventReservations 固有機能

- 開き方: イベント一覧（[PG-A02](../pages/admin/02_Events.md)）の「予約管理（印刷・CSV）」ボタン（ワークショップありのイベントだけ。2026-10-22 追加。それまでは画面へのボタンが無く、アドレスを直接入れて開いていた）
- 戻り先: 左上のリンクは、開いた元の画面へ戻る。イベント一覧から開いたときは「← イベント管理」、ほかの画面から戻り先を渡されて開いたときは「← 戻る」。戻り先が分からないとき（アドレスを直接開いたときなど）はイベント一覧へ戻る（2026-10-22 変更）
- 上の「全N件 / N名」は、キャンセル以外の件数と参加人数の合計
- セッション別フィルタボタン（「全て」＋各セッション時間）
- 予約ページリンクのコピー: お客様向けの予約ページのアドレスをコピーし、2秒間「コピーしました」と出す。コピーできなかったとき（ブラウザが許可しないときなど）は「リンクをコピーできませんでした。次の URL を選択してコピーしてください: （アドレス）」と赤い枠で出し、アドレスの部分は1回押すと全体が選ばれる（2026-10-22 追加。それまではコピーに失敗しても何も出なかった）
- 印刷プレビュー（新規ウィンドウで `window.print()` 自動実行）。表のいちばん下の「合計 N 件 / N 名」は、印刷した予約をすべて数える（キャンセルも含む）。予約者が入力した名前・備考などは、印刷の画面でスクリプトとして動かないよう無害化してから入れる（`lib/escapeHtml.ts` の `escapeHtml`）
- CSV エクスポート（BOM付きUTF-8、Excelで文字化けしない）。ファイル名は `reservations_イベント名_今日の日付.csv`。`=`・`+`・`-`・`@` などで始まる値は、Excel で数式として動かないよう先頭に `'` を付ける（`lib/escapeHtml.ts` の `csvCell`。2026-10-22 変更）。保存は `pages/admin/saveBlob.ts` の `saveBlob` で行う
- 失敗の表示（2026-10-22 追加）: 予約一覧を読み込めなかったときは「予約一覧の読み込みに失敗しました（理由）」、時間枠だけ読み込めなかったときは「時間枠を読み込めませんでした。時間の表示や絞り込みが不完全な場合があります」、当日参加の追加に失敗したときは追加の画面の中に「当日参加の追加に失敗しました（理由）」を出す。状態の変更の失敗は上の「更新フロー」と同じ

## Reservations 固有機能（2026-10-22 追記）

詳しくは [PG-A05 WS予約管理](../pages/admin/05_Reservations.md)。

- 「今後の開催」「過去の開催」のタブ。ワークショップのあるイベントの予約だけを出す
- 今日開催中のワークショップがあれば、開いたときにそのイベントで自動で絞り込む
- 「当日参加を追加」（今後の開催のタブだけ）: 予約なしで来た人を登録する。名前「当日参加」・状態「受付済」で登録し、メールは送らない
- 確認メールが送れなかった予約には、名前の横に「メール未送信」と出る

- CSV のファイル名の日付は、日本時間の今日の日付にした（`todayJst()`。2026-10-23。それまでは UTC の日付だったため、日本の 0 時〜9 時に出すと前日の日付になっていた）
