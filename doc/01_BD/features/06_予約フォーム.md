# FT-06 — 予約フォーム

## 概要

ワークショップ予約フォームの送信機能。URLクエリパラメータからイベントIDを取得し、セッション選択・参加人数入力を経てバックエンド経由でDBに予約を登録する。

| ページID | ページ名 | 用途 |
|---|---|---|
| [PG-12](../pages/public/12_Reserve.md) | Reserve | 予約フォーム本体 |

## 遷移元

[FT-03 イベント表示](03_イベント表示.md) の予約ボタン（`/official/reserve?event_id={id}`）

## 実装ファイル

| パラメータ | 取得方法 | 用途 |
|---|---|---|
| `event_id` | `useSearchParams()` | 予約対象イベントIDとしてAPIに送信 |

## フォーム項目

| フィールド | 型 | 必須 | 条件 | 説明 |
|---|---|---|---|---|
| 開催日（ラジオ） | string | 条件付き | 複数日イベントのみ表示 | `preferred_date` にセット。2026-11-13 から、選べるのはワークショップの実施日のうち今日（日本時間）以降の日だけ（下の「ワークショップの実施日と予約日（2026-11-13 追加）」） |
| セッション（ラジオ） | string | 条件付き | `event.has_workshop = true` のみ表示 | `session_id` にセット。選んだ日に枠が1つも無いときは選ばずに送れる（2026-11-13 変更） |
| 参加人数（セレクト） | number | ○ | WS時はセッション選択後に有効化 | 1〜残席数の選択肢 |
| お名前 | text | ○ | 常時表示 | `required`。100 文字まで（2026-10-23 追加） |
| メールアドレス | email | ○ | 常時表示 | `type="email"` + `required`。画面では文字数の上限なし |
| 電話番号 | tel | — | 常時表示 | 30 文字まで（2026-10-23 追加） |
| 植物持ち込み | checkbox | — | 常時表示 | `bring_plant` |
| 鉢持ち込み | checkbox | — | 常時表示 | `bring_pot` |
| 備考 | textarea | — | 常時表示 | 任意。2,000 文字まで（2026-10-23 追加） |
| 言語（hidden） | string | — | 自動セット | `useLang()` から取得した `'ja'` または `'en'`。`lang` フィールドとして送信 |

## 状態管理

| state | 型 | 説明 |
|---|---|---|
| `form` | `{ name, email, participants, note, session_id, bring_plant, bring_pot, preferred_date, lang }` | フォーム入力値（`lang` は `useLang()` から初期値セット） |
| `status` | `'idle' \| 'loading' \| 'done' \| 'error' \| 'full'` | 送信状態 |
| `event` | `Event \| null` | イベント情報 |
| `sessions` | `WsSession[]` | WSセッション一覧 |

## 派生値（フォーム制御）

```typescript
const expectsSessions = !!event?.has_workshop
// sessions.length ではなく event.has_workshop を使う。
// sessions 取得完了前でも true になるため、ロード中にセクションが消えるフラッシュを防ぐ。
const participantsDisabled = expectsSessions && !form.session_id
const sessionsDisabled = isMultiDay && !form.preferred_date
const canSubmit = !needsDate && !needsSession
```

2026-11-13 から、上の式は次のように変わった（`frontend/src/pages/Reserve.tsx`）。

```typescript
// 予約日の選択肢: ワークショップの実施日のうち、今日（日本時間）以降の日
const dates = event ? reservableDates(event) : []
// 選んだ日の枠が 0 件と分かった（時間を指定せずに予約できる）
const noSessionsForDate = !!event?.has_workshop && sessionsStatus === 'ok' && sessions.length === 0
const expectsSessions = !!event?.has_workshop && !noSessionsForDate
// 枠の読み込み中・失敗のときも、まだ選べないので送らない
const needsSession = expectsSessions && (!form.session_id || sessionsStatus !== 'ok')
```

- それまでは、ワークショップのあるイベントでその日の枠が0件だと、時間枠を選べないまま「予約する」が押せず、予約を送れなかった（不具合）。今は「この日は時間の指定はありません。参加人数とお客様情報を入力してご予約ください。」と出し、「予約時間」の必須の印（*）を消して、時間を選ばずに送れる

## 送信フロー

```
ページ表示
    │
    ▼
useEffect #1: api.events.get(event_id)  ← [eventId] 依存
    │
    ├─ 予約できる日が1日だけ → preferred_date にその日を自動セット（2026-11-13 変更）
    ├─ 複数日イベント → 開催日ラジオを表示（preferred_date が空の間は次段 disabled）
    │
    ▼ preferred_date が確定すると useEffect #2 が起動
useEffect #2: api.events.getSessions(event_id, preferred_date)  ← [event, preferred_date] 依存
    │  （日付を渡すことでその日の予約数を反映した reserved_count を取得）
    ▼
    セッションラジオを表示（残席数を併記）
    ▼
    セッション選択後 → 参加人数セレクトを有効化（1〜残席数）
    │
    ▼（フォーム入力完了後）
onSubmit
    │
    ▼
api.reserve.create({ event_id, name, email, participants, note,
    │                session_id, bring_plant, bring_pot, preferred_date,
    │                preferred_time, lang })  ← preferred_time（選んだ枠の時間の表示）は 2026-11-13 から送る
    │                （POST /api/reserve）
    ├─ 200 ──→ setStatus('done') → 「ご予約を受け付けました」表示
    ├─ 409 ──→ setStatus('full') → 「このセッションは満席になりました」表示
    └─ その他 ──→ setStatus('error') → 下の「送信に失敗したときの文言」
```

- 文字数の上限は、サーバーの入力チェック（`backend/app/routes/reserve.py` の上限）と同じ値（`frontend/src/lib/constants.ts` の `INPUT_MAX_LENGTH`）。入力欄の時点でそれ以上打てないようにする

### 送信に失敗したときの文言（2026-10-23 追加）

| サーバーの答え | 日本語表示で出す文言 |
|---|---|
| 409 | 満席の画面（「このセッションは満席になりました」） |
| 400 で、説明が「このイベントの予約受付は終了しています」「この日の予約受付は終了しています」（受付終了） | サーバーの説明をそのまま |
| 400 で、説明が「予約日がイベントの開催期間外です」「ワークショップの時間枠が正しくありません」（日付・時間が合わない） | サーバーの説明をそのまま |
| 400 で、説明が「この日はワークショップを実施していません」「この時間枠は選んだ日には使えません」「時間枠を選んでください」「予約日を選んでください」（日付・時間が合わない。2026-11-13 追加） | サーバーの説明をそのまま |
| 400 で、説明が「このワークショップは予約不要です。当日会場へお越しください。」（予約不要。2026-11-13 追加） | サーバーの説明をそのまま。英語表示では「No reservation is needed for this workshop. Please come directly to the venue on the day.」 |
| 400（上のどれでもない） | 選んだ日付または時間がこのイベントの予約枠と合いません。日付と時間を選び直してください。 |
| 422（入力の形が違う・長すぎる） | 入力内容に誤りがあります。お名前・メールアドレス・電話番号・人数（1〜10名）・備考（2000文字まで）をご確認ください。 |
| 429（送りすぎ） | 送信回数の上限に達しました。しばらく待ってからもう一度お試しください。 |
| そのほか・通信の失敗 | 送信に失敗しました。再度お試しください。 |

- 英語表示では、受付終了と日付・時間の不一致をそれぞれ英語の文で出す（サーバーの説明は日本語なので使わない）
- それまでは、400・422 も含めて「送信に失敗しました。再度お試しください。」だけだった
- **注意**: 400 の出し分けは、サーバーの説明の文字（上の4つ）と完全に同じかで決めている（`frontend/src/lib/reserve/errorMessage.ts` の `RESERVE_CLOSED_DETAILS`・`RESERVE_MISMATCH_DETAILS`。2026-10-31 に `pages/Reserve.tsx` から移した）。`backend/app/routes/reserve.py` のこの4つの文言を変えるときは、画面も合わせて直すこと。合わないと「日付と時間を選び直してください」の共通の文になる

- 2026-11-13 補足: 400 の出し分けの文言の一覧は、今は `frontend/src/lib/reserve/errorMessage.ts` の `RESERVE_CLOSED_DETAILS`・`RESERVE_MISMATCH_DETAILS`・`RESERVE_NOT_REQUIRED_DETAIL` にある（上の表の受付終了・不一致・予約不要の文言、全部で9つ）。サーバーの文言を変えるときは、このファイルも合わせて直すこと

### ワークショップの実施日と予約日（2026-11-13 追加）

- 予約日の選択肢は、ワークショップの実施日（イベント登録で「実施する日を選ぶ」にしていればその日、そうでなければ開催期間の全日程）のうち、今日（日本時間）以降の日だけ。過ぎた日は出さない
- 選べる日が1日だけのとき（1日のイベント・実施日が1日だけ・残りが1日だけ）は、その日を自動で選ぶ。複数日のイベントでは、選べる日が1日でも、どの日か分かるよう日付の選択肢として出す
- 選べる日が1日も残っていないときは、終了したイベントと同じ「受付終了」の表示にする
- 時間枠は、選んだ日に使える枠（全日程で共通の枠と、その日だけの枠）だけが出る（`GET /api/events/{id}/sessions?date=選んだ日`）
- 一部の日だけワークショップを行うイベントでは、左側のイベントの案内に「ワークショップ実施日: 11/3（火）・11/5（木）」と出す（英語表示は「Workshop dates: 11/3 (Tue), 11/5 (Thu)」）

### 予約不要のワークショップ（2026-11-13 追加）

- イベント登録で「予約必要」の印を外したワークショップ（`ws_requires_reservation` が false）は、終了前なら入力欄を出さず、「このワークショップは予約不要です。」「当日会場へお越しください。」とだけ出す
- それまでは「予約必要」の印を見ておらず、予約不要のワークショップでも予約の入力欄が出ていた
- サーバーも、予約不要のワークショップへの予約は 400 で受け付けない

## バックエンド処理（`POST /api/reserve`）

1. `session_id` が指定されている場合、スレッドロックを取得（同一セッションへの同時送信を直列化）
2. `workshop_reservations` の `participants` を合計して残席を確認:
   - `session_id` で照合した予約の合計
   - `session_id IS NULL` かつ `preferred_time` が一致する古い予約の合計（フォールバック）
3. `used + participants > max_participants` なら 409 を返す
4. `cancel_token` を生成（`secrets.token_urlsafe(16)`。英数字と `-` `_` の約22文字。2026-10-22 から。それまでは8桁の数字）
5. `workshop_reservations` テーブルに INSERT（`status = 'pending'`、`cancel_token` を含む）
6. `_sync_reserved_count(session_id)` でデノーマライズ値を更新
7. `_send_confirmation()` で予約受付メールを送信（キャンセルリンク含む、`lang` フィールドにより日本語または英語）
8. `_send_admin_notification()` で管理者への通知メールを送信

2026-11-13 から、イベントがあり受付期間内かを確かめたあと（上の 1. の前）に、ワークショップのあるイベントでは次を確かめる（`_check_workshop_reservation`）。合わなければ 400 を返す。

| 確かめること | 合わないときの説明 |
|---|---|
| 予約不要のワークショップでないか | このワークショップは予約不要です。当日会場へお越しください。 |
| 複数日のイベントで予約日を送っているか（1日のイベントで省いたら開始日とみなす） | 予約日を選んでください |
| 予約日がワークショップの実施日か | この日はワークショップを実施していません |
| その日に使える枠が1つ以上あるのに、時間枠を選んでいない | 時間枠を選んでください |
| 選んだ時間枠が、このイベントの別の日だけの枠 | この時間枠は選んだ日には使えません |
| 選んだ時間枠が、このイベントの枠でない | ワークショップの時間枠が正しくありません |

- その日に使える枠が0件のときは、時間枠なしで受け付ける（人数の上限は確かめない）
- 2026-11-13 から、確かめた予約日を必ず `preferred_date` として保存する（1日のイベントで送られなかったときは開始日）。時間枠があれば、枠の時間の表示を `preferred_time` に入れて保存する。管理者があとで時間枠を作り直したときに、同じ時間・同じ日の新しい枠へ予約を付け替える手がかりにするため
- 保存のときに、データベースも「その日がワークショップを行う日か」「同じイベントの枠か」「その日に使える枠か」「枠のある日に枠なしで送っていないか」を確かめ直す。合わなければ次の 400 になる
  - 「この日はワークショップを実施していません」（確かめたあとで、管理者がその日を実施日から外した直後など）
  - 「時間枠を選んでください」（時間枠なしで送ったが、確かめたあとで管理者が同じ日に枠を足した直後。先に枠なしで受け付けた予約は、あとから枠が足されてもそのまま残る）
  - 「この時間枠は選んだ日には使えません」
  - 「ワークショップの時間枠が正しくありません」

**スレッドロックの補足**: セッション単位の `threading.Lock` でチェック→INSERT を原子化。単一プロセス（Render 単一インスタンス）を前提とする。

## メール仕様（予約受付）

- **from**: `Habitat Oides <{HABITAT_SENDER}>`
- **subject（ja）**: `[Habitat Oides] ワークショップ予約を受け付けました: {イベント名}`
- **subject（en）**: `[Habitat Oides] Workshop reservation received: {イベント名}`
- **本文**: イベント名・開催日・会場・セッション時間・参加人数・持ち込み有無・備考 + キャンセルリンク（`https://ei8htplants.com/official/cancel?id={cancel_token}`）+ 返信不可フッター
- **言語**: `lang = 'en'` の場合は英語、それ以外は日本語

## 関連機能

- 登録された予約は [FT-11 予約ステータス管理](11_予約ステータス管理.md) で管理者が確認・ステータス変更
- 予約受付メールにキャンセルリンクが含まれるため、予約者はすぐに [キャンセルページ](../pages/public/13_CancelReservation.md) からキャンセル操作が可能
- 管理者がステータスを `cancelled` に変更すると、予約者へキャンセル完了メールが送信される
