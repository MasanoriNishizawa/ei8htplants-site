# FT-06 — 予約フォーム

## 概要

ワークショップ予約フォームの送信機能。URLクエリパラメータからイベントIDを取得し、セッション選択・参加人数入力を経てバックエンド経由でDBに予約を登録する。

## 使用ページ

| ページID | ページ名 | 用途 |
|---|---|---|
| [PG-12](../pages/public/12_Reserve.md) | Reserve | 予約フォーム本体 |

## 遷移元

[FT-03 イベント表示](03_イベント表示.md) の予約ボタン（`/reserve?event_id={id}`）

## 実装ファイル

`frontend/src/pages/Reserve.tsx`

## URLパラメータ

| パラメータ | 取得方法 | 用途 |
|---|---|---|
| `event_id` | `useSearchParams()` | 予約対象イベントIDとしてAPIに送信 |

## フォーム項目

| フィールド | 型 | 必須 | 条件 | 説明 |
|---|---|---|---|---|
| 開催日（ラジオ） | string | 条件付き | 複数日イベントのみ表示 | `preferred_date` にセット |
| セッション（ラジオ） | string | 条件付き | `event.has_workshop = true` のみ表示 | `session_id` にセット |
| 参加人数（セレクト） | number | ○ | WS時はセッション選択後に有効化 | 1〜残席数の選択肢 |
| お名前 | text | ○ | 常時表示 | `required` |
| メールアドレス | email | ○ | 常時表示 | `type="email"` + `required` |
| 植物持ち込み | checkbox | — | 常時表示 | `bring_plant` |
| 鉢持ち込み | checkbox | — | 常時表示 | `bring_pot` |
| 備考 | textarea | — | 常時表示 | 任意 |

## 状態管理

| state | 型 | 説明 |
|---|---|---|
| `form` | `{ name, email, participants, note, session_id, bring_plant, bring_pot, preferred_date }` | フォーム入力値 |
| `status` | `'idle' \| 'loading' \| 'done' \| 'error' \| 'full'` | 送信状態 |
| `event` | `Event \| null` | イベント情報 |
| `sessions` | `WsSession[]` | WSセッション一覧 |

## 派生値（フォーム制御）

```typescript
const expectsSessions = !!event?.has_workshop
// sessions.length ではなく event.has_workshop を使う。
// sessions 取得完了前でも true になるため、ロード中にセクションが消えるフラッシュを防ぐ。
```

## 送信フロー

```
ページ表示
    │
    ▼
api.events.get(event_id)
    │
    ├─ 複数日イベント ──→ 開催日ラジオを表示（preferred_date が空の間は次段を disabled）
    │
    ├─ has_workshop=true ──→ api.events.getSessions(event_id)
    │                             ▼
    │                        セッションラジオを表示（残席数を併記）
    │                             ▼
    │                        セッション選択後 → 参加人数セレクトを有効化（1〜残席数）
    │
    ▼（フォーム入力完了後）
onSubmit
    │
    ▼
api.reserve.create({ event_id, name, email, participants, note,
                     session_id, bring_plant, bring_pot, preferred_date })
    │                （POST /api/reserve）
    ├─ 200 ──→ setStatus('done') → 「ご予約を受け付けました」表示
    ├─ 409 ──→ setStatus('full') → 「満席になりました」表示
    └─ その他 ──→ setStatus('error') → エラーメッセージ表示
```

## バックエンド処理（`POST /api/reserve`）

1. `session_id` が指定されている場合、`workshop_reservations` の `participants` を合計して残席を確認（行数ではなく合計値で判定）
2. 定員超過なら 409 を返す
3. `workshop_reservations` テーブルに INSERT（`status = 'pending'`）
4. `_sync_reserved_count(session_id)` でデノーマライズ値を更新
5. Resend 経由で予約受付メールを送信

## メール仕様（予約受付）

- **from**: `ei8ht plants <{CONTACT_FROM_EMAIL}>`
- **subject**: `[Habitat Oides] ワークショップ予約を受け付けました: {イベント名}`
- **本文**: イベント名・開催日・会場・セッション時間・参加人数・持ち込み有無・備考 + 返信不可フッター

## 関連機能

- 登録された予約は [FT-11 予約ステータス管理](11_予約ステータス管理.md) で管理者が確認・ステータス変更
- ステータスが `confirmed` に変更されると [キャンセルページ](../pages/public/13_CancelReservation.md) へのリンクを含むメールが送信される
