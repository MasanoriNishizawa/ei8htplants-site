# FT-06 — 予約フォーム

## 概要

ワークショップ予約フォームの送信機能。URLクエリパラメータからイベントIDを取得し、セッション選択・参加人数入力を経てバックエンド経由でDBに予約を登録する。

| ページID | ページ名 | 用途 |
|---|---|---|
| [PG-12](../pages/public/12_Reserve.md) | Reserve | 予約フォーム本体 |

## 遷移元

[FT-03 イベント表示](03_イベント表示.md) の予約ボタン（`/official/reserve?event_id={id}`）

## 送信フロー

```
ページ表示
    │
    ▼
useEffect #1: api.events.get(event_id)  ← [eventId] 依存
    │
    ├─ 単日イベント → preferred_date を start_date に自動セット
    ├─ 複数日イベント → 開催日ラジオを表示（preferred_date が空の間は次段 disabled）
    │
    ▼ preferred_date が確定すると useEffect #2 が起動
useEffect #2: api.events.getSessions(event_id, preferred_date)  ← [event, preferred_date] 依存
    │  （日付を渡すことでその日の予約数を反映した reserved_count を取得）
    ▼
    セッションラジオを表示（残席数を併記）
    ▼
    セッション選択後 → 参加人数セレクトを有効化（1〜残席数）
    │
    ▼（フォーム入力完了後）
onSubmit
    │
    ▼
api.reserve.create({ event_id, name, email, participants, note,
    │                session_id, bring_plant, bring_pot, preferred_date, lang })
    │                （POST /api/reserve）
    ├─ 200 ──→ setStatus('done') → 「ご予約を受け付けました」表示
    ├─ 409 ──→ setStatus('full') → 「このセッションは満席になりました」表示
    └─ その他 ──→ setStatus('error') → 下の「送信に失敗したときの文言」
```

- 文字数の上限は、サーバーの入力チェック（`backend/app/routes/reserve.py` の上限）と同じ値（`frontend/src/lib/constants.ts` の `INPUT_MAX_LENGTH`）。入力欄の時点でそれ以上打てないようにする

### 送信に失敗したときの文言（2026-10-23 追加）

| サーバーの答え | 日本語表示で出す文言 |
|---|---|
| 409 | 満席の画面（「このセッションは満席になりました」） |
| 400 で、説明が「このイベントの予約受付は終了しています」「この日の予約受付は終了しています」（受付終了） | サーバーの説明をそのまま |
| 400 で、説明が「予約日がイベントの開催期間外です」「ワークショップの時間枠が正しくありません」（日付・時間が合わない） | サーバーの説明をそのまま |
| 400（上のどれでもない） | 選んだ日付または時間がこのイベントの予約枠と合いません。日付と時間を選び直してください。 |
| 422（入力の形が違う・長すぎる） | 入力内容に誤りがあります。お名前・メールアドレス・電話番号・人数（1〜10名）・備考（2000文字まで）をご確認ください。 |
| 429（送りすぎ） | 送信回数の上限に達しました。しばらく待ってからもう一度お試しください。 |
| そのほか・通信の失敗 | 送信に失敗しました。再度お試しください。 |

- 英語表示では、受付終了と日付・時間の不一致をそれぞれ英語の文で出す（サーバーの説明は日本語なので使わない）
- それまでは、400・422 も含めて「送信に失敗しました。再度お試しください。」だけだった
- **注意**: 400 の出し分けは、サーバーの説明の文字（上の4つ）と完全に同じかで決めている（`frontend/src/pages/Reserve.tsx` の `RESERVE_CLOSED_DETAILS`・`RESERVE_MISMATCH_DETAILS`）。`backend/app/routes/reserve.py` のこの4つの文言を変えるときは、画面も合わせて直すこと。合わないと「日付と時間を選び直してください」の共通の文になる

## バックエンド処理（`POST /api/reserve`）

1. `session_id` が指定されている場合、スレッドロックを取得（同一セッションへの同時送信を直列化）
2. `workshop_reservations` の `participants` を合計して残席を確認:
   - `session_id` で照合した予約の合計
   - `session_id IS NULL` かつ `preferred_time` が一致する古い予約の合計（フォールバック）
3. `used + participants > max_participants` なら 409 を返す
4. `cancel_token` を生成（`secrets.token_urlsafe(16)`。英数字と `-` `_` の約22文字。2026-10-22 から。それまでは8桁の数字）
5. `workshop_reservations` テーブルに INSERT（`status = 'pending'`、`cancel_token` を含む）
6. `_sync_reserved_count(session_id)` でデノーマライズ値を更新
7. `_send_confirmation()` で予約受付メールを送信（キャンセルリンク含む、`lang` フィールドにより日本語または英語）
8. `_send_admin_notification()` で管理者への通知メールを送信

**スレッドロックの補足**: セッション単位の `threading.Lock` でチェック→INSERT を原子化。単一プロセス（Render 単一インスタンス）を前提とする。

## メール仕様（予約受付）

- **from**: `Habitat Oides <{HABITAT_SENDER}>`
- **subject（ja）**: `[Habitat Oides] ワークショップ予約を受け付けました: {イベント名}`
- **subject（en）**: `[Habitat Oides] Workshop reservation received: {イベント名}`
- **本文**: イベント名・開催日・会場・セッション時間・参加人数・持ち込み有無・備考 + キャンセルリンク（`https://ei8htplants.com/official/cancel?id={cancel_token}`）+ 返信不可フッター
- **言語**: `lang = 'en'` の場合は英語、それ以外は日本語

## 関連機能
