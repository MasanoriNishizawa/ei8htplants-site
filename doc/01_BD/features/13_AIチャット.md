# FT-24 — AIチャット

## 概要

Gemini（`gemini-flash-lite-latest`）を使った植物相談・ワークショップ案内チャット機能。
植物の育て方・管理に関する相談と、ワークショップ・予約に関する質問に対応する ei8ht plants AIコンシェルジュ。
会話履歴は画面を開いている間だけ保持する（ページを開き直すと消える）。質問と AI の返事は管理画面のチャットログ用に `chat_logs` テーブルへ保存する。
バイリンガル対応（質問の言語に合わせて日本語または英語で回答）。

## 状態管理

| state | 型 | 説明 |
|---|---|---|
| `messages` | `Message[]` | 利用者と AI のやりとり（role: `'user'` または `'model'`、content: 文字列、localOnly: 表示だけで送らない案内なら true）。歓迎メッセージは入れない（最初は空） |

歓迎メッセージ（「こんにちは。ei8ht plants のAIコンシェルジュです。…」）は state に入れず、画面を描くたびに今の言語で作り、表示するときと送るときに先頭に付ける。言語を切り替えると、表示も次に送る履歴も今の言語の歓迎メッセージになる（2026-10-22 変更。それまでは最初の表示のときに1回だけ state に入れていたので、言語を切り替えても最初の言語のままだった）。
| `input` | `string` | テキストエリアの入力値 |
| `loading` | `boolean` | API呼び出し中フラグ（送信ボタン・テキストエリアのdisabled制御） |

## 送信フロー

```
ページ表示
    │
    ▼
表示: [歓迎メッセージ（今の言語）, ...messages]（歓迎メッセージは state に入れない）
    │
    ▼
ユーザーがテキストエリアに入力（2,000 文字まで。それ以上は入力できない）
    Enter（Shift+Enterは改行。日本語入力の変換中の Enter では送らない）または [送信] ボタンクリック
    │
    ▼
send()
    │
    ├─ input が空、または loading=true → 何もしない（早期 return）
    │
    ├─ userMsg = { role: 'user', content: input（前後の空白を除く） } を messages に追加
    ├─ setInput('') — 入力欄クリア
    ├─ setLoading(true)
    │
    ▼
    api.chat.send(toSendHistory([歓迎メッセージ, ...messages, userMsg]))  → POST /api/chat  { messages: … }
    │  （2026-10-22 から lib/api.ts の api.chat.send を通して送る。それまでは画面の中で fetch を直接呼んでいた。
    │    送る中身・案内の出し分けは同じ。状態コードで案内を分けるため、api.chat.send は応答をそのまま返す）
    │  （送る前に会話を整える。下の「送る会話の整え方」を参照）
    │
    ├─ 200 で reply に本文あり → messages に { role: 'model', content: reply } を追加
    ├─ 200 で reply が空・null・文字列でない → 「うまくお答えできませんでした。…」の案内（表示だけ）
    ├─ 429 → 「メッセージの送信回数が上限に達しました。…」の案内（表示だけ）
    ├─ 422 → 「メッセージを送れませんでした。…」の案内（表示だけ）
    └─ その他のエラー → 「申し訳ありません、エラーが発生しました。…」の案内（表示だけ）
       （案内はすべて日本語・英語の両方に対応）

    ▼（どの場合も最後に）
    setLoading(false)

メッセージ追加時（最初の表示のときを除く）:
    chatAreaRef.current.scrollTop = scrollHeight
    // チャットエリア内を最下部へ自動スクロール
```

### 画面に出る案内（2026-10-20 追加・変更）

| こんなとき | 画面に出る文（日本語） |
|---|---|
| 送信回数の上限（1 分間に 10 回）を超えた | メッセージの送信回数が上限に達しました。しばらく経ってからもう一度お試しください。 |
| サーバーの入力チェックで断られた（文字数・件数など） | メッセージを送れませんでした。内容を短くするか、ページを開き直してください。 |
| AI が返事の本文を返さなかった | うまくお答えできませんでした。言い方を変えてもう一度お試しください。 |
| 通信の失敗など、その他のエラー | 申し訳ありません、エラーが発生しました。しばらく経ってからもう一度お試しください。 |

これらの案内は画面に表示するだけで（`localOnly: true` の印を付ける）、次に送る会話には入れない（AI の返事ではないため。入れると AI に誤った流れを渡し、40 件の上限にも早く届く）。

### 送る会話の整え方（`lib/chatHistory.ts` の `toSendHistory`、2026-10-20 追加）

画面では会話をすべて表示したまま、サーバーに送る分だけを次の順で整える。サーバーの入力チェック（下記）に合わない会話を送らないためのもの。

1. 表示だけの案内（上の表。`localOnly`）と、本文が空白だけのものを外す。先頭の歓迎メッセージは AI の発言として残る
2. 返事が付かなかった過去の質問（エラーなどで答えが出なかったもの）を外す。今回の質問は残す。これで利用者と AI の発言が交互に並ぶ
3. 新しいほうから 40 件だけにする（最後は今回の質問のまま）
4. 1 件ごとに本文を 2,000 文字までに切る（AI の長い返事が残っていても送れるように）。絵文字も 1 文字として数え、途中で壊さない

## バックエンド処理（`POST /api/chat`）

0. 入力チェック（2026-10-20 追加）: 下の「送れる会話の条件」に合わなければ `422` を返して終わる。このときは AI（Gemini）を呼ばず、送信回数にも数えない
1. `GEMINI_API_KEY` が未設定の場合 → `503 Chat is not available`
2. 送り元の IP ごとの回数制限（1 分間に 10 回）を超えた場合 → `429`
3. システムプロンプトに、サイトの公開データ（イベント・商品・記事・取扱店）と、管理画面で登録した有効な Q&A を書き足す
4. リクエストの `messages` から最後のメッセージを分離し、それ以前を `history`（Gemini形式）として渡す
5. `chat_session.send_message(最後のメッセージ.content)` を呼び出し
6. 成功 → チャットログ（`chat_logs`）に保存し（保存に失敗してもチャットは成功扱い）、`{ reply: response.text }` を返す
7. 例外 → `500 Internal Server Error`

### 送れる会話の条件（2026-10-20 追加）

公開チャットは誰でも送れるため、長い文や長い会話で AI の利用料が増えないよう、サーバーで次の条件を確かめる。

| 項目 | 条件 |
|---|---|
| 送り手（role） | `user`（利用者）か `model`（AI）だけ |
| 本文（content） | 1〜2,000 文字。空白・改行だけのものは不可（前後の空白は削らずにそのまま AI に渡す） |
| 会話の件数（messages） | 1〜40 件（約 20 往復分。先頭に付ける歓迎メッセージと AI の返事も数える） |
| 最後のメッセージ | 利用者（`user`）の発言であること |

上限の数は `backend/app/routes/chat.py` の `MAX_MESSAGE_CHARS = 2000`・`MAX_MESSAGES = 40` で決めている。画面側（`lib/chatHistory.ts`）も同じ数に合わせている。

## システムプロンプト概要

- ei8ht plants のAIコンシェルジュとして振る舞う
- 取り扱いブランド（ei8ht plants / HUE / Habitat Oides）の説明を含む
- 予約URL・ワークショップURL・キャンセル手順を案内できる
- 植物の育て方（水やり・日当たり・土・肥料・病害虫）に丁寧に答える
- 分からないことはお問い合わせフォーム（/contact）に案内する
- 質問の言語（日本語/英語）に合わせて回答する

## API仕様

```
POST /api/chat
Request:  { messages: [{ role: 'user' | 'model', content: string }] }  // 1〜40件・各1〜2,000文字・最後は user
Response: { reply: string }
Errors:   422 (入力条件に合わない), 503 (GEMINI_API_KEY未設定), 429 (送信回数の上限), 500 (API呼び出し失敗)
```

詳細は [DD-06 API仕様](../../02_DD/06_API仕様.md) の「Chat」セクションを参照。
