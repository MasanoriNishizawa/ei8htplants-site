# FT-25 — 分析ダッシュボード

（2026-10-17 追加。同日、公開先を Render から Streamlit Community Cloud に変更）

## 概要

イベントの収支・ワークショップの予約・ショップの注文・問い合わせ・サイトのアクセス数を、グラフと表でまとめて見るための画面。サイト本体とは別のプログラム（`analytics/` フォルダ。Streamlit という Python の画面作成の仕組みを使う）で、Streamlit Community Cloud（Streamlit の無料の公開サービス）で公開している。はじめは Render の別のサービスとして公開していたが、Render の無料枠（すべてのサービスを合わせて月 750 時間まで動かせる）をサイト本体と分け合うと足りなくなったため移した。

- 開き方: 管理画面の左のメニュー「分析 ↗」を押す（新しいタブで `https://ei8htplants-analytics.streamlit.app` が開く）
- 見られる人: 管理画面と同じメールアドレス・パスワードでログインでき、見てよい人のリスト（`ANALYTICS_ALLOWED_EMAILS`）に入っている人（下の「ログイン」を参照）
- データ: 本番の Supabase のデータを**読むだけ**。ここから内容を書き換えたり消したりすることはできない
- しばらく使われないと休止する（無料の公開サービスの仕様）。休止中に開くと起動を待つ必要があり、起こすためのボタン（「Yes, get this app back up!」など）が出たときは押す

## 実装ファイル

- `frontend/src/pages/admin/AdminLayout.tsx`（管理画面のメニューの「分析 ↗」。開く先の URL は `ANALYTICS_URL`）
- `analytics/app.py`（入り口。エラーの詳細を出さない設定・Secrets の読み込み・ログインの確認と画面の一覧）
- `analytics/lib/secrets_env.py`（Community Cloud の Secrets に入れた値を、プログラムから読めるようにする）
- `analytics/lib/auth.py`（ログイン）
- `analytics/lib/data.py`（Supabase からの読み取り）
- `analytics/lib/ga.py`（Google アナリティクスからの読み取り）
- `.streamlit/config.toml`（リポジトリ直下。公開先での画面の色・エラー表示の設定）と `analytics/.streamlit/config.toml`（自分の PC で動かすときの設定）
- `analytics/views/`（7つの画面）

ファイルごとの役割は [DD-01 モジュール構成](../../02_DD/01_モジュール構成.md) の「6. 分析ダッシュボード（analytics/）」を参照。

## ログイン

管理画面と同じ Supabase のアカウントを使う。ただし管理画面とは別の場所で動いているので、管理画面にログインしていても、分析ダッシュボードを開いたら改めてログインする。

| 場面 | 動き |
|---|---|
| 開いたとき | 「ei8ht plants 分析」の見出しと、メールアドレス・パスワードの入力欄、「ログイン」ボタンだけが出る。ログインするまでは、グラフもデータの読み込みも行わない |
| 正しく入力したとき | 分析の画面が表示される。左のメニューに「ログイン中: メールアドレス」と「ログアウト」が出る |
| メールアドレスかパスワードが違うとき | 「メールアドレスまたはパスワードが違います。」 |
| ログインに失敗したとき（どの理由でも） | メールアドレス・パスワードの入力欄は空に戻る（パスワードを画面に残さないため）。もう一度両方を入れる |
| どちらかが空のまま押したとき | 「メールアドレスとパスワードを入力してください。」（失敗の回数には数えない） |
| 見てよい人に入っていないとき | 「このアカウントでは閲覧できません。」（`ANALYTICS_ALLOWED_EMAILS` を設定したときだけ） |
| 5回続けて失敗したとき | 最後の失敗から 60 秒は「ログインの失敗が続いたため、しばらく待ってからもう一度お試しください。」と出て、ログインを試せない。60 秒たてば、回数を数え直してまた試せる |
| 認証のサーバーにつながらないとき | 「認証サーバーに接続できませんでした。時間をおいてもう一度お試しください。」（失敗の回数には数えない） |
| ログインの設定（Supabase の URL・キー）が無いとき | 「ログインの設定がありません（NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY）。」と出て、入力欄も出ない |
| ブラウザを再読み込みしたとき・タブを閉じて開き直したとき | もう一度ログインが必要 |
| 「ログアウト」を押したとき | ログイン画面に戻る |
| ログイン中に、見てよい人のリストから外されたとき | 次に画面を操作したとき（メニューを押す・ボタンを押すなど）にログアウトされ、ログイン画面に戻る。ログインしたあとも、画面を描くたびにリストを確かめ直している |

### 見てよい人を絞る（`ANALYTICS_ALLOWED_EMAILS`。必ず設定する）

Supabase で新規登録ができる設定だと、第三者がアカウントを作って見られてしまうため、必ず設定する（あわせて Supabase の新規登録をオフにする。[OP-04](../../05_OP/04_分析ダッシュボードの公開手順.md) の 2 章）。

- Community Cloud の Secrets の `ANALYTICS_ALLOWED_EMAILS` に、見てよい人のメールアドレスをカンマ区切りで入れる（例: `a@example.com,b@example.com`）
- 大文字・小文字の違いと、前後の空白は無視する。一部だけ一致するメールアドレスは通さない
- 設定しないとき（空のとき）は、Supabase にログインできる人は全員見られる
- リストから外した人は、ログイン中でも、次に画面を操作したときにログアウトされる
- 判定には、入力したメールアドレスではなく、Supabase がログイン成功時に返したメールアドレスを使う

### 守っていること

- パスワードと、ログイン成功時に Supabase から返る合言葉（トークン）は保存しない。画面にも記録（ログ）にも出さない。覚えておくのはメールアドレスだけ
- ログインしたあとは、パスワード欄に入力した値をサーバー側の状態からも消す。ログインに失敗したときも入力欄を空に戻す
- 予期しないエラーが起きても、エラーの詳しい内容（プログラムの場所など）は画面に出さない（内容は Community Cloud の画面右下の **Manage app** で出る記録（ログ）で確かめる）。この設定は設定ファイルに加えて `analytics/app.py` の先頭でも入れていて、設定ファイルが読まれない起動の仕方でも効く
- ログインの確認には公開用のキー（anon キー）を使い、データを読むための強い権限のキー（service_role キー）は使わない
- ログインの失敗の回数は、そのブラウザのタブの中だけで数える。再読み込みすると数え直しになる簡易的な対策で、実際の総当たり対策は Supabase 側の回数制限が担う

## データの扱い

| 項目 | 内容 |
|---|---|
| 読むデータ | イベント・イベント収支・WS の時間枠・WS 予約・商品・注文・注文の明細・問い合わせ・記事 |
| 読まないデータ | 氏名・電話番号・住所・問い合わせの本文（読み込む列をあらかじめ決めていて、これらは含めない） |
| メールアドレス | 予約・注文のメールアドレスは「同じ人か」の判定（リピーターの集計）だけに使う。読み込んだらすぐ別の文字列に置き換え（ハッシュ化）、元のメールアドレスは残さない |
| 書き込み | しない（読み取りだけ。追加・変更・削除の通信は行わない） |
| 読み直しの間隔 | 10 分。左のメニューの「データを再読み込み」で、すぐに読み直せる |
| 収支の計算 | 管理画面の収支（`frontend/src/lib/api.ts` の `computeFinances`）と同じ計算式（`analytics/lib/finance.py`）。管理画面の式を変えたら、こちらも合わせて直す |
| 売上が 0 円の収支 | 「まだ開催していない・入力前」とみなして集計から外す |
| アクセス解析 | GA4 の数字を読み取りだけの権限で読む。鍵は、公開先では Secrets の `GA_CREDENTIALS_JSON`（鍵ファイルの中身）、自分の PC では `GA_CREDENTIALS`（鍵ファイルの場所）で渡す（両方あれば `GA_CREDENTIALS_JSON` を使う）。`GA_PROPERTY_ID` や鍵が無い・鍵の中身が読めないときは、画面に理由と設定の手順を表示する。鍵の中身は画面にも記録（ログ）にも出さない |
