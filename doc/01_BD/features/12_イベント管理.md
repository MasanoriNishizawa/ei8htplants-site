# FT-12 — イベント管理

## 概要

Adminイベントの一覧表示・作成・編集・削除（CRUD）機能。ブランドの複数選択、画像ファイルのアップロード（複数可）、URL スラッグ、日ごとの開催時間、ワークショップの時間枠（WSセッション）の設定に対応する。開催予定と過去の区別は終了日（無ければ開始日）から自動で決まる（2026-10-22 に記述を今の画面に合わせた）。

## 画像の追加

- 「+ 追加」の枠を押して画像ファイルを選ぶ（複数まとめて選べる）。選ぶとすぐにアップロードし、終わると一覧に並ぶ
- 各画像の「×」で外せる。アップロード中は保存ボタンが「アップロード中...」になり押せない
- 保存するときは、アップロードが終わった画像の URL だけを送る

## ワークショップの時間枠（WSセッション）

- 「ワークショップあり」に印を付けると、「予約必要」と「WSセッション（各回の時間・定員）」の欄が出る
- 「+ 追加」で1行ずつ足す（時間の例: `10:00〜11:30`、定員）。行がなければ時間指定なしで予約を受け付ける
- 「自動設定」は、開催時間が「10:00〜17:00」のような形のとき、開始の1時間後から終了の1時間前まで、1時間ごと・定員4名の枠を作る
- 保存すると、イベント本体と時間枠を `POST`・`PUT /api/events` の1回でまとめて保存する（2026-11-13 から。それまではイベントの保存のあとに `PUT /api/events/{id}/sessions` で時間枠を保存していた。下の「保存」）

## ワークショップの実施日（2026-11-13 追加）

複数日のイベントで、ワークショップを一部の日だけ行う・日によって時間枠を変える、を設定できる。

### 実施のしかたの切り替え

「ワークショップあり」に印を付けた複数日のイベントでは、時間枠の欄の上に次の2つの選択肢が出る。1日だけのイベントでは出ない（いつも全日程の扱い）。

| 選択肢 | 動き |
|---|---|
| 全日程で実施（共通の枠） | 今までと同じ。開催期間のすべての日でワークショップを行い、どの日も同じ時間枠を使う |
| 実施する日を選ぶ | 開催日を並べたチェックで実施する日を選び、選んだ日ごとに時間枠を設定する |

- 「全日程で実施」から「実施する日を選ぶ」に切り替えると、開催期間のすべての日に印が付き、どの日にも今の共通の枠が写される
- 「実施する日を選ぶ」から「全日程で実施」に戻すと、選んでいた日のうち一番早い日の枠が共通の枠になる。ほかの日に時間の入った枠があるときは「全日程で実施に切り替えると、〇月〇日（〇）の枠を共通の枠にし、ほかの日の枠（〇件）は消えます。よろしいですか？」と確認が出る。［キャンセル］なら切り替えない

### 実施する日と日ごとの時間枠

- 「実施する日（1日以上）」の下に開催日が並ぶ。印を付けた日が実施日になる。最後の1日は外せない（チェックが押せなくなる）
- 初めて印を付けた日は枠なしから始まる。一度外した日に印を付け直すと、外す前の枠が戻る（外したままの日の枠は保存しない）
- 選んだ日ごとに、その日の時間枠の欄が出る。欄の上のボタンは次の3つ
  - 「自動設定」: その日の開催時間（「日ごとに異なる」を使っていればその日の時間、なければ共通の開催時間）が「10:00〜17:00」のような形のとき、共通の枠と同じ決まりで1時間ごとの枠を作る。開催時間がその形でなければ押せない
  - 「ほかの日の枠をコピー」: ほかに枠のある実施日があるときだけ出る。選んだ日の枠をこの日に写す。この日にすでに時間の入った枠があるときは「〇月〇日（〇）の枠（〇件）を、〇月〇日（〇）の枠で置き換えます。よろしいですか？」と確認が出る
  - 「+ 追加」: 空の枠を1行足す
- 枠が無い日は「枠なし（時間指定なしで予約受付）」と出る。その日は、予約ページで時間を選ばずに予約できる

### 開催期間を変えたとき

- 開始日・終了日を変えて開催期間から外れた日は、実施日と日ごとの枠から外れる
- 開催期間を1日に縮めると「全日程で実施」に戻る。残った1日を実施日にしていればその日の枠が、していなければ一番早い実施日の枠が共通の枠になる

### 保存

- 「実施する日を選ぶ」で実施日が1日も無いとき（開催期間を変えて全部外れたときなど）は保存せず、「ワークショップを実施する日を1日以上選んでください」と出す
- イベント本体（`ws_dates` に選んだ日を日付の順で入れる）と時間枠（`sessions`）を、1回の保存で送る。サーバーは両方を1つのまとまりで保存し、どちらかだけが保存されることはない。日ごとの枠には、その枠を使う日（`session_date`）を付けて送る。時間の入っていない行は送らない（それまでは、イベントの保存のあとに時間枠を別に保存していた）
- 「全日程で実施」のときは `ws_dates` を `null` にし、時間枠は今までどおり日付なしで送る
- 編集で開いたとき、実施日が保存されているイベントは「実施する日を選ぶ」の状態で開き、時間枠を日ごとに分けて出す

### 予約が入っている日時を消そうとしたとき（2026-11-13 追加）

- すでに予約が入っている日時の枠を消した・時間の表示を変えた・その日を実施日から外した、などで、予約の移し先が無くなるときは、**何も保存しない**
- 開催期間を縮めて予約の日が期間から外れる・「ワークショップあり」のチェックを外す、も同じ（キャンセル以外の予約すべてについて、その日が保存後もワークショップを行う日かを確かめる）。保存前からワークショップを行う日でなかった古い予約では止めない
- 既存の予約は、同じ時間の表示で同じ日に使える新しい枠があれば、自動でその枠へ付け替える（たとえば「全日程で実施」から「実施する日を選ぶ」に変えても、予約の日に同じ時間の枠が残っていれば保存できる）
- 保存できなかったときは、フォームの下に赤い枠で次のように出す。入力した内容はそのまま残る

```
予約が入っている日時を変更・削除しようとしています。先に予約をキャンセルするか、別の日時へ変更してください。
・7/2（木） 11:00〜12:00 に予約 1 件・2 名
このイベントの予約を見る（別のタブ）
```

- 一覧は日時ごとに「月/日（曜日） 時間 に予約 N 件・N 名」と出す。予約日の無い古い予約は「日付なし」、時間の指定の無い予約（その日に枠が無かった予約）は「時間指定なし」と出る（例「7/3（金） 時間指定なし に予約 2 件・3 名」）
- 「このイベントの予約を見る（別のタブ）」は、イベント別の予約画面を新しいタブで開く（編集のときだけ出る）。そこで予約をキャンセルするか日時を変えてから、元のタブでもう一度［保存する］を押す

### 読み込んだときの食い違いの補正（2026-11-13 追加）

編集で開いたとき、保存されている実施日の設定と時間枠が食い違っていれば、画面で補正して開き、フォームの上に黄色い帯で理由と「内容を確かめて、保存し直してください。」を出す。補正したことは「保存していない変更」として扱う。

| 食い違い | 画面での補正 |
|---|---|
| 「実施する日を選ぶ」のイベントに、全日程で共通の枠が残っている | 各実施日に写して出す（その日に同じ時間の枠があれば写さない） |
| 「実施する日を選ぶ」のイベントに、実施日でない日の枠が残っている | 出せないので案内だけ出す（このまま保存すると消える。予約が入っていれば保存は止まる） |
| 「全日程で実施」のイベントに、日付つきの枠が残っている | 同じ時間の枠を1つにまとめて、共通の枠として出す |
- 実施日・日ごとの枠の変更も「保存していない変更」として扱う（サイドメニューで別の画面へ移るときなどに確認が出る）
- サーバー側の確かめ方は [DD-06 API 仕様](../../02_DD/06_API仕様.md) の `POST /api/events`・`PUT /api/events/{event_id}/sessions` を参照
- **制限**: 画像の保存は、イベントと時間枠の保存のあとに別に行う。画像の保存だけが失敗したときは、イベントと時間枠は保存されたままエラーが出る。新規作成でこれが起きたときに、URL スラッグを入れずに同じ内容でもう一度保存すると、同じイベントが2件できる（将来の改善候補。今は直していない。一覧を見て、重なっていれば片方を消す）

## 削除フロー

```
削除ボタンクリック → confirm → 処理中にする（全部の行の複製・削除を押せなくする）
  → DELETE /api/events/{id}
      ├─ 成功 → 一覧からその行を外す
      └─ 失敗 → 一覧はそのまま、上に「削除に失敗しました（理由）」
  → 処理中を戻す
```

- 複製も同じく処理中は全部の行の複製・削除を押せない（続けて押して同じイベントが2つできるのを防ぐ）。成功したら一覧を読み直し、失敗したら「複製に失敗しました（理由）」を出す（2026-10-22 追加）
- 複製は、2026-11-13 から、ワークショップの実施日（`ws_dates`）・日ごとの開催時間（`daily_times`）・時間枠（日ごとの枠の日付も）も写し、イベントと時間枠を1回で作る。ワークショップありのイベントで複製元の時間枠を読み込めなかったときは、枠の無い複製を作らないよう中止し、「複製元の時間枠を読み込めなかったため、複製を中止しました（理由）」を出す
- 一覧の読み込みに失敗したときは「イベントの読み込みに失敗しました（理由）」を出す（「予定なし」と見分けられるようにする）

## イベントサイト編集（AdminEventSite。2026-10-22 追記）

イベント一覧の「サイト」から開く画面（`/admin/events/:id/site`）。イベント専用ページ（[PG-20](../pages/public/20_EventSite.md)）の中身を入れる。

- **読み込みに失敗したとき**: 入力欄を出さずに、赤い枠で「イベントの読み込みに失敗しました（理由）」と「再読み込み」ボタンだけを出す。空の入力欄のまま「保存」を押して、入れてあった中身を空で上書きしてしまうのを防ぐため。「再読み込み」を押すと読み込み直す（2026-10-22 追加。それまでは失敗しても空の入力欄が出ていた）
- **保存に失敗したとき**: 赤い枠で「保存に失敗しました（理由）」を出す。入力は残るので、もう一度「保存」を押せる
- **保存に成功したとき**: 「保存しました」を少しの間出し、公開ページが最新を読み直すための印を同じブラウザに残す（[PG-20](../pages/public/20_EventSite.md) の「表示内容」）
- **アーカイブのギャラリー画像 URL**: 1行に1つの URL を書く欄。入力中は改行や空の行をそのまま残し、欄から離れたとき・保存するときに、前後の空白を取って空の行を除いた URL の一覧にする（2026-10-22 変更。それまでは1文字打つたびに空の行を消していたため、Enter で改行できなかった）
- 項目名と入力欄を結び付けて、項目名を押すと入力欄に移る・読み上げソフトが項目名を読むようにした
