# BD-05 — バッチ処理一覧 (Batch Process List)

## 本システムにおけるバッチ処理

本システム（ei8htplants-site）は **決まった時刻に自動で動く処理（バッチ処理・定時処理）を持たない**。

すべての処理は、ページを開く・フォームを送る・管理画面で操作する、といった操作に応じてその場で行う。

次のことは、以前は手作業だったが今は自動で行う（2026-10-22 に記述を今の動きに合わせた）。

| 内容 | 今の動き |
|---|---|
| イベントを「過去」に分ける | 手でチェックを付ける作業は無い。サーバーがイベント一覧を返すたびに、終了日（無ければ開始日）が今日（日本時間）より前なら「過去」として扱う |
| WS予約の確認メール | 予約を受けたときに自動で送る（キャンセル用のリンク付き）。管理者が「確認済み」にしてから連絡する作業は無い |
| 注文の確認メール・発送のお知らせ | 注文を受けたとき、管理画面で「発送済み」にしたときに自動で送る |
| 予約の確認メールが届かなかったことの記録 | Resend からの知らせ（Webhook）を受けて、予約に「メール未送信」の印を自動で付ける |

## 手で行う運用作業

自動にしていない、管理者が行う作業の記録。

| 作業 | いつ | 担当 | 手順 |
|---|---|---|---|
| お問い合わせへの返信 | お問い合わせを受けたあと | 管理者 | 管理画面の「お問い合わせ」（`/admin/contacts`）で「返信」ボタンを押し、件名と本文を入れて「送信する」。送ると自動で既読になる |
| 注文の発送 | 注文を受けたあと | 管理者 | 商品を送ったら、管理画面の「注文管理」（`/admin/orders`）で状態を「発送済」にする。配送会社と追跡番号（任意）を入れて「発送済みにする」を押すと、購入者に発送のお知らせが届く |
| 「メール未送信」の予約への連絡 | WS予約一覧で「メール未送信」が出たとき | 管理者 | 予約者に別の方法で連絡する（自動で送り直す仕組みは無い） |
| 当日参加の登録 | ワークショップの当日 | 管理者 | 管理画面の「WS予約」（`/admin/reservations`）で「当日参加を追加」を押し、イベント・時間枠・人数を選んで登録する |
| 出店料の支払い | 出店料の支払い期限まで | 管理者 | ダッシュボードの「出店料の支払い」で期限を確かめ、払ったらイベントの管理情報で「支払い済み」にする |
| 手伝いへのワークショップ分の支払い | 支払ったあと | 管理者 | 管理画面の「ワークショップ集計」（`/admin/ws-summary`）で、そのイベントの「支払い済み」にチェックを付ける |
| データベースの変更（マイグレーション） | 新しい版で DB の変更があるとき | 開発担当 | Supabase の SQL エディタで `backend/migrations/` の SQL を実行する（[DD-05 データベース詳細](../02_DD/05_データベース詳細.md) の「マイグレーション管理」） |

## 将来の自動化の候補

今は対象外だが、規模が大きくなったら自動化を考える処理。

| 処理 | 概要 | 優先度 |
|---|---|---|
| 「メール未送信」の予約への送り直し | 届かなかった確認メールを、宛先を直したあとに送り直す | 中 |
| 画像URL有効性チェック | 登録された画像URLが有効か定期的に確認・通知 | 低 |
