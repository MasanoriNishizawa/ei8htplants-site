# PG-13 — CancelReservation

## 概要

ワークショップ予約のキャンセルページ。確定メールに記載されたキャンセルIDを入力して予約をキャンセルする。認証不要。

キャンセルID は、予約を受け付けたときにサーバーが作る推測されにくい文字（英数字と `-` `_` の約22文字。2026-10-22 から）。それより前の予約は8桁の数字で、そのまま使える。

## URL / ルート

`/official/cancel`
`/official/cancel?id={cancel_token}` — メールのリンクからアクセスした場合、IDを自動入力

## 実装ファイル

`frontend/src/pages/CancelReservation.tsx`

- 入力欄は、英数字と `-` `_` の1〜64文字だけを受け付ける（`pattern`・`maxLength`）。入力や貼り付けのときに、それ以外の文字（空白・記号など）は自動で取り除く（2026-10-22 変更。それまでは数字だけ・8桁までだった）
- 入力が空のときはボタンを押せない（薄く表示）

## 状態遷移

| status | 表示内容 |
|---|---|
| `idle` | 初期状態（フォーム表示） |
| `loading` | ボタン disabled、「処理中...」 |
| `done` | 「キャンセルが完了しました」「ご予約のキャンセルを受け付けました。またのご参加をお待ちしております。」 |
| `already` | 「この予約はすでにキャンセル済みです。」（400） |
| `notfound` | 「キャンセルIDが見つかりません。メールをご確認ください。」（404） |
| `limited` | 「送信回数の上限に達しました。しばらく待ってからもう一度お試しください。」（429。2026-10-22 追加） |
| `error` | 「エラーが発生しました。再度お試しください。」（その他・通信の失敗） |

## API

`api.reserve.cancel(token)` → `POST /api/reserve/cancel { token }`（失敗でも例外にせず応答をそのまま返すので、状態コードで表示を分ける）

- `200`: キャンセル成功（2026-10-22 から、応答の中身は `{"ok": true}` だけ。それまではキャンセルした予約の記録をそのまま返していた）
- `400`: すでにキャンセル済み
- `404`: キャンセル ID が存在しない
- `429`: 同じ送り元から短い時間に送りすぎた（1 分間に 5 回まで。キャンセル ID の総当たりを防ぐため）

## キャンセルトークン仕様

- `secrets.token_urlsafe(16)` で作る、英数字と `-` `_` の約22文字（2026-10-22 から。それまでは `secrets.choice(string.digits)` × 8 の8桁の数字。古いトークンもそのまま使える）
- 予約を受け付けたとき（`POST /api/reserve`）に作って保存し、受付メールのキャンセル用リンクに入れる（2026-10-22 に修正。それまでは「管理者が `confirmed` に変更した時点で生成」と書いていた）
- 同じトークンが複数の予約にある場合（古い8桁のトークンが重なったとき）は、最新の未キャンセル予約を対象にする
- 一度作ったら変わらない（状態を変えても新しく作らない）
