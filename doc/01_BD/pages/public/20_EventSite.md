# PG-20 — EventSite（イベントのページ）

**URL**: `/official/events/:id`
**レイアウト**: `Layout`
**機能**: FT-03
**実装ファイル**: `frontend/src/pages/EventSite.tsx`

---

## 画面の目的

イベント1つの詳しいページ。`:id` にはイベントの URL スラッグ（管理画面で入れたもの）か、イベントの ID を入れる。スラッグを先に探し、無ければ ID で探す。中身は管理画面の「イベントサイト編集」（PG-A13）で入れた内容（`page_content`）を使う。

## 使う API

| 操作 | API | ログイン |
|---|---|---|
| イベントを1件読む | `GET /api/events/{スラッグまたはID}` | 不要 |

画面の幅が 700px 以上なら写真（左）と情報（右）の2列、それより狭いと縦に並ぶ。写真が無いイベントは情報だけを出す。

## 表示内容

| 部分 | 出すとき | 内容 |
|---|---|---|
| 写真 | 写真があるとき | 左右のボタン・指でなぞる操作で切り替え。写真を押すと拡大して表示。ワークショップがあるイベントは「Workshop」の印 |
| ブランド | ブランドを選んでいるとき | 押すとそのブランドの Instagram を開く |
| キャッチコピー・サブタイトル・コンセプト | 入れているとき | |
| 会場 | 住所があるとき | 住所・アクセスの説明と Google マップ。住所は、イベントのページの中身に会場の住所（`page_content.venue.address`）が入っていればそれを、無ければイベントの住所（`address`）を出す。トップページ・イベント一覧のカード（`EventPreview`）と同じ決め方（2026-10-22 変更。それまではイベントの住所だけを見ていた） |
| ワークショップ | ワークショップがあるとき | 開催後（過去のイベント、またはアーカイブを有効にしたとき）は「ワークショップを開催しました。ご参加いただいた皆様ありがとうございました。」。開催前で予約が必要なら「ワークショップを予約する」（`/official/reserve?event_id=イベントのID`） |
| ラインナップ・ゲスト・出展者 | 入れているとき | 画像・名前・説明。ゲストは Instagram へのリンク |
| アーカイブ | アーカイブを有効にしたとき | 題名（無ければ「ご来場ありがとうございました」）・メッセージ・写真 |
| シェアボタン | いつも | スラッグがあればスラッグの URL を共有する |

- イベントが無いときは「イベントが見つかりませんでした。」と出る。読み込みに通信の失敗などで失敗したときは「読み込めませんでした。通信状況をご確認のうえ、もう一度お試しください。」と「再読み込み」ボタンを出す
- 管理画面の「サイト」で保存した直後は、古い内容を見せないように、ブラウザに残っている前の結果を使わずに最新の内容を読み直す（2026-10-22 変更）
  - 管理画面は保存したときに、同じブラウザの中に「このイベントは保存し直した」という印（`event_dirty_イベントのID`）を残す。このページは開いたときにこの印を確かめ、あれば最新を読み直して印を消す（1回使ったら消える）
  - 印はイベントの ID で残るので、URL スラッグのアドレス（`/official/events/plant-market-2026` など）で開いたときは、いったん普通に読み、読めたイベントの ID・スラッグの印を確かめてから、あれば読み直す。それまでは ID のアドレスで開いたときしか読み直さなかったため、スラッグのアドレスでは保存前の古い内容が出ることがあった
  - 別のパソコン・スマホ・ブラウザでは印が無いので、この読み直しは起きない
- SNS で共有したときのプレビューには、イベント名・日付と会場・1枚目の写真が出る（[FT-26](../../features/15_検索エンジン・SNS向け情報.md)）

## 写真を読み込めなかったとき（2026-10-23 追加）

写真の URL から画像を読み込めなかったときは、その写真の代わりに、カードと同じ縦横比 3:4 の枠に「写真を読み込めませんでした」（英語表示では「Photo could not be loaded」）と出す。この枠は押しても拡大しない。ほかの写真へは左右のボタン・スワイプで切り替えられる。
