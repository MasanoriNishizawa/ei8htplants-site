# PG-16 — Checkout（ご注文手続き）

**URL**: `/official/checkout`
**レイアウト**: `StoreLayout`
**機能**: FT-13
**実装ファイル**: `frontend/src/pages/Checkout.tsx`

---

## 画面の目的

カートの商品を注文して、カードで支払うページ。お客様情報とお届け先を入れ、Square のカード入力欄でカード情報を入れて「注文を確定する」を押す。検索結果には出さない（noindex）。

## 使う API

| 操作 | API | ログイン |
|---|---|---|
| 最新の在庫を確かめる | `GET /api/products/{id}`（カートの商品ごと） | 不要 |
| 送料を出す | `GET /api/shipping/rate?prefecture=都道府県` | 不要 |
| 注文する（決済） | `POST /api/orders` | 不要 |

## 入力項目

| 項目 | 必須 | 入力できる文字数 | 内容 |
|---|---|---|---|
| お名前 | ○ | 100 文字まで | |
| メールアドレス | ○ | 画面では上限なし（サーバーでメールアドレスの形かを確かめる） | 確認メールの宛先 |
| 電話番号 | — | 30 文字まで | |
| 郵便番号 | ○ | 10 文字まで | |
| 都道府県 | ○ | 選ぶ | 選ぶと送料（¥1,000〜¥1,800）を読み込み、合計に入れる |
| 市区町村 | ○ | 100 文字まで | |
| 番地・建物名 | ○ | 200 文字まで | |
| 建物名・部屋番号 | — | 200 文字まで | |
| 備考 | — | 2,000 文字まで | |
| カード情報 | ○ | — | Square のカード入力欄に入れる（カード番号はこのサイトには届かない） |

- 入力できる文字数は、サーバーの入力チェック（`backend/app/routes/orders.py` の上限）と同じ値。入力欄の時点でそれ以上打てないようにし、送ってから「入力内容に誤りがあります」となるのを防ぐ（2026-10-23 追加。値は `frontend/src/lib/constants.ts` の `INPUT_MAX_LENGTH`。サーバーの上限を変えるときはここも合わせる）
- サーバー側の上限の正確な値は [DD-06 API仕様](../../../02_DD/06_API仕様.md) の「Orders」

## 動き

1. 開いたとき（1回だけ）、カートの商品ごとに最新の情報を取り直し、カートを最新の値段・在庫に置き換えて、次の案内を出す（2026-10-23 に「販売終了」「確認できなかった」を追加）

   | こんなとき | 案内（日本語表示） |
   |---|---|
   | 在庫が 0 | 「商品名」は売り切れのためカートから削除しました |
   | 商品が削除された（取り直しで 404） | 「商品名」は販売を終了したためカートから削除しました（カートから外す） |
   | 通信の失敗などで取り直せなかった | 「商品名」の最新の在庫・価格を確認できませんでした。通信状況をご確認のうえ、ページを再読み込みしてください（カートには残す） |
   | 在庫が数量より少ない | 「商品名」の在庫がN点になりました（数量を変更しました） |
   | 値段が変わった | 「商品名」の価格が ¥◯ から ¥◯ に変わりました。合計は新しい価格で計算しています |

   案内は、言語を切り替えるとその言語で出し直す
2. Square のカード入力欄を読み込む。10秒で読み込めなければ「カード入力フォームの読み込みがタイムアウトしました。ページを再読み込みしてください。」。自分の PC（localhost）では「Square決済はlocalhostでは動作しません。…」と出て決済できない
3. 「注文を確定する」で、カード情報を Square に預けて代わりの合言葉（トークン）を受け取り、`POST /api/orders` に注文を送る。処理中は「処理中...」
4. 成功したらカートを空にして、注文完了（[PG-17](17_OrderComplete.md)）へ移る。失敗したら、下の表の文言を出す（2026-10-23 変更。それまではサーバーの返した文字をそのまま出していたため、入力の誤りのときに英語の開発者向けの文字が出ることがあった）

### 注文に失敗したときの文言（2026-10-23 追加）

| サーバーの答え | 日本語表示で出す文言 |
|---|---|
| 422（入力の形が違う・長すぎる） | 入力内容を確かめてください。お名前・メールアドレス・電話番号・ご住所・備考に誤りや長すぎる項目がないかご確認ください。 |
| 402（カードの決済ができなかった） | カードの決済ができませんでした。カード情報をご確認いただくか、別のカードをお試しください。（Square の説明があれば後ろに括弧で添える） |
| 400・404・409（購入できない商品・商品が無い・在庫不足） | サーバーの日本語の説明をそのまま出す（例「在庫が不足しています: 商品名」「この商品は現在購入できません: 商品名」）。説明が無ければ「ご注文の内容に購入できない商品やお届け先が含まれています。」「商品が見つかりません。カートの内容をご確認ください。」「在庫が不足しています。カートの数量をご確認ください。」 |
| 429（送りすぎ） | 送信回数の上限に達しました。しばらく待ってからもう一度お試しください。 |
| 500 で、説明に「お支払いは完了」が入っている | サーバーの説明（「注文処理中にエラーが発生しました。お支払いは完了しています。お問い合わせページよりご連絡ください。」）。お金は払われているので、もう一度注文せずに連絡してもらう |
| 500（それ以外） | ただいまご注文を受け付けられません。時間をおいて再度お試しください。 |
| 502 で、説明に「確認できませんでした」が入っている | サーバーの説明（「決済の結果を確認できませんでした。二重のお支払いを防ぐため、再度ご注文される前にお問い合わせページよりご連絡ください。」）。払われたか分からないので、二重払いを防ぐため注文し直さずに連絡してもらう |
| 502（それ以外。決済サービスにつながらないなど。お金は払われていない） | サーバーの説明。無ければ「決済サービスでエラーが発生しました。時間をおいて再度お試しください。」 |
| そのほか・通信の失敗 | 注文処理に失敗しました。もう一度お試しください。 |

- 英語表示では、状態コードごとに決めた英語の文を出す（サーバーの説明は日本語なので使わない。402 の Square の説明だけは英語なので添える）
- **注意**: 500・502 の出し分けは、サーバーの説明に「お支払いは完了」「確認できませんでした」の文字が入っているかで決めている。`backend/app/routes/orders.py` のこの2つの文言を変えるときは、画面（`frontend/src/pages/Checkout.tsx` の `orderErrorMessage`）も合わせて直すこと。合わないと「払われたのに払われていない」ような案内になり、二重払いにつながる

- カートが空のときは「カートに商品がありません。」と出る
- 都道府県を選ぶまでは送料と合計は「—」
- 決済は「注文を確定する」を押したときに行う。キャンセル・返品は受け付けない旨（不良・破損のときだけ到着後7日以内に連絡）を画面に出している
