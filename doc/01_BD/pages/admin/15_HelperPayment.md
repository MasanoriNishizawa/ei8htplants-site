# PG-A15 — 支払い集計（Admin）

## 概要

手伝いの人に払う金額を年度ごとにまとめる画面（サイドメニューの「収支」の下の「支払い集計」）。手伝いありのイベントの売上の取り分（ワークショップの売上を除く）を、年度（4月〜翌年3月）ごとに合計し、12で割った金額を次の年度の毎月の支払い額として出す。見るだけの画面で、入力する欄は無い。

## URL / ルート

`/admin/helper-payment`（サイドメニューから開く。ログインが必要）

## 実装ファイル

`frontend/src/pages/admin/AdminHelperPayment.tsx`

## 画面レイアウト（スマホ）

左のメニューは「☰」で開く（管理画面共通）。中身は次のように縦に並ぶ。

```
┌────────────────────────────┐
│ 支払い集計                 │
│ （説明文）                 │
│                            │
│ 2026年度（2026/4〜2027/3） │
│ ┌────────────────────────┐ │
│ │ イベントA  2026-05-03  │ │
│ │             12,000 円  │ │
│ └────────────────────────┘ │
│ [年間合計 20,400 円]       │
│ [2027年度 月額支払い]      │
│ [1,700 円/月]              │
└────────────────────────────┘
```

## 表示内容と計算

| 項目 | 内容 |
|---|---|
| 対象のイベント | 過去のイベント（終了したイベント）のうち、収支の「手伝いの支払いあり」（`payment_flag`）に印があるもの。開催前・開催中のイベントはまだ入らない |
| 年度 | 開始日が4月〜12月ならその年、1月〜3月なら前の年の年度 |
| イベントごとの金額 | 売上の取り分（`salesShare`）。（売上 − ワークショップの売上（参加人数 × 1,000円）− 支出）× 20%（四捨五入）。マイナスになったときもそのまま入る |
| 年間合計 | その年度のイベントの金額の合計 |
| 月額支払い | 年間合計 ÷ 12（四捨五入）。次の年度の毎月の支払い額 |

- 年度は新しい順、年度の中のイベントは開催日の古い順に並ぶ
- 対象のイベントが無いときは「手伝いありのイベントがありません。」と出る
- 読み込みに失敗したときは、表の代わりに赤い枠で「データの読み込みに失敗しました（理由）」とだけ出す（「手伝いありのイベントがありません。」とは出さない。2026-10-22 追加。それまでは失敗しても何も出ず、イベントが無いように見えた）。（理由）の部分には、ログインの期限切れ・見つからない・入力の誤りなどのわけが入る（[DD-07 エラーハンドリング](../../../02_DD/07_エラーハンドリング.md) の「管理画面の失敗の文言」）
- 計算のしかたは [PG-A14 全体の収支](11_Finances.md) の「computeFinances の仕様」と同じ。ワークショップ分の支払いは [PG-A16 ワークショップ集計](16_WsSummary.md) で別に管理する
