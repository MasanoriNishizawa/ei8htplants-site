# PG-A02 — イベント管理（Admin）

## 概要

イベントの一覧表示・追加・編集・削除を行う管理画面。一覧と作成/編集フォームの2つのビューで構成される。

## URL / ルート

| ビュー | URL |
|---|---|
| 一覧 | `/admin/events` |
| 新規作成フォーム | `/admin/events/new` |
| 編集フォーム | `/admin/events/:id/edit` |
| 管理情報の確認画面 | `/admin/events/:id/admin-info`（2026-10-16 追加） |
| 管理情報の編集画面 | `/admin/events/:id/admin-info/edit`（2026-10-16 に URL を変更。それまでは `/admin/events/:id/admin-info` が編集画面だった） |
| 画像ダウンロード | `/admin/events/:id/images`（2026-10-16 追加） |

## 画面レイアウト — 一覧

```
┌─────────────────────────────────────┐
│ イベント管理     [+ 新規追加]       │
├─────────────────────────────────────┤
│ ┌───────────────────────────────┐   │
│ │ イベント名                    │   │
│ │ 2024-05-01 〜 2024-05-03      │   │
│ │ / 会場名                      │   │
│ │ [編集][管理情報][画像DL][収支]│   │
│ │ [サイト][予約N件]             │   │
│ │ [予約管理（印刷・CSV）]       │   │
│ │ [複製][削除]                  │   │
│ └───────────────────────────────┘   │
│ ┌───────────────────────────────┐   │
│ │ ...                           │   │
│ └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

- 複数日開催は `start_date 〜 end_date` 形式で表示（同日の場合は start_date のみ）
- 収支合計・各イベントの収支金額は一覧に表示しない（`/admin/finances` に集約）
- 各行のボタンは左から「編集」「管理情報」「画像DL」「収支」「サイト」「予約」「予約管理（印刷・CSV）」（この2つはワークショップありのイベントのみ）「複製」「削除」の順に並ぶ。画面幅が狭いときは折り返す
- 「予約」ボタンは、WS予約一覧（`/admin/reservations`）をこのイベントで絞り込んで開く。キャンセル以外の予約があれば「予約 N件」と件数を出し、背景が薄い緑になる
- 「予約管理（印刷・CSV）」ボタン（2026-10-22 追加）は、このイベントだけの予約画面（`/admin/events/:id/reservations`）を開く。時間枠での絞り込み・状態の変更・印刷・CSV の書き出し・当日参加の追加ができる（[FT-11 予約ステータス管理](../../features/11_予約ステータス管理.md) の「EventReservations 固有機能」）。その画面の「← イベント管理」でこの一覧に戻る。それまでこの画面へはイベント一覧から開くボタンが無かった
- 「複製」「削除」は、どちらかを処理している間は全部の行で押せない（薄く表示する）。読み込み・複製・削除に失敗したときは、一覧の上に赤い枠で「イベントの読み込みに失敗しました（理由）」などと出す
- 「画像DL」ボタン（2026-10-16 追加）を押すと、そのイベントの画像ダウンロード画面（`/admin/events/:id/images`）が開く。画面の「← 戻る」でイベント一覧に戻る

- 「予約必要」と「WSセッション」は「ワークショップあり」に印を付けたときだけ出る
- **URL スラッグの自動入力**（2026-10-22 変更）
  - 新規作成では、イベント名を打つたびに、名前からスラッグを作り直して入れる（英小文字・数字・ハイフンだけが残るので、日本語だけの名前では空のまま）
  - スラッグの欄を自分で書き換えると、それ以後はイベント名を変えてもスラッグは変わらない
  - 「自動生成」ボタン（イベント名が入っているときだけ出る）を押すと、名前からスラッグを作り直し、以後はまた名前に合わせて変わる
  - 既存のイベントを編集するときは、スラッグが入っていれば名前を変えてもスラッグは変わらない（公開中のアドレスが勝手に変わらないようにするため）。スラッグが空のイベントは、名前を変えると名前から作る
  - それまでは、スラッグが空のときだけ名前から作っていたため、名前を1文字打った時点のスラッグで止まることがあった
- 画像は「+ 追加」の枠からファイルを選ぶ（URL を入れる欄は無い）
- 開催予定か過去かは、終了日（無ければ開始日）から自動で決まるので、チェック欄は無い
- 項目の意味と保存の流れは [FT-12 イベント管理](../../features/12_イベント管理.md) の「フォーム状態」
- 編集モード（既存イベントの編集）時のみ、フォーム下部に「管理情報を編集」ボタンが表示される
- このボタンを押すと管理情報の確認画面（`/admin/events/:id/admin-info`）が開く（2026-10-16 変更。それまでは編集画面が直接開いた）。確認画面の「← 戻る」でこのイベント編集画面に戻る

## 管理情報の画面の流れ（2026-10-16 変更）

管理情報は「確認画面」と「編集画面」の2つに分かれている。いつもは確認画面で内容を見て、直したいときだけ「編集」ボタンで編集画面を開く。

```
イベント一覧の「管理情報」ボタン
（またはイベント編集画面の「管理情報を編集」）
    ↓
確認画面（/admin/events/:id/admin-info）
    ↓ 「編集」ボタン
編集画面（/admin/events/:id/admin-info/edit）
    ↓ 「保存する」ボタン（保存に成功したとき）
確認画面（上部に「保存しました」を3秒間表示）
```

- 確認画面の「← 戻る」は、確認画面を開く前の画面（イベント一覧、またはイベント編集画面）に戻る。編集画面を開いて保存した後や、編集画面から戻ってきた後でも、行き先は変わらない。前の画面が分からないとき（URL を直接開いたときなど）はイベント一覧に戻る
- 編集画面の「← 戻る」は確認画面に戻る（保存していない変更があるときは確認が出る。下記）
- ブラウザの「戻る」ボタンの動き: 確認画面 → 編集画面 → 保存（または画面内の「← 戻る」）で確認画面に戻った後、ブラウザの「戻る」を押すと、1回目は1つ前の確認画面、2回目でイベント一覧（イベント編集画面から開いた場合はイベント編集画面）に戻る。画面内の「← 戻る」は履歴をさかのぼるのではなく、確認画面を開く前の画面へ直接移るので、1回でイベント一覧（イベント編集画面から開いた場合はイベント編集画面）に戻る

│   搬入日時                          │
│   2026年10月24日（土） 09:00        │
│   搬出日時                          │
│   未入力                            │
├─────────────────────────────────────┤
│ 宿泊                                │
│   ホテル名                          │
│   〇〇ホテル                        │
│   宿泊料金                          │
│   14,000円（収支から）              │
├─────────────────────────────────────┤
│ 出店料                              │
│   出店料                            │
│   20,000円                          │
│   支払い方法                        │
│   事前振込                          │
│   支払い期限                        │

│   要項の文章                        │

- 見出しの下に、イベント名と開催期間（曜日つき。1日だけのイベントは開始日だけ）を表示する
- 「編集」ボタンは見出しの右と、画面のいちばん下の2か所にある。どちらを押しても編集画面が開く。画面の幅が足りないときは、見出しの右のボタンは見出しの下に回る
- 各項目は、パソコンなど幅が広い画面では「項目名」と「値」が横に並び、スマホなど幅が狭い画面では項目名の下に値が並ぶ
- 何も入力されていない項目（空白や改行だけが入っているものも含む）は、薄い文字で「未入力」と表示する
- 管理情報が1つも登録されていないときは、各カードの上に「まだ管理情報が登録されていません。「編集」ボタンから搬入・搬出、宿泊、出店料などを登録できます。」と表示する
- 読み込みに失敗したときは「管理情報の読み込みに失敗しました。ページを再読み込みしてください。」と赤い枠で表示する。このときも下の「編集」ボタンは表示される

### 各項目の表示のしかた

| カード | 項目 | 表示のしかた |
|---|---|---|
| 搬入・搬出 | 搬入日時・搬出日時 | 曜日つきの日時（例: 「2026年10月24日（土） 09:00」） |
| 宿泊 | ホテル名 | 入力した文字のまま |
| 宿泊 | 宿泊料金 | 3桁ごとに区切った金額（例: 「14,000円」） |
| 出店料 | 出店料 | 3桁ごとに区切った金額 |
| 出店料 | 支払い方法 | 選んだ方法（当日現金・事前振込・その他） |
| 出店料 | 支払い期限 | 曜日つきの日付（例: 「2026年10月9日（金）」） |
| 出店料 | 支払い状況 | 色つきの札（バッジ）で表示する（下記） |
| 出店要項 | 要項の文章 | 入力した文章を、改行もそのままに表示する |
| 出店要項 | 要項の画像 | 小さな正方形の画像（サムネイル）を並べる。押すと画面いっぱいに拡大表示される（拡大表示の操作は編集画面と同じ。下の「画像の拡大表示」を参照） |
| メモ | メモ | 入力した文章を、改行もそのままに表示する |

**支払い状況の札**

- 「支払い済み」にチェックが入っていれば、緑の「支払い済み」
- チェックが入っていなければ、赤の「未払い」
- 未払いで、支払い期限を過ぎているときは、「未払い」の横に赤く塗った「期限切れ」も表示する。期限の当日はまだ「期限切れ」にしない（翌日から表示する）。日付はスマホ・パソコンの時計の日付で判断する
- 出店料（収支から補う金額も含む）・支払い方法・支払い期限がどれも未入力で、「支払い済み」にもチェックがないときは、札を出さずに「未入力」と表示する

**収支から補う金額**

- 管理情報の「出店料」「宿泊料金」が未入力で、そのイベントの収支に 0 以外の出店料・宿泊費が入っているときは、収支の金額を表示し、後ろに小さく「（収支から）」と添える
- これは編集画面を開いたときに入力欄へ最初に入る値と同じ決め方。編集画面で保存すると、その金額が管理情報にも保存される
- 収支が読み込めなかったときは、補わずに「未入力」と表示する（画面そのものは表示される）

### 保存していない変更の確認（2026-10-16 追加）

- 画面を開いたときから入力欄の内容を変えて、まだ保存していない間は、「保存する」ボタンの横に「未保存の変更があります」と表示する。対象はすべての入力欄（搬入・搬出、宿泊、出店料、支払い済みのチェック、出店要項の文章・画像の追加と削除、メモ）。搬入・搬出は日付だけ入れた途中の状態も変更として扱う。いったん変えた入力を元の値に戻すと、表示は消える
- この状態で「← 戻る」を押すと「保存していない変更があります。破棄して移動しますか？」（2026-10-23 にほかの画面とそろえた。それまでは「…破棄して戻りますか？」）と確認が出る。「OK」で変更を捨てて確認画面に戻り、「キャンセル」で編集画面に留まる
- この状態でページを再読み込みしたり、タブ・ブラウザを閉じようとしたりすると、ブラウザの確認が出る（文言はブラウザが決める）
- この状態で左のメニュー（サイドメニュー。スマホでは左上のメニューボタンで開くメニュー）のリンクや「ログアウト」を押すと、「保存していない変更があります。破棄して移動しますか？」と確認が出る（2026-10-21 追加。それまでは確認なしで移動し、入力が消えていた）
  - 「OK」: 変更を捨てて、押したページへ移る（ログアウトのときはログアウトする）
  - 「キャンセル」: 移動しない。編集画面と入力した内容はそのまま残る。スマホのメニューも開いたまま
  - 次のときは確認を出さない（今の画面が残り、入力が消えないため）
    - 「分析 ↗」を押したとき（新しいタブで開く）
    - 今いる画面と同じメニューを押したとき
    - Ctrl（Mac では Command）・Shift などのキーを押しながらクリックしたとき、ホイールボタンでクリックしたとき（新しいタブ・ウィンドウで開く操作）
- 注意: ブラウザの「戻る」ボタンで離れるときは、今も確認は出ない（入力は消える）。保存していない変更は消えるので、先に「保存する」を押すこと
- 画面を開いたときの読み込みに失敗した場合は、この確認は出ない
- 読み込み・保存に失敗した場合は画面上部に赤いバナーでエラーメッセージを表示する
- 画面を開いたときの読み込み（イベント・管理情報・収支）が1つでも失敗した場合は、「保存する」ボタンが薄く表示され、押せなくなる（2026-10-16 追加）。何も入っていない状態のまま保存して、登録済みの管理情報（搬入・宿泊・出店要項など）や収支を空の値で消してしまうのを防ぐため。この状態で何か入力しても押せないままなので、ページを再読み込みしてやり直す
- 保存すると、収支の出店料・宿泊費もこの画面の出店料・宿泊料金に合わせて保存される（空欄なら 0）。収支のほかの内容（売上など）は、保存する直前の最新の内容がそのまま残る（2026-10-16 変更。それまでは画面を開いた時点の収支で丸ごと上書きしていたため、その後に収支画面で保存した売上などが消えることがあった）
- 「保存に失敗しました」と出たときは、もう一度「保存する」を押せばよい（管理情報は保存済みで、収支への反映だけ失敗している場合がある）
- 搬入日時・搬出日時は「日付」「時」「分」の3つの入力欄に分かれている。画面幅が狭いときは、日付の下に時・分がまとまって折り返す。時・分の選択欄は指で押しやすいよう高さ 44px 以上にしている

### 出店要項（2026-10-16 追加）

主催者から届いた出店要項（出店のルール・注意事項など）を、文章と画像でイベントごとに保管する欄。「メモ」欄のすぐ上にある。

- **要項の文章**: 主催者から届いた要項の本文を貼り付ける欄
- **要項の画像**: 画像を何枚でも登録できる
  - 「画像を追加」ボタンを押すと画像を選ぶ画面が開く。複数枚をまとめて選べる
  - 使える画像は JPEG・PNG・WebP・GIF で、1枚 10MB まで
  - 選んだ画像は1枚ずつ順番にアップロードされ、ボタンに「アップロード中...（2/5）」のように進み具合が表示される
  - アップロードできなかった画像があると「次の画像をアップロードできませんでした: （ファイル名）（JPEG・PNG・WebP・GIF、10MB まで）」と表示される。うまくいった画像はそのまま残る
  - アップロード中は「画像を追加」ボタン・「保存する」ボタン・各画像の「削除」ボタンは押せない
  - 登録した画像は小さな正方形の一覧（サムネイル）で並ぶ。各画像の下の「削除」ボタンを押すと確認が出て、「OK」で一覧から外れる
  - サムネイルを押すと、画面いっぱいに拡大表示される（下記）
- **保存について**: 画像の追加・削除は「保存する」ボタンを押したときに確定する。追加・削除したあと保存していない間は、保存ボタンの横に「未保存の変更があります」と表示される（ほかの入力欄の変更と同じ。上の「保存していない変更の確認」を参照）。保存せずに画面を離れると、追加・削除はなかったことになる
  - 「削除」で一覧から外した画像のファイル自体は保存場所（Supabase Storage）からは消えない

#### 画像の拡大表示

- 画面全体が暗くなり、画像が画面に収まる大きさで表示される
- 画像が2枚以上のときは、上部に「2 / 5」のように何枚目かが表示され、下部の「← 前へ」「次へ →」ボタンで切り替えられる（キーボードの左右の矢印キーでも切り替え可能）。最初の画像では「前へ」、最後の画像では「次へ」は押しても何も起きない
- 閉じるには、右上の「閉じる」ボタンを押す・画像の外側の暗い部分を押す・キーボードの Esc キーを押す、のいずれか
- 拡大表示中は後ろの画面がスクロールしない

## 収支入力画面（EventFinance）での保存の制限（2026-10-16 追加）

イベント一覧の「収支」ボタンから開く収支入力画面（`/admin/events/:id/finances`）も、管理情報の編集画面と同じ考え方で保存を制限している。

- 画面を開いたときの読み込み（イベント・収支・予約・管理情報）が1つでも失敗した場合は、「保存する」ボタンが薄く表示され、押せなくなる。画面上部には「データの読み込みに失敗しました。ページを再読み込みしてください。」と表示される
- 何も入っていない状態（金額が 0 など）のまま保存して、登録済みの収支や管理情報を上書きしてしまうのを防ぐため
- 保存すると、収支の出店料・宿泊費が管理情報にも書き込まれる。管理情報のほかの内容（搬入・宿泊・出店要項など）は、保存する直前の最新の内容がそのまま残る（2026-10-16 変更。それまでは画面を開いた時点の管理情報で上書きしていたため、その後に管理情報の編集画面で保存した搬入・出店要項などが消えることがあった）
- 「保存に失敗しました」と出たときは画面に留まるので、もう一度保存ボタンを押せばよい（収支は保存済みで、管理情報への反映だけ失敗している場合がある）
- 注意: 収支入力画面と管理情報の編集画面を同時に開いたまま、別々に保存すると、出店料・宿泊費は最後に保存した画面の値になる（ほかの項目は消えない）。両方を同時に開いて編集しないようにする

## 画面レイアウト — 画像ダウンロード（EventImages、2026-10-16 追加）

イベントに登録されている画像を、出どころ（どこに登録された画像か）ごとに一覧表示し、1枚ずつパソコンやスマホに保存するための画面。SNS 投稿用などに画像を手元に集めたいときに使う。イベント一覧の各行にある「画像DL」ボタンから開く。

```
┌─────────────────────────────────────┐
│ ← 戻る                              │
│ 画像ダウンロード                    │
│ イベント名 — 開始日                 │
│ 全 N 枚                             │
├─────────────────────────────────────┤
│ イベント画像  3 枚                  │
│ ┌──────┐ ┌──────┐ ┌──────┐          │
│ │ 画像 │ │ 画像 │ │ 画像 │          │
│ └──────┘ └──────┘ └──────┘          │
│  01       02       03               │
│ [ダウン] [ダウン] [ダウン]          │
│ [ロード] [ロード] [ロード]          │
├─────────────────────────────────────┤
│ イベントサイト：ラインナップ  2 枚  │
│  04 商品名   05 商品名              │
│  ...                                │
└─────────────────────────────────────┘
```

- 画像は次の順にグループ分けして表示する。グループ見出しの横にそのグループの枚数が出る

| 表示順 | グループ名 | 画像の出どころ | 画像の下に出る補足 |
|---|---|---|---|
| 1 | イベント画像 | イベント編集画面で登録した画像（表示順どおり） | なし |
| 2 | イベントサイト：メイン画像 | イベントサイト編集画面のメイン画像 | なし |
| 3 | イベントサイト：ラインナップ | イベントサイトのラインナップの各画像 | ラインナップのタイトル |
| 4 | イベントサイト：ゲスト | イベントサイトのゲストの各画像 | ゲストの名前 |
| 5 | イベントサイト：アーカイブ | イベントサイトのアーカイブ（過去の様子）の画像 | なし |
| 6 | 管理情報：出店要項 | 管理情報の編集画面の「出店要項」に登録した画像 | なし |

- 同じ画像が複数のグループに登録されている場合は、上のほうのグループにだけ表示する（2回出さない）
- 画像が1枚もないグループは表示しない。どのグループにも画像がないときは「このイベントには画像が登録されていません」と表示する
- 画像には、グループをまたいで 01・02・03… と通し番号が付く
- 「ダウンロード」ボタンを押すと、その1枚が保存される。保存中はボタンが「保存中...」になる
  - 保存されるファイル名は「イベント名_通し番号（2桁）.拡張子」（例: `春の植物市_03.jpg`）。イベント名にファイル名に使えない文字（`\ / : * ? " < > |` と改行）が含まれるときは `_` に置き換える
  - 拡張子は画像の URL から取る。取れないときは画像の種類から決め、それでも分からなければ `jpg` にする
- 保存に失敗したときは、その画像の下に「ダウンロードに失敗しました。元画像を開くから保存してください。」と表示される。「元画像を開く」を押すと画像が新しいタブで開くので、そこから手動で保存する
- 画像（サムネイル）そのものを押すと、元の画像が新しいタブで開く
- 管理情報が読み込めなかったときは、「管理情報：出店要項」のグループだけ表示されない（ほかのグループは表示される）
- イベントそのものが読み込めなかったときは「イベントの読み込みに失敗しました。」と赤い枠で表示する
- 画像は横に並べ、画面幅に合わせて折り返す（スマホでも横にはみ出さない）

## イベントの追加・編集・収支・サイト編集での保存していない変更の確認（2026-10-23 追加）

管理情報の編集画面と同じく、次の画面でも、入力を変えてまだ保存していないときに確認が出る（文言は「保存していない変更があります。破棄して移動しますか？」）。

| 画面 | 変更とみなすもの | 確認が出る画面の中の操作 |
|---|---|---|
| イベントの追加・編集（EventForm） | 入力欄・写真・WS セッション・日ごとの開催時間（新規は空のフォーム、編集は読み込み直後の内容と比べる） | **[キャンセル]**、**[管理情報を編集]** |
| 収支の入力（EventFinance） | すべての入力欄（読み込み直後の内容と比べる） | 左上の **[← 収支一覧]**・**[← イベント管理]** |
| イベントサイト編集（AdminEventSite） | すべての入力欄とギャラリー画像 URL の欄（読み込み直後・保存した直後の内容と比べる） | （画面の中に戻るリンクは無い） |

- どの画面でも、サイドメニュー・ログアウト・ページの再読み込み・タブを閉じるときに確認が出る
- 保存に成功したあとは出ない（イベント・収支は保存すると前の画面へ移る。サイト編集は保存した内容を新しい基準にする）
- 読み込みの前・読み込みに失敗したときは、変更なしとして扱う
- 収支の入力画面の単位（円・人・km）は幅をそろえ、入力欄の右端がそろうようにした（2026-10-23）
