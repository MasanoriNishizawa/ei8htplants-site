# BD-01 — システム構成 (System Architecture)

## 1. アーキテクチャ概要

```
ブラウザ (React SPA)
    │
    │  /api/* → HTTP
    │
    ├── [開発時] Vite dev server (port 5173)
    │               │ proxy /api → localhost:8000
    │               ▼
    └── [本番時] ─── FastAPI (uvicorn, port 8000)
                         │
                         ├── Supabase (PostgreSQL + Auth + RLS)
                         │       ← データ読み書き・管理者認証
                         │
                         └── Resend API
                                 ← メール送信（お問い合わせ受信時）
```

**開発時**: Vite dev server + uvicorn の2プロセス構成。Vite の proxy 設定で `/api` をバックエンドに転送。  
**本番時**: `npm run build` でビルドしたSPAを FastAPI の `StaticFiles` で配信。単一プロセス。

### 分析ダッシュボード（2026-10-17 追加）

サイト本体とは別に、売上・収支・予約などをグラフで見るための「分析ダッシュボード」を Render の別のサービスとして動かしている。管理画面の左のメニュー「分析 ↗」を押すと、新しいタブで開く。

```
ブラウザ（管理画面のメニュー「分析 ↗」から新しいタブで開く）
    │
    │  https://ei8htplants-analytics.onrender.com
    ▼
分析ダッシュボード（Streamlit。Render の別サービス。analytics/ フォルダ）
    │
    ├── Supabase Auth
    │       ← ログイン（管理画面と同じメールアドレス・パスワード）
    │
    ├── Supabase（PostgreSQL）
    │       ← データの読み取りだけ（書き込み・削除はしない）
    │
    └── Google アナリティクス 4（任意）
            ← アクセス数の読み取りだけ（アクセス解析の画面）
```

- サイト本体とは別のサービスなので、分析ダッシュボードが止まってもサイト・管理画面には影響しない
- 画面・ログイン・データの扱いは [FT-25 分析ダッシュボード](features/14_分析ダッシュボード.md)、公開の手順は [OP-04 分析ダッシュボードの公開手順](../05_OP/04_分析ダッシュボードの公開手順.md) を参照

## 4. 環境変数

### `frontend/.env`

| 変数名 | 公開 | 説明 |
|---|---|---|
| `VITE_SUPABASE_URL` | フロントエンドに公開される | Supabase プロジェクトURL |
| `VITE_SUPABASE_ANON_KEY` | フロントエンドに公開される（安全） | Supabase 匿名キー（RLSで保護） |

### `backend/.env`

| 変数名 | 公開 | 説明 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 非公開 | Supabase プロジェクトURL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 非公開 | 匿名キー（公開読み取り用） |
| `SUPABASE_SERVICE_ROLE_KEY` | **絶対に非公開** | サービスロールキー（RLSバイパス・管理用） |
| `RESEND_API_KEY` | **絶対に非公開** | Resend APIキー |
| `GEMINI_API_KEY` | **絶対に非公開** | Google AI Studio APIキー（AIチャット機能） |
| `CONTACT_TO_EMAIL` | 非公開 | お問い合わせ受信メールアドレス |
| `CONTACT_FROM_EMAIL` | 非公開 | お問い合わせ送信元メールアドレス |

### 分析ダッシュボード（2026-10-17 追加）

ローカルではリポジトリ直下の `.env` から読む。Render では、分析ダッシュボードのサービスの Environment に設定する（値は設計書に書かない）。

| 変数名 | 必須 | 公開 | 説明 |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 必須 | 非公開 | Supabase プロジェクトURL（ログインとデータの読み取り） |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 必須 | 非公開 | 匿名キー。ログイン（Supabase Auth）だけに使う |
| `SUPABASE_SERVICE_ROLE_KEY` | 必須 | **絶対に非公開** | データの読み取り（GET だけ）に使う。ログインには使わない |
| `ANALYTICS_ALLOWED_EMAILS` | 推奨（実質必須） | 非公開 | 見てよい人のメールアドレス（カンマ区切り、大文字小文字は区別しない）。未設定なら Supabase にログインできる人は全員見られる。Supabase で新規登録ができる設定だと、第三者が登録して見られてしまうため、必ず設定する |
| `PYTHON_VERSION` | 推奨 | 非公開 | `3.12.9`（Render が使う Python のバージョン。`analytics/.python-version` と同じ値を念のため入れる） |
| `GA_PROPERTY_ID` | 任意 | 非公開 | GA4 のプロパティ ID（数字。測定 ID の `G-…` ではない） |
| `GA_CREDENTIALS` | 任意 | 非公開 | GA4 の読み取り用の鍵ファイルの場所。Render では Secret Files に置いた鍵ファイルのパス（`/etc/secrets/<ファイル名>`） |

> **重要**: `.env` ファイルは `.gitignore` で管理。リポジトリに絶対にコミットしないこと。

## 5. デプロイ手順（概要）

```
1. フロントエンドビルド
   cd frontend && npm run build
   → frontend/dist/ に成果物生成

2. 環境変数設定
   backend/.env に本番の接続情報を設定

3. サーバー起動
   cd backend && uvicorn app.main:app --host 0.0.0.0 --port 8000

4. DB マイグレーション（初回のみ）
   Supabase SQL エディタで backend/migrations/002_admin_features.sql を実行
```

分析ダッシュボードは、サイト本体とは別の Render のサービスとして作る。作り方は [OP-04 分析ダッシュボードの公開手順](../05_OP/04_分析ダッシュボードの公開手順.md) を参照（2026-10-17 追加）。

## 6. 管理者認証フロー

```
/admin アクセス
    │
    ├── AdminLayout: supabase.auth.getSession() 実行
    │       │
    │       ├── session あり → Admin UI 表示
    │       └── session なし → ログインフォーム表示
    │                               │
    │               メール + パスワード入力
    │                               │
    │           supabase.auth.signInWithPassword()
    │                               │
    │               ├── 成功 → セッション確立 → Admin UI
    │               └── 失敗 → エラーメッセージ表示

バックエンドAPI（Admin操作）:
    SUPABASE_SERVICE_ROLE_KEY で admin_supabase を生成 → RLS バイパス
    ※ バックエンドAPIへのリクエスト認証は現フェーズ未実装
```

分析ダッシュボードのログイン（2026-10-17 追加）は、管理画面と同じアカウントを使うが、管理画面のログイン状態は引き継がない（別のサービスのため、開いたら改めてログインする）。詳しくは [FT-25 分析ダッシュボード](features/14_分析ダッシュボード.md) の「ログイン」を参照。
