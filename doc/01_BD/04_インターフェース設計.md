## 2. Supabase 連携

### 接続方式

```
バックエンド (supabase-py 2.16.0)
    ├── supabase      = create_client(URL, ANON_KEY)
    │       役割: 公開データの読み取り（anon role, RLS 適用）
    └── admin_supabase = create_client(URL, SERVICE_ROLE_KEY)
            役割: 全データの読み書き（service_role, RLS バイパス）

フロントエンド (@supabase/supabase-js 2.49.8)
    └── createClient(URL, ANON_KEY)
            役割: Supabase Auth のみ（Admin認証・セッショントークン取得）
            ※ データ読み書きにはフロントエンドから直接 Supabase を呼ばない
```

### データフロー

```
公開ページのデータ取得:
    ブラウザ → /api/* → FastAPI → supabase (anon) または admin_supabase → Supabase DB
    ※ 記事・商品・Q&A など、一部の公開 API も admin_supabase で読む（表は DD-06 API仕様）

管理画面の書き込み:
    ブラウザ → /api/* → FastAPI → admin_supabase (service_role) → Supabase DB

Admin認証:
    ブラウザ → @supabase/supabase-js → Supabase Auth （直接通信）

画像・動画のアップロード:
    ブラウザ → POST /api/upload または /api/upload/video（multipart/form-data + Bearer JWT）
             → FastAPI → admin_supabase.storage.from_('images' または 'videos').upload()
             → Supabase Storage
             → 返却: { "url": "https://...supabase.co/storage/v1/object/public/..." }
```

### Supabase Auth

| 項目 | 設定 |
|---|---|
| 認証方式 | メール + パスワード |
| セッション管理 | Supabase Auth が JWT を発行・管理 |
| セッション確認 | `supabase.auth.getSession()` |
| ログイン | `supabase.auth.signInWithPassword({ email, password })` |
| ログアウト | `supabase.auth.signOut()` |

### Supabase Storage

| 項目 | 画像 | 動画 |
|---|---|---|
| バケット名 | `images` | `videos` |
| アクセス制御 | Public（URLで誰でも参照可能） | Public |
| アップロード経由 | `POST /api/upload`（認証必須） | `POST /api/upload/video`（認証必須） |
| 許可する種類 | JPEG・PNG・WebP・GIF | MP4・MOV（QuickTime）・WebM・M4V |
| 最大ファイルサイズ | 10MB | 500MB |
| 利用箇所 | イベント・ギャラリー・コラボレーション・商品・記事・出店要項の画像 | コラボレーションの動画 |

## 3. Resend 連携

### 連携仕様

| 項目 | 値 |
|---|---|
| SDK | `resend` Python SDK (2.10.0) |
| API Key | ei8ht plants 名義のメールは `RESEND_API_KEY`、Habitat Oides 名義のメール（WS予約）は `HABITAT_RESEND_API_KEY` |
| 送信元 | ei8ht plants 名義: `ei8ht plants <CONTACT_FROM_EMAIL の値>`。Habitat Oides 名義: `Habitat Oides <HABITAT_FROM_EMAIL の値>` |
| 送信方向 | バックエンド → Resend API → 受信者メールボックス |

### 送信メールの一覧

`backend/app/routes/contact.py`・`orders.py`・`reserve.py` の件名から作った（2026-10-22 に作り直した）。`{…}` には実際の値が入る。

| 送るとき | 名義 | 宛先 | 件名 | API |
|---|---|---|---|---|
| お問い合わせを受けたとき（管理者へ） | ei8ht plants | `CONTACT_TO_EMAIL`（返信先は問い合わせた人） | `[ei8ht plants] お問い合わせ: {名前}` | `POST /api/contact` |
| お問い合わせを受けたとき（問い合わせた人へ・自動返信） | ei8ht plants | 問い合わせた人 | `お問い合わせを受け付けました \| ei8ht plants` | `POST /api/contact` |
| 管理画面から返信したとき | ei8ht plants | 問い合わせた人 | 管理画面で入力した件名（初めは `Re: ei8ht plants お問い合わせ`） | `POST /api/contacts/{id}/reply` |
| WS予約を受けたとき（予約者へ・日本語） | Habitat Oides | 予約者 | `[Habitat Oides] ワークショップ予約を受け付けました: {イベント名}` | `POST /api/reserve` |
| WS予約を受けたとき（予約者へ・英語。画面が英語のとき） | Habitat Oides | 予約者 | `[Habitat Oides] Workshop reservation received: {イベント名}` | `POST /api/reserve` |
| WS予約を受けたとき（管理者へ） | Habitat Oides | `info@habitatoides.com` | `[予約通知] {イベント名} に新しい予約が入りました` | `POST /api/reserve` |
| WS予約をキャンセルしたとき（予約者へ） | Habitat Oides | 予約者 | `[Habitat Oides] ワークショップ予約をキャンセルしました: {イベント名}` | `POST /api/reserve/cancel`・`PATCH /api/reserves/{id}`（キャンセルにしたとき） |
| 注文を受けたとき（購入者へ） | ei8ht plants | 購入者 | `ご注文ありがとうございます（注文番号: {注文番号}）\| ei8ht plants` | `POST /api/orders` |
| 注文を受けたとき（管理者へ） | ei8ht plants | `CONTACT_TO_EMAIL` | `[ei8ht plants] 新規注文 {注文番号}` | `POST /api/orders` |
| 決済できたが注文の記録に失敗したとき（管理者へ） | ei8ht plants | `CONTACT_TO_EMAIL` | `[ei8ht plants] CRITICAL: 課金済み注文レコード作成失敗` | `POST /api/orders` |
| 発送済みにしたとき（購入者へ） | ei8ht plants | 購入者 | `発送のお知らせ（注文番号: {注文番号}）\| ei8ht plants` | `PATCH /api/orders/{id}`（`shipped` にしたとき） |

- 注文番号は注文 ID の先頭8文字を大文字にしたもの
- WS予約の受付メールには、キャンセル用のリンク（`https://ei8htplants.com/cancel?id={キャンセルID}`）が入る。本文の項目はイベント名・開催日・会場・時間・参加人数・持ち込み・備考
- 発送のお知らせには、配送会社と追跡番号を入れたときだけ「配送情報」が入る。ヤマト運輸・佐川急便・日本郵便（ゆうパック）は追跡ページの URL も入る

### 送れなかったときの動き

| 場面 | 動き |
|---|---|
| お問い合わせ・予約・注文・発送のメール | 送れなくても受付・注文・ステータスの変更は成功のまま（記録は残る）。サーバーの記録（ログ）に失敗を残す |
| WS予約の受付メール | 送るときにエラーになったら、その予約に「メール未送信」の印（`email_failed`）を付ける。管理画面の WS予約一覧で名前の横に「メール未送信」と出る |
| 管理画面からの返信 | `RESEND_API_KEY` が未設定なら `500`（`RESEND_API_KEY が設定されていません`）、送信に失敗したら `500`（`メール送信に失敗しました: …`）。送れたときだけ既読にする |
| API キーが未設定 | 問い合わせ・注文のメールは送らずに受付だけする。予約のメールは `HABITAT_RESEND_API_KEY` が未設定なら送らない |

### Resend の Webhook（届かなかったときの知らせ）

Resend から `POST /api/reserve/webhook/resend` に知らせが届く。種類が「跳ね返された（`email.bounced`）」か「送れなかった（`email.failed`）」なら、そのメールの ID（予約を受けたときに `resend_email_id` に保存したもの）で予約を探し、「メール未送信」の印（`email_failed`）を付ける。それ以外の知らせや読めない内容は何もせず、常に `{"ok": true}` を返す。今のコードでは、知らせが本当に Resend から来たかの確かめ（署名の確認）はしていない。

## 4. Square 連携

自前の購入手続きの画面（`/checkout`）で決済する（2026-10-22 に記述を今の仕組みに合わせた。それまでは「外部のオンラインストアへのリンクだけ」と書いていたが、今はそのリンクは無い。ブランドページの「Shop now →」は自前の `/shop` を開く）。

```
1. 購入手続きの画面（/checkout）を開く
   → Square の Web Payments SDK（カード入力欄のプログラム）を読み込み、カード入力欄を出す
     （VITE_SQUARE_ENVIRONMENT が production なら本番用、それ以外は試験用を読み込む）
2. 「注文を確定する」を押す
   → カード情報を Square に預け、代わりの合言葉（トークン）を受け取る（カード番号はサイトに届かない）
3. 画面が POST /api/orders に、お客様情報・お届け先・カートの中身・トークンを送る
4. サーバーが在庫を確保し、Square の Payments API（/v2/payments）で合計金額（円）を決済する
   → 決済できなかったら在庫を戻し、402 を返す
5. 注文を記録して、確認メールを送る → 画面は /order/complete に移る
```

| 項目 | 値 |
|---|---|
| 画面側 | `frontend/src/pages/Checkout.tsx`（`VITE_SQUARE_APP_ID`・`VITE_SQUARE_LOCATION_ID`・`VITE_SQUARE_ENVIRONMENT`） |
| サーバー側 | `backend/app/routes/orders.py`（`SQUARE_ACCESS_TOKEN`・`SQUARE_LOCATION_ID`・`SQUARE_ENVIRONMENT`） |
| 自分の PC（localhost）で開いたとき | カード入力欄を出さず「Square決済はlocalhostでは動作しません。…」と出す |

詳しくは [PG-16 Checkout](pages/public/16_Checkout.md)・[DD-06 API仕様](../02_DD/06_API仕様.md) の「Orders」。

## 5. Google Gemini 連携

AI チャット（`/chat`）の回答を作る。`backend/app/routes/chat.py` が google-genai でモデル `gemini-flash-lite-latest` を呼ぶ。サイトの公開データ（開催予定のイベント・販売中の商品・公開中の記事の題名・取扱店）と、管理画面で有効にした Q&A を指示文に入れる。予約・注文・お問い合わせなどの個人情報は入れない。詳しくは [FT-24 AIチャット](features/13_AIチャット.md)。

## 6. Google アナリティクス 4（GA4）

公開ページを開くと、本番のドメインでだけページの閲覧を GA4 に送る（管理画面と、管理画面にログインしているブラウザからは送らない）。分析ダッシュボードは GA4 の Data API でアクセス数を読み取る。詳しくは [BD-01 システム構成](01_システム構成.md) と [FT-25 分析ダッシュボード](features/14_分析ダッシュボード.md)。
