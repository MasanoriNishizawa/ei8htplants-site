## 2. Supabase 連携

### 接続方式

```
バックエンド (supabase-py 2.16.0)
    ├── supabase      = create_client(URL, ANON_KEY)
    │       役割: 公開データの読み取り（anon role, RLS 適用）
    └── admin_supabase = create_client(URL, SERVICE_ROLE_KEY)
            役割: 全データの読み書き（service_role, RLS バイパス）

フロントエンド (@supabase/supabase-js 2.49.8)
    └── createClient(URL, ANON_KEY)
            役割: Supabase Auth のみ（Admin認証・セッショントークン取得）
            ※ データ読み書きにはフロントエンドから直接 Supabase を呼ばない
```

### データフロー

```
公開ページのデータ取得:
    ブラウザ → /api/* → FastAPI → supabase (anon) → Supabase DB

管理画面の書き込み:
    ブラウザ → /api/* → FastAPI → admin_supabase (service_role) → Supabase DB

Admin認証:
    ブラウザ → @supabase/supabase-js → Supabase Auth （直接通信）

画像アップロード:
    ブラウザ → POST /api/upload (multipart/form-data + Bearer JWT)
             → FastAPI → admin_supabase.storage.from_('images').upload()
             → Supabase Storage
             → 返却: { "url": "https://...supabase.co/storage/v1/object/public/images/..." }
```

### Supabase Auth

| 項目 | 設定 |
|---|---|
| 認証方式 | メール + パスワード |
| セッション管理 | Supabase Auth が JWT を発行・管理 |
| セッション確認 | `supabase.auth.getSession()` |
| ログイン | `supabase.auth.signInWithPassword({ email, password })` |
| ログアウト | `supabase.auth.signOut()` |

### Supabase Storage

| 項目 | 設定 |
|---|---|
| バケット名 | `images` |
| アクセス制御 | Public（URLで誰でも参照可能） |
| アップロード経由 | `POST /api/upload`（FastAPI 経由、認証必須） |
| 許可 MIME タイプ | `image/jpeg`, `image/png`, `image/webp`, `image/gif` |
| 最大ファイルサイズ | 10MB |
| ファイル名形式 | `{uuid}{拡張子}`（衝突回避） |
| 利用箇所 | イベント画像・ギャラリー画像・コラボレーション画像 |

## 3. Resend API 連携

### 連携仕様

| 項目 | 値 |
|---|---|
| SDK | `resend` Python SDK (2.10.0) |
| API Key | 環境変数 `RESEND_API_KEY` |
| 送信方向 | バックエンド → Resend API → 受信者メールボックス |

### 送信パターン一覧

| 送信タイミング | 送信元 | 宛先 | 件名 | 呼び出しエンドポイント |
|---|---|---|---|---|
| お問い合わせ受信時 | `CONTACT_FROM_EMAIL` | `CONTACT_TO_EMAIL`（店舗） | `[ei8ht plants] お問い合わせ: {名前}` | `POST /api/contact` |
| WS予約受付時 | `CONTACT_FROM_EMAIL` | 予約者メール | `[ei8ht plants] ワークショップ予約を受け付けました: {イベント名}` | `POST /api/reserve` |
| 管理者が返信時 | `CONTACT_FROM_EMAIL` | 問い合わせ者メール | 管理者が入力した件名 | `POST /api/contacts/{id}/reply` |

**WS予約確認メールの本文に含まれる項目**: イベント名・開催日・会場・セッション時間（`session_id` 指定時）・参加人数・植物持込・鉢持込・備考

### エラー時の挙動

- メール送信失敗 → `500 Internal Server Error`
- DB保存成功・メール失敗の場合、DBにレコードは残る（管理画面で確認可能）
- 環境変数 `RESEND_API_KEY` 未設定時 → `{"detail": "Mail not configured"}`

## 6. 内部API（フロントエンド ⇔ バックエンド）

フロントエンドとバックエンド間の通信は `lib/api.ts` が窓口。  
エンドポイント詳細は `doc/DD/06_API仕様.md` を参照。

```
ベースURL: /api
プロトコル: HTTP（開発）/ HTTPS（本番）
フォーマット: JSON（アップロードのみ multipart/form-data）
認証: なし（公開エンドポイント）/ Bearer JWT（Admin操作エンドポイント）
```
